# 独立常驻主机 DDNS

DDNS 是独立运维组件，不属于 Agent 核心，也不建立另一套任务/会话数据库。可由专用主机维护一条独立域名记录，NAS 保持原有记录。若共用公网出口，两个域名仍可能指向同一个公网地址；DDNS 本身不提供端口转发、HTTPS 证书或内网穿透。

入站验证、独立 HTTPS 服务及标准端口受限时的方案见 [HTTPS 入口](HTTPS.md)。

## 用户服务

`ddns-go.user.service` 适用于已有 systemd 用户管理器的 Linux 主机。二进制安装到 `~/.local/bin/vortocode-ddns-go`，配置位于 `~/.config/vortocode-ddns/config.yaml`。配置目录应为 0700；服务使用 UMask 0077，使新配置文件为 0600。不要把配置、密钥或证书私钥放进仓库。

模板仅监听 `127.0.0.1:9876`，可经 SSH 本机回环转发进行配置。模板不安装二进制、不创建 DNS 记录；安装者需从官方固定版本下载并核验发布摘要，检查原有文件和监听冲突后才安装。不要把 Web 配置页公开到公网。

```sh
ssh -N -L 127.0.0.1:19876:127.0.0.1:9876 <常驻主机>
```

打开 `http://127.0.0.1:19876`，先建立管理登录，再填 DNS 服务商和目标域名。域名只填要由该主机管理的完整主机名。公网 IPv4 需通过验证过的公网检测接口获取，不能把主机的私有网卡地址直接写进 A 记录；没有可用公网 IPv6 时先关闭 AAAA 更新。检测接口应启用 HTTPS 证书校验，不使用 `-skipVerify`。

## 阿里云权限

本次核验的 ddns-go v6.17.7 阿里云适配器调用三项 DNS 操作：`alidns:DescribeSubDomainRecords`、`alidns:AddDomainRecord`、`alidns:UpdateDomainRecord`。可以为独立 RAM 用户创建仅允许这些操作、限定目标根域的自定义策略；例如 `acs:alidns:*:<账号 ID>:domain/example.com`。不需要删除记录、整个阿里云账号管理或主账号 AccessKey 权限。

阿里云通常按域名授予记录管理权限：程序只填写一条记录，并不代表 RAM 密钥也只能修改这条记录。若需要按子域形成真正独立的权限边界，需先将子域作为独立托管域并核验客户端对该区域的支持，不能只改策略中的名字就认为完成隔离。

AccessKey ID/Secret 由用户通过本机隧道配置页填写，不能发到聊天或写入仓库。配置完成后的自动化检查只应返回服务状态、配置权限、服务商/域名是否符合预期和解析结果；不打印密钥、原始配置或带签名的 API 请求。

## 验收分层

1. **组件**：官方版本摘要、实际二进制版本、用户服务启用/运行、回环监听、原助手服务仍正常。
2. **配置**：用户安全填写密钥，配置文件权限正确，只有预期域名和地址族。
3. **解析**：服务商收到成功回执，权威/公共 DNS 的目标记录更新；原 NAS/网站记录保持原值。泛解析返回地址不能当作已有独立站点的证据。
4. **入口**：公网端口可达、可信 HTTPS、正确反向代理和精确账号回调；DNS 成功不能代替这一层。
5. **App**：常驻服务已部署相应手机接口，真实手机登录、刷新及撤销通过。

本仓库模板不自动开放路由端口、覆盖已有记录或部署常驻助手。DNS 记录有现有用途时，先核对站点和变更范围。
