# 手机只读入口

同仓库中的独立 Web 客户端，复用 `packages/mobile-client`。当前提供同账号 Web 登录、电脑端设备管理、高级手动配对和只读助手概览。聊天、任务批准、推送、远程画面与原生安全存储尚未接入。原有 `prototypes/mobile-assistant` 继续只用模拟数据。

默认方案现已调整为**同账号登录关联助手**，页面将旧的核对码流程收进高级入口。同账号 OAuth 和 HttpOnly BFF 会话已接入本地源码，登录连接当前运行端；Desktop 已提供需原生确认的关联设置卡片，云端助手列表尚未完成；详见[账号连接方案](../docs/MOBILE_ACCOUNT_ACCESS.md)。启用条件与会话边界见该文档，以下配对流程属于高级手动连接。

## 构建与运行

```sh
npm ci --ignore-scripts
npm run build
```

在本目录执行，输出到忽略的 `web/mobile/`。生产 Gateway 从 `/mobile` 返回手机页面，从 `/mobile/manage` 返回电脑端管理页面；静态 JS/CSS/品牌图片由 `/static/mobile/` 的受限资源路由返回。没有构建资源时返回 503，不展示失效的假入口。服务首页的 JSON 提供两条路径。

正式环境需要 HTTPS、明确配置管理员令牌和同源部署；没有开放任意跨站 CORS。源码运行时先构建前端，再启动/重启 Gateway；Desktop 打包前也必须先完成此构建，生成资源才会被原有 `web/` 打包规则收录。此轮没有重新打包、安装或更新已部署服务。

本地隔离验收可在仓库根目录运行 `python scripts/preview-mobile-reader.py --control-file /private/tmp/<独占验收文件名>.json`。只绑定 127.0.0.1:5216，临时状态根目录，关闭模型/调度生命周期。控制文件是一次验收用的随机测试身份、权限 0600，不是现有服务配置；不要打印或分享它。脚本退出会删除临时状态与控制文件。

## 高级手动连接流程

1. 电脑打开 `/mobile/manage`，以管理员身份登录，开放 5 分钟窗口。
2. 手机打开同一服务的 `/mobile`，进入“高级：手动连接自托管助手”，填写设备名称，发起配对。
3. 电脑刷新请求，比较名称与码，输入手机上的码，再确认只读授权。
4. 手机检查结果，明确确认两端码一致，再读取助手名称、主聊天登记和目标摘要。
5. 电脑可以关闭窗口或撤销设备；下一次读取会核对撤销，认证失效清除手机当前连接视图。

高级手动连接的手机凭证由本页通过 Web Crypto 生成，只保存在闭包中，不放 URL、localStorage、sessionStorage 或 Cookie。刷新、关闭与页面离开会清除本页连接；这是一版验证真实读取合同的浏览器入口，长期连接仍待原生安全存储适配。断开本页不会自动撤销已批准设备，电脑端可继续管理它。

待配对时取消会用本请求的凭证证明撤销请求；若批准回执已丢失，也会撤销同一设备的授权。取消没有取得回执时保留请求身份并显示失败，不自行当作取消成功。配对状态可在原请求有效期内重读，不生成第二份授权。

断线保留最近读取的内容与旧时间，并标为历史；授权失败清除连接视图。目标状态沿用原领域记录，页面不计算新的验收结论。所有动态内容使用 DOM 文本节点，不把设备名称、目标或服务器错误当 HTML 执行。

见 [当前验收记录](ACCEPTANCE.md) 和 [协议与仓库边界](../docs/MOBILE_CLIENT_ARCHITECTURE.md)。

同账号隔离验收：仓库根目录运行 `python scripts/check-mobile-browser.py`。可选 `--preview --port 5218` 保留临时服务直到 stdin 收到换行/结束，需交互终端；测试账号仅写权限 0600 的临时文件，退出清除。不会连接已有账号数据库。
