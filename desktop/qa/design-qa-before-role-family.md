## 证据与比较条件

- source visual truth：`docs/design/channels/prototype-source.png`，来自主人选定的 #883 原型频道页面。
- implementation：`docs/design/channels/desktop-dark.png`、`desktop-light.png`、`create-dark.png`、`long-title-1080.png`、`create-1080.png`。
- 入口：`desktop/qa/channels.html`，生产组件、合成记录与传输；不连接真实服务、凭据或模型。
- 标准视口：1440×1000 CSS px，deviceScaleFactor=1；源图及最终深浅色、弹窗截图均为 1440×1000 像素，无缩放。
- 首轮 `first-pass.png` 为原生 1716×907、密度 1，仅用于记录布局问题；没有将它与不同视口的源图作像素一致性结论。
- 最小支持窗口：1080×900 CSS px，截图 1080×900、密度 1；与 Desktop 当前最小窗口宽度一致。720 宽度低于现有窗口支持范围，不宣称通过移动端或该宽度验收。
- 状态差别：源图是有消息、专员交付及回复面板的完整目标；本次实现图是刚创建的空频道。只比较相同的频道分组、选中状态、标题/说明、输入区位置与控制入口，不将尚未迁移的消息、头像或回复能力算作已实现。
- 源图与实现截图在同一次图像输入中共同打开比较；另外共同查看了弹窗、长标题和浅色截图。控件与文字在原尺寸下可读，本步无额外裁切需求；没有仅凭路径或代码作视觉结论。

## Findings 与迭代

1. [P2，已修] 首轮沿用旧首页的四行空白布局，输入框停在页面中段。证据 `first-pass.png`；新增频道独立布局并提高空状态选择器优先级。复查 `desktop-dark.png`：输入区留在底部，1440×1000 下可见；不影响普通会话布局。
2. [验收夹具问题，已修] 首轮夹具未按原输入区结构装配，且接错草稿 setter，输入不能保留。修为生产 Hook 的 `setPromptState`，使用原 `composer-wrap` 与 `conversation-body` 样式。实测研究频道/产品频道草稿来回切换，互不覆盖。
3. [验收夹具问题，已修] 主题按钮原先切换 class，与现有 token 的 `data-theme` 不符。修正后分别核对根节点的实际主题，再生成深浅色截图。
4. [范围内无剩余 P0/P1/P2] 1080 宽度长标题、长说明会换行或截断，面板和发送控件仍可见，无横向溢出；新建弹窗所有字段与操作均可见。

## 五项表面检查

- 字体：沿用现有字体栈和字号 token，中文层级、占位说明、长标题换行可读。现有全局品牌与原型的字重/导航密度差异属于后续完整外壳迁移，未声称逐像素复刻。
- 间距与布局：频道分组、添加、选中行、删除入口有明确层次；弹窗圆角与间距使用现有 token；输入区保持底部。正式页面仍保留原主导航与助理面板。
- 颜色：深浅色复用 canonical token；选中/禁用/错误/焦点有区别。尚未将原型整套背景层次替换到全应用。
- 图片：本步没有新栅格图或角色头像。Hash、添加、删除沿用现有 Lucide 图标；原型里的角色图不被用占位图冒充，角色迁移仍未实现。
- 文案：频道名称、说明、保存目标、删除记录的后果、无权限提升与过期回执均可见；共用词来自 `design/copy.json`。频道说明展示为转义文本。
