# P3 个人空间交互验收

使用 `personal-space.html`，加载生产的空间选择器、侧栏和 `useComposerDraft`。
数据均为合成，不读取凭据、不连接真实运行端、不调用模型。

## 已检查

- 两个同名、同地址空间按登记分别选择；当前目标和来源显示正确。
- 在 A 输入文字、添加文本附件，切到 B 时两者均为空；切回 A 原草稿恢复。
- 新建未发送旁聊，回主要聊天后能从旁聊列表找回原文字。
- A 的旧发送失败在 A→B→A 后回传，不覆盖新的输入。
- 模拟连接失败时保留原目标，弹窗显示错误，可再次选择或关闭。
- Tab / Shift+Tab 的首尾焦点留在弹窗；Escape 关闭后焦点回到空间入口。
  键盘检查使用浏览器协议派发，包含 macOS 键码；自动化工具的普通键盘调用未产生键事件，
  这不是原生 Desktop 的键盘实跑结论。
- 浅色 960×760、深色 400×720：弹窗在可视范围内，标题、说明、选择和管理入口未溢出。
  主界面仍有原先的 720px 最小宽度；本检查只确认窄窗口下的弹窗。

## 复查步骤

运行 Desktop 的 Vite，打开 `/qa/personal-space.html`。依次在两个空间输入不同内容并
切回核对；添加附件；新建旁聊后返回；用「模拟延迟发送」留下旧请求，切空间再回传旧失败。
勾选「模拟切换失败」核对失败状态。用主题切换和窗口调整检查弹窗，关闭后检查入口焦点。

## 边界

草稿只保存在当前窗口内存，刷新夹具或关闭应用后不保留。此次未实跑常驻进程安装、
Desktop 退出重开、真实模型、真实文件发送、真实运行端切换、升级或服务部署。
现有 Cargo 门禁使用已准备的 sidecar 输入，不代表重新构建和签名了安装包。
