# P4 设置目标隔离验收

使用生产 `SettingsModal`、设置子组件、`useLlmProfile`，IPC 和专员台账均为合成。
`settings-source-reads.html` 使用生产 `useTrustLevel`、`useExtensionsStatus` 和可控异步接口，
不调用原生 IPC、模型或服务。夹具不读取或写入用户配置。

## 已检查

- 设置展示打开时的运行端、空间/项目和连接登记；本机与个人空间区块分别标识归属。
- 专员页加载目标 1 后，用合成后台事件更换来源：原名录控制隐藏停用，目标 2 无请求。
  关闭设置再明确打开后，才开始读取目标 2。
- 原运行端失效后，本机模型仍可编辑；切换分类再返回，模型草稿保留。
  保存只修改合成本机配置，没有重新启动已变化的目标，反馈为下次启动生效。
- A 的授权、Hook、扩展读取延后；切到 B 并取得 B 的数据，再回传 A，B 的数据保持不变。
- 保存 B 的授权按钮旧回调，切回 A 后执行旧回调：没有写入任何目标。
  回到 B 明确修改当前授权，仅 B 收到一次写入。
- 设置搜索显示归属，并区分 MCP 管理入口和项目扩展。
- 浅色/深色检查目标、分区、提示和原设置布局，保留原弹窗和未保存确认交互。

## 复查入口

启动 Desktop Vite，打开：

- `/qa/settings-redesign.html?section=staff&staff=ready&theme=light`
- `/qa/settings-redesign.html?section=personal&staff=ready&theme=light`
- `/qa/settings-source-reads.html`

首个夹具提供 `changeSettingsTarget()` 合成后台换端，以及 `settingsTargetCalls()` 读取请求
目标，不操作实际服务。新来源需要关闭再重开设置。读取夹具中按 A→B→回传 A→切回 A→
回调旧授权→B→修改当前授权操作，最终写入记录仅为 B。

## 边界

离线组件验收不代表真实运行端切换、真实手机关联、真实审批或模型调用已经实跑。
未验证签名 Desktop 的原生确认窗口、安装/退出重开/升级或服务部署。本机原生进程的
launch/revision、安全确认与后台审批仍由既有合同负责。本轮没有重建安装包。

最终源码核对另修正了全局指令范围文案：同一用户目录下的临时引擎和本机常驻助手共享
此文件；模型配置仍保持独立。现有截图的布局检查早于这处文案修正；修正后补行为测试、
类型/渲染检查和完整门禁，不把截图当作真实常驻进程已经验证的证据。
