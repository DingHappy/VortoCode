# 主人待办与交付阅读验收

## 本轮范围

从安装版 0.2.49 的使用检查继续，基于 `5160e4ec` 在独立 worktree 修复三个优先问题：待办决策归属、任务/小组交付阅读、异常入口定位。前一轮 #776 仍是独立排版 PR；本轮不包含它的完整改动。小组标题与成员折叠沿用该轮已确定的设计。

## 行为与保护

- 只根据当前 client 与 assistant scope 读到的小组 `children` 关系分流内部记录，来源未读到、归属冲突时保留原入口；成员明确向主人提问不被收起。整组交付在主要聊天保留一次，整组失败仍是异常。状态、验收和任务数据不被更改。
- 完整历史保留所有记录，并标注小组与成员；已知内部任务可返回小组，任务卡不再拟写绕过协调人的通用验收/返工请求。原问题回答控件仍保留。
- 长原要求默认折叠；结果在独立阅读区域展示、可复制和查看已读取原文。复用已有安全 Markdown 组件，HTML/脚本转义，无图片和自动访问。旧群聊原文解析方式未变。
- 小组将协调总结、验收证据和成员已保存结果分开。任务 ID、当前轮次、协调人是否接受均明确显示；不猜测最终稿，不将协调人接受等同于主人验收。现有存储/读取有长度限制，界面明确长结果可能截断、缺失时需补交。
- 异常入口是一次显式导航：返回摘要、滚动并聚焦异常区，普通数据刷新不抢焦点；没有异常时显示诚实的空态。

## 实际验证

- TypeScript、完整前端 Vitest 和 Vite 生产构建通过；确切数量见 PR。保留已有大 chunk 提示。
- 回归覆盖：内部验收/失败仍保留历史，明确主人提问不丢失；缺失/冲突归属保守回退；整组状态；HTML/脚本链接处理；错误小组的初始结果不展示；长要求与操作顺序。
- Chrome 原生界面实际检查 `qa/owner-attention.html`，使用真实生产组件和合成服务。7 条输入记录始终保留；已知小组时 4 件主人待办、2 条内部记录；模拟归属未取得后 5 件主人待办、0 条确认归属的内部记录，内部失败回到异常中。未知发送回执和向主人的问题始终可达。
- 885 字的完整原要求默认折叠，交付文本有标题、表格、清单及来源；“复制原文”返回成功。成员交回文本与完整小组经过均能打开。
- 点击「查看需核对」后活动元素为 aria-label「需要核对」的区块，例行时间线在下面；全部记录仍有内部失败和内部待审阅记录。
- 宽栏、360px 外框的深色任务页、浅色小组交付页均无页面横向溢出；超宽表格在内部滚动。批准/发送动作计数始终为 0。
