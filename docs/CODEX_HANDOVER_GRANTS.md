# Codex 交接版本与固定轨迹

2026-10-31。复用原 `handover.json`、`actions.json` 与监督 marks。覆盖普通交接和
Goal 交接，不新增执行器、API、任务库、评测运行时或模型入口。

## 本轮复现与修复

普通会话此前只记录名称、目录和交接时间。离线复现：模型判断中先收回再交接同一会话，
旧 `continue` 仍产生一条拟话，判断状态为 succeeded。收回与重交接后，旧普通动作也可能
因“当前仍有交接”再次通过审批。Goal 交接已有随机 token，普通交接没有相同保护。
这是替身模型与临时状态的反例，不是已发送越权 RPC 或已发生生产事故的证据。

现在每次交接都有独立 token，交接时间相同也不同。原 Goal token 继续使用，不另建版本库。
每条新动作保存完整交接记录的 `handover_fingerprint`；这是变化检测指纹，不是签名、凭据或执行授权。
即使手工拟话允许跨 Codex 轮次保留，它也不能跨交接撤销后恢复。

监督器将当前交接快照用于整个本次会话检查。模型返回后复核，`continue/ask/done` 旧结论
都不能借新交接生效；自动叫停与拟话创建前也在原锁内复核。普通 `done` 收回交接采用
锁内比较再删除，避免刚检查完又被另一进程替换的新交接被误删。

每个待批、已批动作在清理、批准、认领前核对交接版本。已认领的 `sending`、结果不明
`unknown`、已有回执的 `sent` 不因重新交接重写为可执行状态，也不自动重发。撤销审批
不等于撤回已经提交的 RPC；迟到回执仍按原动作 ID 对账。

仍按固定顺序锁交接再锁动作，锁内不调用模型、通知或外部 RPC。进度报告遇到动作锁忙
可以先保存，批准与认领不能依赖清理是否及时完成。

## 兼容与有限推进

- 旧普通交接没有 token 时仍可读取。用户新拟动作可绑定它的完整记录指纹，读取不自动
  改写授权；重新交接会获得新 token，旧版本不能恢复。
- 已持久化但没有交接指纹的旧普通待批/已批动作要求重新拟定，不能静默补绑当前交接。
  新版中重新拟定的人工消息和叫停仍走原审批；没有新增自动权限。
- 自动草稿还须具备 [动作版本依据](CODEX_ACTION_CAUSALITY.md)，旧版本缺失时重新拟定；
  交接版本未变也不能让新指令之后的旧判断生效。
- 旧 Goal 动作缺少新指纹时，仍须通过原 Goal token、目标版本、执行观察与材料门，
  不撤掉已有保护。显式损坏的新字段不能伪装成旧格式。
- 同轮已经尝试的判断仍记在原 marks 中，撤销、重交接、重启不退还判断机会或 Goal 额度。
  新交接不会触发同轮自动重评；需要后续工作时，由人核对后在原会话发起下一轮。

## 固定轨迹与运行方式

直接接入已有 pytest/e2e 门禁，不扩写原 14 题私人助手评分，也不建立合成“模型基线”。

```bash
# 无模型、无远端 RPC、仅临时合成数据
python -m pytest tests/e2e/test_codex_grant_trajectory.py tests/unit/test_codex_grant_compatibility.py -q

# 原完整门禁已包含以上单测及 e2e
./scripts/ci-local.sh
```

固定轨迹包含：原观察员采集 → 原报告接收 → 人工确认交接 → 完成事件 → 替身模型判断 →
判断中撤销并重交接 → 拒绝旧结论 → 重读持久记录与后续巡视不重试。动作轨迹分别覆盖
message/interrupt 和 proposed/approved/sending/unknown/sent，既检验旧动作拒绝，也检验
新交接下重新拟定的人工控制仍可批准。另在拟话创建、叫停创建和锁内收回前注入交接变化，
覆盖“刚检查完就变化”的窗口。

断言依据是实际文件状态、判断次数、动作身份、通知及原生产函数返回，不检查源码子串，
也不靠模型文字自评成功。其通过只能证明这些确定性合同，不能证明模型理解了所有自然语言
约束、综合助理能力、原生 Desktop、真实 Codex、常驻主机或部署已验收。
