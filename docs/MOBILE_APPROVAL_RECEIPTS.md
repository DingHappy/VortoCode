# 手机对话审批的回执与核对

接续 [本轮同类授权](BOUNDED_TURN_APPROVAL.md)。本轮优化只覆盖 iPhone 对话内的 App 审批卡，沿用原 `chat/card` POST 与 `chat/turn` GET；不增加审批接口、授权存储或执行恢复。

## 用户可见行为

- 等待 Face ID 或提交期间，批准、拒绝和范围按钮锁定，连续点击只开始一次决定。
- 签名尚未完成、HTTP 请求尚未启动时失败，可以重新手动选择。发起 HTTP 后遇到超时、断线、取消或回执无法核验，则保留卡片并锁定决定，显示「核对状态」，不自动重发。
- 「核对状态」只读当前回合。查询失败继续锁定；明确查到原卡仍在等待且没有已确认回执时，才重新开放选择，仍需用户手动点击。后台轮询返回 pending 不能解锁重试。
- 已收到与原卡身份、摘要、批准/拒绝和范围一致的回执时，不因后续查询失败或仍返回 pending 而重新开放这张卡。核对到原卡闭合、被替换或回合结束后移除旧等待；进度失联继续显示原有 unknown 提示，不据此推断之前动作没执行。

范围批准、单次批准和拒绝共用这一条回执路径。批准回执只说明卡片决定已受理，不表示工具执行或任务验收已完成。

## 身份与异步边界

发送前再次核对实际登录 token / 助理身份、会话代次、设备与写入能力、回合、原待批卡及本次尝试。签名器返回后再检查取消和会话期限；即使底层 Face ID 签名器忽略任务取消，也不会因此继续发送旧请求。

账号或回合重置令旧尝试失效。旧签名、POST、状态读取及收尾回调不能更新新尝试或清除新操作的忙碌状态。轮询只能清理已闭合的旧卡，不能替用户批准或创建范围。

发送前核对不是撤回已经发出的 HTTP 请求。通过该边界后发生的切换、取消或网络故障，不能保证服务器没有受理；仍由原卡片终态、服务端身份核验及只读核对约束，不自动补偿或重放。手机重启不恢复内存回合或发送中的批准。

## 验证与范围

Swift 合同覆盖重复点击、发送前/后失败的区别、查询失败、人工核对、回执身份与范围不匹配、已经确认的卡不重新开放，以及签名期间身份变更/取消时零 HTTP 请求。HTTP 全由 URLProtocol 替身接收，不使用真实账号、钥匙或模型。

这不是 Codex 动作、任务单、随手记和撤销等其它写操作的完整回执重构；这些入口继续沿用原行为。iOS 模拟器编译与离线合同不代替实际界面交互、真实 Face ID、真机安装或线上验收。
