# VortoCode 账号服务设计（提案）

状态：**P1 进行中**。服务端已上线（独立私有仓库），Desktop 登录见 `desktop/src-tauri/src/account.rs`。

## 目标与边界

给 VortoCode 用户一个可以登录的账号，服务四件事（按落地顺序）：

1. **登录身份**：注册、邮箱验证、登录、找回密码；Desktop 能登录，能看到并吊销自己的设备。
2. **付费与额度**：登录即可用模型，不用自己配服务和 Key；充值与套餐由中转站承担。
3. **多设备与常驻电脑**：常驻电脑登记到账号下，Desktop 自动列出，不再手填地址和令牌。
4. **用户与发版**：知道多少人在用哪个版本；按账号分发 Beta。

**不做**：不上传代码、对话、文件；不在账号服务里做计费（钱的账只在中转站）；不托管任何签名私钥。

## 总体结构

```
Desktop ──浏览器登录(OAuth2 + PKCE)──▶ 账号服务  account.<公司域名>
   │                                      │ ① 用户、设备、邀请码、会话（自己的库 vortocode_account）
   └──带访问令牌调用──────────────────────▶│ ② P2 起：经中转站管理接口为用户开通/轮换模型 Key
                                          ▼
                                   中转站（计费、充值、套餐）
同一台 MySQL 8：vortocode_account 与中转站的库是**两个库、两个账号**，账号服务读不到中转站的表。
```

- **独立服务**：一个小型后端（Python FastAPI，与 VortoCode 同语言），Docker 部署在中转站同一台服务器，nginx 反代 + 自动续期证书，与现有子域名同一套做法。
- **独立账号体系**：和中转站账号**不是同一个账号**。P2 时在两者之间建立绑定：账号服务用服务端保存的中转站管理凭据，为每个 VortoCode 用户开通一个中转站用户与 Key；用户付费仍在中转站页面完成。

## P1：登录身份（第一期，细化）

### 用户可见
- 网页：注册（需邀请码）、邮箱验证、登录、忘记密码、修改密码、我的设备（可吊销）、删除账号。
- Desktop：设置里新增「VortoCode 账号」（与现有的中转站「账号」页分开）：登录 / 退出 / 当前账号 / 本机设备名。

### 注册方式
**先邀请制**：管理员在服务器上用命令生成邀请码（可设次数和过期时间）。稳定后再改为开放注册（加人机验证与频率限制）。

### Desktop 登录流程（OAuth 2.0 授权码 + PKCE，RFC 8252 原生应用做法）
1. Desktop 生成 `code_verifier` / `code_challenge`，在本机 `127.0.0.1` 随机端口起一个一次性回调监听。
2. 打开系统浏览器到 `/authorize?client_id=vortocode-desktop&code_challenge=…&state=…&redirect_uri=http://127.0.0.1:<port>/callback`。
3. 用户在浏览器里登录（密码只输在网页上，Desktop 不经手）。
4. 回调带回授权码；Desktop 用授权码 + `code_verifier` 换取令牌。
5. **访问令牌**短期（15 分钟）；**刷新令牌**长期（30 天，每次刷新轮换，旧的立即作废，发现重用即吊销整个会话链）。刷新令牌存 **macOS 钥匙串**，不写文件。
6. 每次登录登记为一台「设备」（名称、平台、App 版本、最后活跃时间），用户可在网页或 Desktop 吊销。

### 数据（vortocode_account 库）
| 表 | 主要字段 |
|---|---|
| users | id、email（唯一，验证状态）、password_hash（argon2id）、status、created_at、deleted_at |
| invites | code_hash、max_uses、used、expires_at、created_by |
| email_tokens | 用途（验证/重置）、token_hash、expires_at、used_at |
| devices | user_id、name、platform、app_version、created_at、last_seen_at、revoked_at |
| refresh_tokens | device_id、token_hash、family_id、expires_at、revoked_at、replaced_by |
| audit_log | user_id、事件（登录、失败、改密、吊销、删除）、ip 前缀、时间 |

所有令牌、邀请码、邮件链接**只存哈希**。不存明文 IP，只存前缀（用于风控与审计）。

### 安全基线
- 密码 argon2id；登录与注册按 IP 和账号限频（Redis）；连续失败后递增等待。
- 网页表单 CSRF 防护；Cookie 用 `Secure` / `HttpOnly` / `SameSite=Lax`。
- 邮件链接一次性、短时效；找回密码不暴露「邮箱是否存在」。
- 删除账号：立即吊销所有会话与设备，个人数据在 30 天内彻底删除（期间可撤销）。
- 管理操作只能在服务器上通过命令完成，不开放管理网页。

### 运维
- 新库纳入现有备份链：服务器每日备份脚本同时导出 `vortocode_account`，经只读账号拉回 NAS，恢复演练一并核对。
- 健康检查与关键失败（发信失败、数据库不可达）接入常驻助理的运维心跳。

## 后续阶段（概要）
- **P2 付费与额度**：账号服务为用户开通中转站账号与 Key（管理凭据只在服务器）；Desktop 登录后自动用这个 Key；显示余额并跳转中转站充值。
- **P3 多设备与常驻电脑**：常驻电脑用设备授权码流程登记到账号；Desktop 列出账号下的常驻电脑，交换短期连接令牌；少量设置同步。
- **P4 用户与发版**：登录与刷新时上报版本和平台（仅此两项）；Beta 通道按账号开放；检查更新可改走账号服务。
