# iPhone 端设计

日期：2026-11-07。依据 [ADR-017](DECISIONS.md#adr-017iphone-对齐-desktop设计语言两端共用2026-11-07)。本文取代 2026-10-25 的手机入口草案（四项底栏与「成果」页），旧稿见 git 历史。

## 一句话

iPhone 学 Muse 手机端的形式，结构照搬 Desktop 已按 [ADR-016](DECISIONS.md#adr-016desktop-以会话为中心2026-11-05) 改好的样子；颜色、字号、圆角、组件和状态词两端用同一份定义。手机负责交代、跟进和批准，执行留在常驻电脑上（`owner_device` 能力档案不变）。

## 结构

不放底部标签栏。

| 位置 | iPhone | 对应 Desktop |
| --- | --- | --- |
| 起点 | 全屏主要聊天，打开 App 停在最新一条 | 打开就是主要聊天 |
| 顶部 | 左上抽屉按钮；居中头像和名字，下面一句话说明后台正在做什么；右上更多 | 对话标题栏 |
| 等你处理 | 主要聊天顶部一行，带件数，可展开 | `WaitingInbox`，同一来源 |
| 左侧抽屉 | 主要聊天（角标）、任务小组、旁聊；底部设置、搜索、新对话、常驻电脑状态 | 侧栏 |
| 点头像 | 全屏助理详情：头像、名字、连接状态、当前模型；五段：动态 / 目标 / 审核记录 / 定时 / 身份 | 右侧助理面板 |
| 对话里 | 审批卡、小组交付消息、可展开的执行过程 | 同样的卡片和折叠块 |
| 任务小组 | 群聊，分「交付与原文」「小组经过」；可回复、验收、退回 | `TeamChat` |
| 设置 | 抽屉底部齿轮，卡片式分组 | 头像菜单里的设置 |

## 设计语言两端共用

三层，都只有一个出处：

1. **变量**：`design/tokens.json` 是唯一出处，`python scripts/design_tokens.py` 生成 `desktop/src/styles/tokens.css` 和 `MobileCore/DesignTokens.swift`。`tests/unit/test_design_tokens.py` 检查生成文件没有过期，也没有被手改。SwiftUI 用 `VCColor.bg.color`，跟随系统浅色 / 深色，取值和 Desktop 一样。深色两端统一用 Desktop 的深色（画布 `#1a1a19`、抽屉和侧栏 `#141413`、卡片 `#222221`），不另设纯黑。
2. **组件**：审批卡、等你处理、动态记录行、执行过程、小组气泡、头像名片、状态胶囊。两端结构、字段顺序、按钮顺序相同。
3. **状态词和界面词**：沿用 [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) 第 7 节，放在 `design/copy.json`，同一个脚本生成 Desktop 的 `lib/copy.generated.ts` 和 iPhone 的 `MobileCore/Copy.swift`。

手机按 iOS 习惯处理的部分：
- 正文跟随 Dynamic Type，不锁死字号；
- 主要命中区至少 44 × 44；
- 支持系统返回手势；
- 减少透明度时换成实色。

## 从 Muse 学什么，不学什么

参考：用户提供的 8 张 Muse 手机截图（2026-10-25，只在本地忽略目录，不进仓库）和 Meta 公开的设计说明。没有实际操作过 Muse。

学：
- 一段长对话是中心，旁聊放进抽屉；
- 头像是身份入口，下面一句话说明后台在做什么；
- 点头像能看记录和权限（「看不见就无法信任」）；
- 审批卡只给关键操作，避免习惯性点同意；
- 圆形浮动按钮、胶囊输入框、无描边大圆角卡片；
- 设置用卡片分组。

不学：
- 手机直接跨应用办事：我们的手机对话只能查资料、改自己的事项和记忆；
- 兴趣资讯动态：我们的「动态」只放工作记录；
- 钱包、订阅、推荐码；
- 点子页：等有真实内容再加。

| M4（进行中） | TestFlight 分发；真机核对 Face ID 批准、审批回执、推送、断网重连 | — |

### M1 做到哪里

手机接口目前只有对话、待批准的 Codex 动作和任务单、时间线、目标、审核记录这些。所以：

- 抽屉里的「任务小组」「旁聊」只写着去电脑上看，不显示列表，等 M3 有手机接口再接（M3 已接上）；
- 助理详情的「定时」只有说明；「身份」显示名字、手机权限和来源核对，性格与记忆的编辑留在电脑上；
- 抽屉里的「搜索」只查这台手机已经读到的主要聊天，不发请求；
- 抽屉右上没有「新对话」：主要聊天只有一段，旁聊等 M3。

审批卡、动态记录行、「等你处理」、状态胶囊、头像在 `OwnerViews.swift` 里各有一个组件，颜色、圆角和间距都用生成的变量，字号跟随 Dynamic Type。头像下面那句状态由 MobileCore 的 `AssistantStatusLine` 决定：连不上 → 等你处理的件数 → 在忙 → 只读 → 来源没读到 → 跟进中的目标数，读不到时照实说，不说成「没事」。

### M2 做到哪里

- **不加新接口，也不改 Caddy**。原来的 `chat/turn` 多返回两样：`partial`（到目前为止的回复，最多 2 万字）和 `steps`（执行步骤，每步一句，和 Desktop 时间线同一个 `tool_summary`，不带工具参数和结果，最多 30 步）。手机回合在跑时每秒读一次，有卡等你时每 2 秒；两次之间把新长出来的字逐步显示，所以比真正的流式慢一秒左右。打开「减弱动态效果」时直接显示全文。
- **执行过程**默认收起，只显示正在做的那一步，点开看每步和状态。
- **排队**：这一轮没结束（在跑或有卡等你）时可以照常写，点发送先排在手机上（最多 5 条，虚线气泡，可删除）。上一轮**正常结束**才自动发下一条；失败、结果无法核对、电脑上正有别的回合、旧请求要核对时停住，等你点「发出」，因为排队时写的话可能已经不适合上一轮的结果。队列只在这台手机的内存里，换登录或关掉 App 就没了；每条有自己的请求 id，重试不会起两个回合。
- 随手记不排队，有卡等你时也能直接记。

### M3 做到哪里

- 抽屉列出任务小组（进行中的在前，等你回复或验收的带小圆点，结束的变灰）和最近的旁聊；「等你处理」也算上等你的小组，点「去处理」打开群聊。
- 小组群聊：成员、经过、交付与原文；成员读过外部内容的消息标出来，只当纯文本显示。打开着每 5 秒读一次。
- 在群里说话、验收通过、退回（要写原因）都要 Face ID：前两样会让小组接着在常驻电脑上干活，验收会结束小组。停止小组用日常钥匙，先弹确认。
- 旁聊在手机上**只能看**：接着聊要在电脑上，或者在主要聊天里说。手机发起的回合只进主要聊天，不往别的会话里写。
- 7 个新接口见 [手机客户端架构](MOBILE_CLIENT_ARCHITECTURE.md)；部署前要在 97 的 Caddy 白名单里放行（仓库模板 `deploy/Caddyfile.mobile-proxy` 已更新，发布脚本在白名单缺路径时停下不切换）。

### M4 做到哪里

- 图标改成满版方形、无透明通道（源文件 `design/app-icon-ios.svg`），App Store 不再拒收。
- Info.plist 声明只用标准加密（`ITSAppUsesNonExemptEncryption = NO`），每次上传不用再答出口合规。
- `scripts/ios-testflight.py`：只从干净的最新 main 发；用 App Store Connect API 钥匙让 Xcode 自动签发布版；上传前核对推送是 production、不可调试、有 TestFlight 标记、扩展和团队对得上。步骤和真机验收清单见 `mobile/ios/ACCEPTANCE.md` 的 M4 一节。
- 要主人做的：在 App Store Connect 建 App、建 API 钥匙、把自己加进内部测试组。

之后再考虑：图片和附件、语音输入、点子页。
