# 手机端入口设计草案

日期：2026-10-25。状态：本地交互原型已完成；尚未实现生产手机客户端、跨设备审批或手机推送。

本轮参考用户提供的八张 Muse 手机截图。以下观察仅来自截图；没有操作 Muse，也没有验证其后端、权限、安全实现、语音、通知或截图中的新闻内容。截图仅保存在忽略的本地制品目录，不作为公开仓库资产。

## 设计决定

手机是常驻助手的随身入口，负责交代、跟进、查看成果和作出决定；常驻服务器继续拥有任务、会话、调度与执行记录。Desktop 保留项目开发、详细审查和交付操作。

默认进入主聊天。底部导航调整为「对话 / 动态 / 目标 / 成果」，各项同时有图标和文字。此前三张浅色概念图保留为探索记录，尚未选定最终视觉稿；本草案修订它们的信息结构，不表示用户已选定其中一张。

「待你决定」是跨页面入口，不增加一套独立审批状态。顶部保留紧凑的待处理提示，动态里同时置顶原事项；两处读取同一来源。无有效统计时显示「待核对」，失联时显示历史状态。

助手头像是稳定的身份和详情入口。详情分为「记录 / 待处理 / 电脑 / 定时 / 身份」。动态页展示工作摘要，详情中的记录展示执行过程；两者按原任务或回合关联。

## 页面规格

| 页面 | 首屏要回答的问题 | 主操作 | 详情与状态 |
| --- | --- | --- | --- |
| 对话 | 我正在和谁协作，可以交代什么 | 发送消息或补充当前要求 | 主聊天、旁聊、图片/文件、任务卡和决定入口；保留草稿与阅读位置 |
| 动态 | 助手做了什么、推进到哪里、哪里要我处理 | 查看待决定或待验收事项 | 顶部可折叠今日概览，随后是带来源、时间和状态的工作时间线；原工具步骤默认折叠 |
| 目标 | 长期事项下一步是什么、被什么阻塞 | 查看目标或在对话中补充要求 | 验收标准、关联任务和最新证据；首期可先只读，写入需原合同支持 |
| 成果 | 这次交付了什么、依据在哪里 | 预览成果或查看交付依据 | 文件版本、所属任务、仓库/提交/验证记录与适用范围；预览使用现有安全边界 |
| 助手详情 | 助手是否可用，当前有哪些能力和记录 | 查看记录、处理决定或查看电脑状态 | 记录、待处理、电脑、定时、身份；不把已配置当作已连接 |
| 决定详情 | 我将批准什么，后果是什么 | 明确批准、拒绝或回答 | 原文、对象、范围、来源、有效性与回执；过期和来源变化时重新读取 |
| 设置 | 修改哪台设备/哪个实例的设置 | 编辑明确归属的配置 | 手机外观与通知、设备配对、实例能力、账户与关于；连接服务不自动授予桌面控制 |

首次未登录时显示 VortoCode 账号入口；登录与常驻助手相同的账号后，选择该账号下已登记的助手，进入主聊天。普通使用不要求手动核对码。手动连接只放在高级自托管入口；设备不支持的能力按真实状态说明，不显示能点击却没有执行路径的操作。

## 两层导航

1. 主导航：对话、动态、目标、成果，首次默认对话；通知可直达具体事项。
2. 左侧抽屉：主聊天、旁聊列表、新旁聊、搜索、连接管理和设置。
3. 顶部助手入口：小头像、名字、当前服务连接与最后核对时间，点击进入助手详情。
4. 助手详情二级栏：记录、待处理、电脑、定时、身份；默认记录。
5. 待你决定提示：各主页面均可发现，进入同一个决定详情；详情只投影原确认对象，不自行维护审批副本。

「动态」的首版含义固定为工作动态。图 3 的兴趣资讯若后续加入，应在独立订阅范围中显示来源和日期，不能混进任务完成统计。随手想法先通过对话保存与跟进，是否增加「点子」独立页由真实使用决定。

## 关键流程与反馈

| 流程 | 用户可见反馈 | 必须保持的边界 |
| --- | --- | --- |
| 同账号登录并选择助手 | 显示账号下已登记的助手、连接状态和本次设备权限 | 使用稳定账号身份核验归属，设备会话可撤销；不把公网暴露作为默认前提 |
| 交代任务 | 草稿 → 发送中 → 已受理/未取得回执 → 执行状态 | 请求身份和范围稳定；未取得回执先查询，不自动用新身份重发 |
| 收到问题或审批 | 通知定位原事项，展示原文与影响范围 | 通知本身不批准；精确绑定实例、会话、任务、轮次和版本，旧决定不能作用于新轮次 |
| 完成工作 | 执行结束 → 待审查/待验收 → 用户确认依据 | done、收到回复、交付链接和用户验收分开；沿用现有目标验收规则 |
| 连接中断 | 最后核对时间、历史内容标识、保留未发草稿 | 失联不等于任务停止或没有事项；离线不排队自动批准，不盲目重放写入 |
| 查看电脑 | 助手服务、远程画面、操作权限分别报告 | 默认观察；接管需独立授权，不由头像绿点或服务连接状态推导 |
| 返回页面 | 保留阅读位置、输入和已展开的详情 | 后台更新不抢焦点、不强行切页，不因关闭手机而撤销服务器任务 |

语音入口按设备实际能力接入，需有录音、取消、转写和发送前核对状态；原型中的麦克风不能被描述为已实现。定时事项必须展示作用实例、时区、下一次执行和启停回执，看到页面不触发任务。

## 视觉与无障碍方向

深色方案作为本轮优先出图方向，实际外观计划跟随系统并提供浅色。学习截图的沉浸阅读与圆角浮层，使用 VortoCode 自有头像、名称和品牌标记。

| 元素 | 草案规格 |
| --- | --- |
| 画布 | 390 × 844 为基准，兼容 320–430 宽；保留系统安全区域 |
| 色彩 | 近黑底、深灰内容面、清楚的主副文字；蓝色用于主要操作，品牌橙只作识别 |
| 字号 | 正文 16–17，辅助文字至少 12–13，标题 24–28；跟随动态字体，不锁死高度 |
| 头像 | 主页面使用约 40–48 的紧凑头像，助手详情才放大；不压住消息 |
| 浮层 | 顶栏/底栏可以轻微模糊，正文使用稳定实色；减少透明度时切实色 |
| 导航 | 圆角底栏有图标与短标签，选中状态同时改变形状/底色和文字，不只依赖颜色 |
| 触控 | 主要命中区至少 44 × 44；支持系统返回、清晰关闭和焦点回到原入口 |
| 消息 | 助手正文以轻排版为主，只对任务、问题、交付对象使用卡片；长文有摘要与展开 |
| 状态 | 执行中、待回答、待验收、失败、历史待核对都有文字；只有有效验收依据才表达完成 |

原型应分别验证长消息、键盘弹出、放大字体、VoiceOver 标签/焦点、深浅色对比和减少动态效果；这些是待验收项，不是截图已证明的能力。

## 与现有框架的衔接

| 能力 | 现有可复用内容 | 手机端仍需补齐 |
| --- | --- | --- |
| 主聊天与旁聊 | Gateway 会话、actor、事件序号和回放 | 设备身份、可靠重连、主会话定位与移动输入；IM 历史只读投影不等于已实现跨端接续 |
| 动态与今日概览 | `assistantWorkday`、现有动态来源与 [统计合同](ASSISTANT_WORKDAY.md) | 手机投影、来源时效、通知定位和阅读状态，不增加任务库 |
| 目标 | 原目标、标准、证据及用户确认合同 | 手机表单与并发/迟到回执处理；只读与可写按服务能力分别开放 |
| 成果 | `ArtifactCenter`、现有制品及交付记录 | 手机安全预览和来源导航，不直接在手机执行生成的代码/HTML |
| 决定 | 原确认、问题、任务下派与核心控制合同 | 跨设备授权、精确对象定位、回执和撤销；不能假定现有 Desktop 原生确认可直接由手机代答 |
| 电脑与定时 | 原常驻连接、远程桌面、调度记录 | 手机连接呈现与能力发现；原生画面/接管和推送需单独验收 |

执行核心继续由服务端适配。手机消费统一身份、进展、结果和待决定对象；增加核心不会增加一套手机任务状态或把核心私有审批转成默认可批准。

## 分阶段落地

1. 设计原型：主聊天、工作动态、决定详情、助手详情和设置；目标/成果展示真实结构的只读示例。演示数据明确标注，不调用真实模型或执行任务。
2. 连接与读取：完成设备配对、实例身份、只读来源、重连与历史标识，再接聊天受理/事件回放。
3. 受保护写入：只有设备授权与原领域合同闭合后才开放手机回答/批准，先验证超时、换端、版本变化和撤销，不引入第二份审批记录。
4. 日常完善：通知深链、语音、文件分享、定时事项编辑与远程画面按使用收益逐项加入、分别验收。

首条验收链路是「手机交代 → 常驻执行 → 手机查看依据 → 明确作决定 → 各端一致显示回执」。原型、HTTP 联调、已安装 App、真实主机和真实模型证据分别记录。

## 当前可试用的原型

[手机交互原型](../prototypes/mobile-assistant/README.md)在独立目录运行，预览地址为 `http://127.0.0.1:5215/`。三张核心页面是主聊天、工作动态和助手详情；目标、成果、设置、旁聊与决定回执提供可点击的结构示例。具体截图与验收边界见[原型验收记录](../prototypes/mobile-assistant/design-qa.md)。

本轮采用深色视觉，并提供浅色切换。已检查 iPhone 393 × 852 与 Pixel 427 × 952 的模板预览，以及键盘、草稿隔离、断线禁用写入和两步决定流程。演示数据仅保存在页面内存中，刷新即重置；消息、批准、通知、定时和电脑连接都不作用于真实服务。原型没有更新已安装的 Desktop，也没有发布到自动更新通道。

下一阶段先接设备身份与只读来源，验证重连和历史状态，再接聊天受理与事件回放。手机写入和审批仍需原领域合同、设备授权与并发回执分别闭合。

开发进展：已建立[独立设备授权与只读 v1 通信基础](MOBILE_CLIENT_ARCHITECTURE.md)，复用现有助理名称、主会话登记和个人目标。通信包与原型分离；原型仍只展示模拟数据。当前继续同仓库开发，待协议与独立发布节奏稳定后再评估拆仓。

后续开发进展：同仓库增加 [mobile 浏览器入口](../mobile/README.md)，已接两端核对码配对、电脑端设备管理及真实只读合同。此界面是接入阶段的读取入口，尚未实现完整四项导航和原生长期连接；原型仍用于打磨最终体验，临时验收实例与用户真实数据分开。

用户后续确定：默认通过同一 VortoCode 账号关联，核对码仅保留为高级方式。现有账号登录、手机登录、助手登记/发现与运行端授权的区别见[账号连接方案](MOBILE_ACCOUNT_ACCESS.md)；当前默认页已按此调整，同账号自动连接的服务接入尚未完成。

2026-10-26：手机 Web 的同账号 OAuth 与当前运行端授权已接通，Desktop 有原生关联设置卡片；云端目录仍未接入。同仓库新增 [iPhone 入口工程](../mobile/ios/README.md)，实现原生连接首页/设置和系统浏览承接原 Web。这是第一版原生入口，尚未把本草案中的四项导航、聊天、审批与通知实现成原生页面，不能把已构建工程称为完整 App。

0.2.0 更新：已建立原生概览、目标列表/详情和设置，系统认证 + Keychain + Swift 读取均已实际通过隔离模拟器验收。当前只读阶段采用三项导航；本草案四项导航、聊天、审批和成果页仍需后续原合同接入。
