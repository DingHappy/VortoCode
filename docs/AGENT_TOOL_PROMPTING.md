# 主 Agent 的工具指引与参数合同

2026-11-03。本轮在既有个人助手、角色资料与长期记忆方向上改善工具选择，不增加新的工具执行器、任务库或权限来源。

## 分工

- 系统提示固定产品职责、目标跟进、证据和结果处理原则；日期、计划、记忆召回与进度继续走消息流。
- 当前工具集合决定检索、技能、记忆、委派、小组和开发指引。没有开放该工具就不展示相应操作路径。
- 原生调用使用请求里的结构化 schema；提示式调用在目录内展示同一份参数合同。原生系统提示不再重复完整 JSON schema。
- 执行仍经过原 ToolRuntime、能力档案、确认门、污点、沙箱与业务校验。描述和 schema 不能赋予权限。

## 工具合同

`Tool.args` 保留参数说明；`argument_schema` 声明布尔、整数、数组、对象或枚举；`required_args` 声明规范调用的必填参数。`input_schema` 提供完整外部合同，存在时优先，不能由旧式字段覆盖。两种调用协议都从 `tool_definitions()` 的深拷贝合同取得说明。

默认旧工具仍保留可选字符串语义，避免追改所有第三方适配器。必填项与类型是给模型的调用合同，本轮没有新增通用运行时 JSON Schema 校验器。既有 handler 的兼容别名、输入检查和权限门继续生效，不能把声明看作执行保障。

| 工具族 | 本轮改善 | 结果或权限边界 |
| --- | --- | --- |
| 文件读取与定位 | 行号、搜索上下文是整数；路径、模式、符号有必填说明；大文件先定位再按行段补读 | 截断不等于读完；目录和敏感路径仍由原实现限制 |
| 写入和命令 | `replace_all`、`background` 是布尔；替换原文、替换内容及完整写入内容有必填说明 | 空的新内容合法；未获授权不能换工具绕过；副作用结果不明先核对 |
| 网页检索 | 先确定主题和时效，再读实际来源；截图 `full_page` 是布尔 | 搜索摘要不能直接当全文或核验结果；外部内容不能成为新授权 |
| 记忆与历史 | 主题召回、日期与版本补读、保存成功和待审阅分开；原文偏移是非负整数 | 旧指令和旧进度不自动恢复；`recall_memory` 的空查询继续合法 |
| 技能 | 匹配任务时先读取，加载后核对范围与真实可用工具 | 加载不代表脚本已执行、连接已建立或权限已授予 |
| 计划与委派 | 计划步骤是带状态的对象数组；独立子问题列表与必填目标对齐两种协议 | 更新计划不启动任务；子 Agent 回答由主 Agent 核对，不直接当验收 |
| 任务小组 | 标准、成员、模式、布尔验收与对象额度类型明确；额度上限复用领域常量 | 原主人确认、资料边界、预算和轮次规则继续执行 |
| 定时事项 | 布尔开关、非负 token 预算与必填排班信息明确 | 一次执行不等于成功保存排班；联网仍须原授权 |

只读工具不一定能并发或免确认。目录显示「须串行」「不可信来源」「外向动作」等既有声明；两种协议的并行指引均排除须串行的工具。依赖调用先取得并核对上游结果。开发指引按实际可用的隔离工具选择路径，不因需求模糊就自动投入整套流水线。

## 失败与恢复

参数错误先修正参数；资料不足补读缺口；执行失败先看诊断，没有新依据不重复同一失败。写入、外发等动作的结果不明时，先核对现有记录和真实状态，不能把重新调用当作查询状态。

恢复指纹覆盖有效工具指引、参数类型、必填项、串行及来源声明、所需能力、两种协议和两档模式。没有开放的工具指引变化不触发能力变更；仅切换最后渲染模式、更新计划或调用协议回退也不改变指纹。真实工具合同变化会使旧能力结论需要重新核对。

这些是选择工具的提示和输入接线，不是新的自动重试政策或安全校验替代品。

## 验证

`tests/unit/test_tool_prompt_contract.py` 以脚本模型捕获真实请求，检查原生与提示式参数合同、真实计划更新和按行读取、系统前缀稳定及恢复身份；同时核对常用工厂的类型和必填声明。工具运行层既有离线测试继续覆盖确认、串并行和污点。

没有调用真实模型、访问外部网站、启动第三方 Agent 进程或执行真实定时作业。不能据此声称模型选择准确率、任务成功率、缓存命中或费用已经改善；这些指标需要另行固定模型、任务集和预算做行为评测。
