## 反例与处理

离线替身模型在等待期间，插入一条人工指令，并完成批准、认领与成功回执。
观察员尚未报告新轮次，结束时又没有待处理动作，原检查因此接受旧 continue，生成
“继续旧计划”；旧 done 也能收回当前交接。明确失败回执同样不能撤销指令曾变化的事实。
这是合成竞态，不是生产事故或真实 RPC 证明。

现在在判断开始时保存会话动作版本，模型返回后复核。变化使 continue/ask/done 全部
作废；已经认领的判断和 Goal 已用次数保留，不退款、不自动重评。同一版本还进入自动
拟话、拟叫停的锁内创建检查，以及普通 done 的比较后收回，覆盖检查后再发生新动作的窗口。

每条新自动动作保存创建提交后的 action_version。批准、认领及原清理路径再次核对，
即使后来的人工动作已经结束，也不能执行旧建议。动作自身的合法状态更新同步推进它的
依据版本；其他动作发生变化后，旧依据不会被补绑或刷新。人工新提议仍逐条由用户批准。
已认领的外部执行仍按原 ID 收回执，不因版本变化重发、取消或伪造结果。

Goal 的待用户处理原因也保存版本；版本已变或旧原因无版本时显示暂停核对，不能继续
展示旧判断为当前结论。通知是生成时的观察，不承诺撤回已经送出的旧通知。

## 单文件提交与兼容

原 .vortocode/codex/actions.json 首次写入时，从旧数组迁移为：

```json
{"schema_version":1,"store_id":"32位十六进制身份","thread_revisions":{"会话ID":1},"actions":[]}
```

示例仅展示结构。实际 actions 列表和版本在原动作锁内，经同目录临时文件一次替换。
保存失败两者均不推进；外部执行仍须等待成功认领。load_actions 和 HTTP 对外仍返回原列表。
读取旧数组不改文件，旧自动草稿缺少动作版本时要求重新拟定，不通过迁移补授权。
旧格式快照只用于变化检测，不是权限来源；首次迁移保守地使其他会话的旧格式判断失效。
迁移后其他会话正常写入不会改变本会话版本。

版本表最多 256 个会话，计数为 1 至 2^53-1。只裁剪没有保留动作、也无当前交接的会话版本；
有交接的版本不会随 100 条历史裁剪清零。达到容量或计数上限停止写入，不回绕或清零。
显式未知 schema、非法身份/计数/版本、缺失关联均按原存储错误保留文件，HTTP 返回 503。
不把损坏的新版对象降级为旧数组。旧写入器覆盖为数组再迁移会生成新的 store_id，不能
恢复旧自动动作的授权依据；这不等于允许混用旧写入器。

部署前应备份并停止旧服务写入，再整体切换同版本。旧服务不能保证理解新文件，不能热混跑。
整体回滚备份、任意文件篡改、文件彻底删除、硬盘损坏与掉电 fsync 保证不在本合同内；
不能以新字段宣称具备外部恰好一次执行或自动灾难恢复能力。
