# 常驻助理任务交付

2026-10-12。本轮修改源码，不替换已安装应用、不部署常驻服务。

助理负责收集、提议、跟进和汇报；项目工作台继续使用原 TaskLedger、TaskRunner、隔离开发与审查机制。

## 交互任务卡

助理对话显示所属会话的最近任务卡，右侧动态显示待确认卡并支持点开任意任务单。目标、验收标准和外部内容提示在下发前可读。

- 等待确认：确认下发或撤回，沿用显式确认与决策审计。
- 正在下发 / 提交结果待核对：读取实际状态；支持幂等提交的任务可使用同一请求标识继续提交，不能撤回为“从未执行”。
- 执行中 / 等待处理：核对状态或打开对应常驻项目任务。
- 执行结束：展示分支及结果，打开项目任务；当前任务已结束且具有分支时进入原分支审查入口。重验和 Draft PR 沿用工作台原闸门。
- 显式核对终态任务时读取原项目审查快照，展示当前 commit、绑定该提交的验证结果和精确文本 hunk 审查数量。验证提交不匹配、证据失效或缺少有效时间时分别显示过期/未知，不从结果文案推断测试通过。快照任务、分支与 commit 必须匹配；读取失败不覆盖已核实的任务执行状态。
- 失联：保留上次执行状态，同时显示当前无法核实、上次成功核对时间；断开连接时禁用动作。

执行结束、代码验证、人工验收与 Goal 达成分别管理。卡片不提供自动合并或绕过重验的 PR 按钮。

助理复盘的验收对照始终按任务单原始标准的顺序和数量展示。模型漏报、替换标准、重复或矛盾地报告同一标准时，相应原标准标为「无法确认」，不能缩小分母形成「全部对上」；声称通过或未通过但没有文字依据时也保留待核对。模型自行新增的标准不进入原任务的验收计数。失败复盘的 `retry` 只接受布尔值，诊断与重试做法只接受文本；类型不合规视为无效复盘，不起草重试单。

PR 前多视角审查合并同一问题时保留所有有效报告者，包括失败后重试才报告的视角。修复后任一原报告者未完成复审，都保留未解决的问题并交人工处理；修复仍最多一轮。非字符串证据作为格式错误处理，不转换成文字后触发自动修复。这些检查校验格式、来源和完整性，不证明模型所述证据本身已经独立验证。

## 下发与恢复合同

任务单保存固定 request_id；项目运行时将其映射为稳定任务 ID，首次创建即持久化，重复请求只返回原任务。相同标识但 prompt 或 owner_session 不同返回 409，不重新排队。记录损坏时拒绝重建。

下发前 GET /api/tasks 的 submission_idempotency 必须为 1，submission_scope.repo_root 必须与登记的规范目录一致。POST 同时携带 expected_repo_root，由接收端在创建任务前再次检查；GET /api/tasks/{id} 的 execution_scope.repo_root 和任务 ID 用于回读核对。旧运行时缺少这些身份字段时停止下发/核对，需要先更新项目服务。HTTP 超时、响应丢失、取消或进程退出不能证明远端未创建任务；已记录的请求标识与目标用于核对和安全重试。返回异常任务 ID 时保留记录并阻止重复下发。

每张任务单的发送和核对共用跨进程锁；台账更新另有短事务锁。任务首次发送固定目标登记的端口与目录，登记变化时不把原任务交给其它目标。旧 send_failed 记录缺少幂等身份时必须人工核对，不自动补发。

后台核对只发 GET，不自动提交、续跑或批准任务。正常轮询最多核对 20 个非终态任务，并发最多 4 个，优先较久未核对的条目；GET /api/dispatches?refresh_id=<id> 可显式核对一张终态任务。进程恢复后的已有任务不因重放请求再次执行；中断任务通过原工作台恢复流程处理。

活动任务单上限 200；保留最近 200 个终态记录，较早终态先完整写入 .vortocode/dispatches/archive/ 再移出活动台账。未完成任务不会被新记录挤掉。坏台账保留原文件并明确报错，不当作空台账。

## 客户端与验证边界

任务卡快照绑定当前运行端；异步动态、任务单、资料、手机历史、记忆与定时资料的响应检查当前连接与范围。动态刷新同时检查请求轮次，旧请求不能覆盖新结果。

后台动态刷新与手动核对共用按连接/范围绑定的有限队列：重复轮询合并，手动事项逐个保留，相同事项合并，最多 16 个在途/等待项。手动核对只读取任务，失败回到卡片；换连接后新请求不等待旧连接。资料保存会使此前的读取失效，防止迟到响应恢复旧名字。

同一连接/范围上的任务卡共用操作锁，包括确认框等待期间。交付导航独立在 assistantNavigation 中：先比对任务单固定目标与登记表，再检查登记结果和已连接项目身份；任务回读还必须匹配原任务 ID 与实际规范目录。取消切换或旧连接的迟到响应不再推进审查；历史任务单缺少固定定位时提示用户手工核对。预检失败、尚未创建的任务不提供“打开项目任务”。

自动测试使用受控 worker、临时台账和 ASGI 请求，不调用真实模型。浏览器夹具使用实际卡片和产品 CSS，覆盖按钮状态和交互，但不证明已安装 Tauri、真实常驻主机切换、实际 Git diff/重验/PR、手机消息或真实模型效果。原生与正式发布仍单独验收。

## 定时事项交互卡片（2026-10-12）

普通 cron 作业提供暂停、恢复、刷新和执行记录。早晚报、任务跟进与 Heartbeat 仍按运行端环境配置管理，卡片明确标为配置管理，不提供无效开关。作业启用与调度总开关分开显示；总开关未开启时不把理论 next_due 表述为将实际执行。

启停请求只接受已有作业名、严格布尔值及读取时的整个 cron.yaml SHA-256 版本。配置内容与版本来自同一次文件读取；配置变化返回 409，用户刷新后再决定。Desktop、CLI 与助理工具的四个配置写入口共用跨进程锁，复用原单行编辑与解析回验；人工直接改文件不参与该锁。暂停仅阻止后续排期，不中断已在跑的任务。

执行记录复用 RunLedger 中 kind=cron 且 sandbox.cron_job 精确匹配的条目，最多读取最近 200 个保留记录并返回该作业最多 10 条，仅投影时间、状态、摘要及错误。没有记录不等于从未运行；手动执行不更新定时 last_run，因此“上次定时执行”与实际结果历史分别展示。台账不是永久审计存档。

卡片操作期间禁用按钮并以同步 ref 防重复点击，断线禁用读取与写入。App 的加载轮次防止旧列表覆盖新配置，主机切换后异步响应不更新新主机卡片。配置保存成功但后续读取失败会明确提示已保存、需要重新核对；HTTP 提交响应丢失仍需刷新确认，不自动重试修改。

### 幂等提交排队中断恢复（2026-10-13）

修复一个持久化后的崩溃窗口：幂等提交任务已经写盘，但尚未成功进入执行队列时，进程退出后原记录可能一直停在 queued；同 request_id 重试只返回原记录，不会执行，却误显示为仍在排队。

启动恢复现在识别 dev 类型且 ID 严格符合保留的 `task-submit-<32位小写十六进制>` 格式的 queued 记录，将其持久标记为 interrupted，并注明未自动重放、需要核对原任务及持久计划。沿用原 TaskRunner / 台账 / 状态通知，不增加后台池或自动执行。助理重新核对原远端 ID 后显示 stopped 与中断原因；原 request_id 仍返回同一记录，不创建替代任务。

没有持久 plan_id 的任务不能通过恢复入口重新执行；有计划的任务仍由原 TaskRecovery 检查停止状态、计划/分支/版本和既有恢复记录。其他类型、普通历史 queued、仅含类似前缀的 ID 及完成任务不因该规则改变。中断状态保存失败时启动恢复报错，不发送成功通知。

工程回归覆盖落盘后 enqueue 失败、重启识别、重复提交不执行、助理仅 GET 核对原 ID、无计划拒绝恢复、无关记录不变，以及持久化失败。未重启现有运行端、未安装候选包、未进行真实主机故障注入或新增模型调用。

### 助理核对恢复任务

助理任务单的显式“核对状态”现可读取项目工作台已验证绑定的第一层恢复任务。项目任务快照在存在合法恢复记录时返回原任务的 `recovery_source_revision`；助理按固定恢复 ID 读取子任务，并校验实际项目目录、父任务、类型、prompt、owner、Goal、plan及恢复合同版本。异常 ID 不会用于读取其它任务。

原任务 status/error/remote_task_id 保留，新增独立 recovery_task/recovery_error 投影。卡片显示上次核对的恢复进度、时间、分支和执行结果，保留原失败记录；恢复执行结束仍待审查。恢复任务的验证证据使用其自己的任务 ID、分支和提交核对；审查失败不把进度抹掉，也不生成验证通过。资料不匹配则清除本次恢复投影并提示无法核实。

该操作只 GET，不创建、不恢复、不重新提交任务；原 request_id 的幂等身份不变。普通轮询不扫描恢复链。最多观察一层，若恢复任务还有后续恢复，提示到原项目查看完整链；原“打开项目任务”入口仍定位原任务，由工作台提供恢复导航。旧运行端缺少合法版本信息时不能确认恢复关联，需要更新运行端或在项目中核对。

### 恢复展示的版本失效处理

恢复观察现在保存原任务 source_revision。普通刷新也会在原有每轮最多20张、并发4个的限制内核对已有恢复缓存的原任务，包含已完成的恢复缓存；每张仍只 GET 原任务，不读取子任务或审查接口。原任务的恢复 ID、计划、停止状态或合同版本变化，或旧运行端无法提供版本依据时，清除旧恢复展示和其中的验证证据，并提示显式重新核对。

关联仍匹配时保留原恢复观察的 checked_at，不用普通刷新的时间伪装成刚核对了子任务进度。网络不可达时保留历史观察，sync_state 标记不可达，卡片明确提示恢复信息为上次记录、当前无法重新核实。显式刷新没有再找到合法恢复关联时也给出说明。该版本校验只针对恢复关联；子任务当前进度和提交仍须显式读取核对，不是持续实时验证。
