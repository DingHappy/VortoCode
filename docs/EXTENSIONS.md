# MCP、Skill 与插件接入

VortoCode 的「插件」页集中展示 MCP 连接和项目扩展。当前已有接入与权限边界；还没有统一插件商店、任意插件一键安装、插件自动升级或通用第三方应用授权中心。

| 类型 | 当前入口与能力 | 使用范围 |
| --- | --- | --- |
| MCP 工具服务 | 插件页手动连接、刷新状态、重新连接；读取目录后按权限调用工具 | external/unattended 会话；local 会话拒绝外部 MCP |
| 带凭据 MCP 连接器 | 从已配置的名称读取用户私有凭据；默认只读，并筛除未声明只读的工具 | 私人助理 General；不在 Project/Scratch 加载连接器凭据 |
| GitHub 设备授权 | 助理「身份」页的已配置连接器可发起设备授权、查看状态和删除本地凭据 | 配置了 GitHub App 的连接器；不是任意应用的通用授权 |
| Skill | 发现 `skills/` 与 `.vortocode/skills/` 中的 `SKILL.md`，先提供目录，`use_skill` 按需加载正文；`save_skill` 经确认保存 | 项目/工作区；General 暂无独立个人 Skill 目录，不读取项目 Skill |
| Hook 与项目规则 | 查看当前来源、覆盖关系及信任状态；Hook 使用既有信任开关 | 项目范围；不会因查看插件页而执行 |

项目规则的发现和加载均只读取规范化工作区内的普通文件。规则文件或父目录的符号链接指向项目外、链接失效或循环时会跳过，并继续按现有优先级查找其它规则；项目内的链接仍可使用。用户自己的全局规则使用原独立加载路径，不会因这个项目边界被重新定位到仓库内。

连接成功只证明服务目录已读取，不能代替真实应用调用、授权范围和结果验收。MCP 资源/提示支持与协议限制见 [MCP HTTP](./MCP_HTTP.md)。

## 私人助理连接 MCP

1. 打开私人助理会话并完成一次对话以初始化会话，再进入「插件」。
2. 服务须由操作者预先写入该运行实例的 `config/mcp.yaml`。插件页当前不编辑配置、不安装服务，也不提供凭据输入。
3. 点击「连接已配置服务」。这会读取配置、连接服务并发现目录，不调用模型或执行工具；会话忙碌时拒绝更新。
4. 之后由当前会话按工具权限使用服务。只读连接器仅暴露 `readOnlyHint: true` 的工具；返回内容仍按外部不可信内容处理。

手动连接无需开启 `VORTOCODE_WEB_MCP`。该环境开关只控制原来的 Web 首回合连接路径。两条路径都仅在 General 允许带命名凭据的连接器，缺失或未知范围不会继承此许可。

带凭据连接器使用既有 `credential` 名称和用户私有凭据文件合同，凭据只进 HTTP 头，不放在 YAML 的 `headers`、URL、聊天或 Skill 中。以下是关闭状态的虚构配置；它不会建立服务：

```yaml
servers:
  - name: example
    transport: http
    protocol: streamable_http
    protocol_version: '2025-06-18'
    url: https://connector.example.test/mcp
    credential: example
    read_only: true
    enabled: false
```

凭据须在运行服务的同一系统用户下保存为私有普通文件。已配置 GitHub 设备授权的连接器，可从助理「身份」页完成授权并保存凭据，再到插件页连接当前会话；其它服务需操作者预先配置。本页不要求在对话中提供凭据。缺凭据或权限不符会跳过该连接器，手动连接失败保留原连接与工具；失败尝试不会刷新旧目录的成功观察时间。重试期间会话被替换时，新连接会被清理，不接入另一会话。

支持本机撤销的运行实例在断开时，会先禁用该凭据对应的所有本进程 MCP 连接器能力，移除已有 Web 会话中的对应工具，再尝试删除本机凭据、取消待处理授权并关闭本地连接。同一凭据对应多个服务别名时一并处理，其余已连接服务保留。操作不代表 GitHub 侧授权已撤销，也不证明已发出的远端请求停止。

身份页按运行实例的 `local_revocation_supported` 能力显示「断开本机连接」；旧实例仍显示「移除凭据」，旧版删除回执不会被解释为已禁用连接。凭据状态与插件页的会话连接观察独立：可用、未保存、不可用、已过期、待确认。查询会复用实际连接器的凭据文件校验，并检查已知有效期；损坏、过大的或指向其它文件的授权元数据会显示待确认，不推断为永久有效。手工配置凭据允许没有 OAuth 元数据。

`/api/assistant/connectors` 返回 `credential_status`、`credential_available`、`credential_error`、`authorized_at`，以及 `connection_status: unobserved`；只检查本机文件，不调用供应商或 MCP 服务。旧 `connected` 字段保留为凭据可用性的兼容别名，不是服务连接证据；新界面不使用该字段推断连接。真正的当前会话目录连接观察仍来自 `/api/extensions/mcp`，也不代表真实工具调用已验收。旧运行实例未提供新字段时，界面显示待确认。

Desktop 的凭据快照绑定当前运行实例；切换主机或运行实例后，不展示旧快照或接收旧请求的迟到结果。授权轮询合并同一来源的在途查询，凭据操作后重读状态，并忽略操作前的旧查询响应。确认窗口期间切换运行实例也不会把原操作发给新的实例。

### 本机断开回执与竞态边界

- DELETE `/api/assistant/connectors/{name}` 保留 `removed`，并返回 `calls_blocked`、`revocation_scope: current_process`、`credential_cleanup_confirmed`、`connections_disabled`、`closed_connections`、`cleanup_status`。凭据删除和连接清理分别确认；`cleanup_status` 可以为 `unconfirmed`，不会因此恢复后续调用权限。
- 清理使用共享的 5 秒合作式超时额度；异常、超时或取消会保留未确认状态。这不是 OS 强制隔离或强杀保证。仍在建立的连接不会提前算作清理完成，迟到的连接结果会被拒绝并继续清理；同一会话的旧清理结果不能覆盖新的成功连接观察。
- 实际传输调用在权限确认之后再次核对凭据文件身份，返回结果后也会核对。已删除、权限变化或替换的凭据不会继续为旧连接授权；撤销后到达的工具结果会被丢弃。旧工具引用、资源/提示工具和同进程其它会话共享相同约束，不重放被打断的调用。
- 首次设备码请求和后续令牌响应都绑定当前授权尝试；取消、替换或过期后的迟到响应不能写回凭据、覆盖新验证码或清除新尝试。失败信息不返回原始供应商载荷。
- 清理文件失败时，当前进程保留该凭据身份的撤销标记，不能靠旧文件自动重连；重新授权生成的新凭据可显式建立新连接，但不会复活旧引用。该标记是进程内状态，不能替代凭据文件删除或供应商撤销；文件清理未确认时，不能据此认定重启后仍已撤销。
- 其它进程不接收即时广播，但标准连接器会在下次调用时检查凭据文件身份。当前进程的回执不代表其它机器或进程的连接已关闭。`remote_requests_verified` 和 `provider_authorization_revoked` 均为 `false`，应在供应商侧单独核实。

## 项目 Skill

项目技能以 `SKILL.md` 保存名称、描述与正文指令。`.vortocode/skills/` 的同名定义覆盖 `skills/`；越过工作区的符号链接和过大的文件会被忽略。正文中的相对引用以技能所在目录为基准；加载正文不等于自动执行脚本，也不会扩大文件、命令、联网或发布权限。

私人助理的个人 Skill 管理、GitHub 之外的通用应用授权/撤销和安装后真实任务验收仍待接入。不要把项目技能清单或 MCP 配置文件的存在当作这些能力已完成。
