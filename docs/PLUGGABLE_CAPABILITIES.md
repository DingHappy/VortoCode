# 可插拔能力：共同权限，按领域接入

2026-11-01。浏览器、手机设备和外部业务服务按可插拔能力演进；会话、任务与安全规则继续由
现有 runtime 管理。已实现浏览器驱动接口与原 CDP 接入、Android 已有会话首个切片；通用设备
合同和统一插件管理仍是后续设计。

实施补充：[Android 已有会话插件](ANDROID_SESSION_PLUGIN.md) 已接入默认关闭的生产装配，
支持绑定 Appium 原生会话、投影及确认点按；未创建会话或安装设备依赖，真实模拟器仍待验收。
下文的通用 DeviceDriver 与统一管理合同继续作为目标，首个 Android 实现不提前抽通用设备框架。

## 分层与当前基础

| 层 | 职责 | 当前接点 |
| --- | --- | --- |
| 框架核心 | 会话/任务归属、能力档案、确认、污点、预算、取消、审计、恢复和验收依据 | 原 MainAgent、SessionActors、TaskRunner、ToolRuntime 与领域台账 |
| 能力适配器 | 连接某种资源、观察、执行单次动作、取消和清理；声明自己支持的操作 | 内置助理插件、MCP、浏览器 BrowserBackend/BrowserDriver 与 Android 已有会话适配器 |
| 业务流程 | “检查项目进展”“处理某网站表单”等可复用指令，组合已授权工具 | 原项目 Skill 与已批准的个人 Skill；Skill 本身不提供新权限 |
| 产品管理 | 展示能力状态、来源、作用范围、支持的动作及确认要求，接入/停用 | 沿用现有插件/定制入口；当前浏览器仍跳转原设置，尚无设备插件管理卡 |

助理插件 `src/plugins/`、MCP 与 Skill 已有不同的凭证、协议和生命周期合同。统一管理信息时
保留这些合同；网站 Cookie 不转换成 `.token`，设备认证也不挪进 MCP 配置。
复用 [工具运行层](TOOL_RUNTIME.md)、[助理插件](ASSISTANT_PLUGINS.md)、
[MCP 接入](MCP_HTTP.md) 和 [网站连接](WEBSITE_CONNECTIONS.md)，不增加第二个工具执行器。

## 本轮已实现：浏览器驱动可替换

`src/browser/backend.py` 定义纯 Python 合同：

- `BrowserBackend`：冻结的驱动 ID、接口版本、支持的 `desktop/mobile` 网页模式和创建函数。
  只接受当前 API 版本，未知模式或版本拒绝，不协商降级、不自动切到另一驱动。
- `BrowserLaunch`：宿主提供的专用目录与网页模式。构造声明不检测浏览器、不启动进程，工厂
  返回未启动实例；`BrowserSession` 持有租约后才启动。
- `BrowserDriver`：运行状态、启动/关闭、页面求值、导航、观察、点击/输入和滚动。
  `close()` 只有确认自身进程退出后才能成功返回；出错保留清理占位，沿用原显式重试路径。
- `chromium_backend()`：当前生产唯一默认驱动，复用原 `CdpBrowser`。宿主代码可向
  `build_browser_tools(..., backend=...)` 注入另一个经审阅实现，工具名称与网页确认逻辑保持相同。

传输驱动不构造 Tool，不决定动作是否免确认，也不持有确认回调、模型、任务存储或自动恢复循环。
人工登录、域名检查、DOM 投影、每次确认、撤销与资源清理由原 `website_browser` 适配层管理。
`browser_connections` 返回驱动身份、接口版本与支持模式，便于解释“当前能做什么”。

各驱动的 profile 分开：原 CDP 保留 `profiles/<connection_id>`；其它驱动使用
`driver-profiles/<connection_id>/<backend_id>`，不复制旧 Cookie。无论驱动是否相同，一个网站连接
共用原目录下的所有权锁，不能借换驱动绕开当前占用。换驱动首次启动仍交还真人登录。
接口版本不是浏览器协议或 profile 格式版本；驱动 ID 代表稳定且兼容的实现身份，改变不兼容
profile 格式时必须换身份并建立新目录，不能继续加载旧数据。

这一步是受信任宿主的可替换接口。**没有第三方安装器、插件市场、动态 Python 导入、远程下载、
项目目录扫描或用户可选驱动配置**。模型参数中的 `backend_id/module` 不能选择代码。
`browser_factory` 保留为旧可信测试兼容入口，与 `backend` 不得同时提供。
驱动运行在当前宿主进程信任边界内，接口不是恶意插件沙箱；第三方实现不能只凭自报能力取得信任。

## Android / iOS 的插件边界（Android 首个切片已实现）

原生 App 使用自己的 DeviceDriver 合同，保留 Android/iOS 各自观察与操作语义；不要求原生
设备实现 JavaScript `evaluate()`。共用的是上层操作归属、审批和生命周期规则。

| 接入 | 驱动边界 | 权限目标 |
| --- | --- | --- |
| 网页 | Chromium CDP，桌面/手机网页是同一驱动支持的两种模式 | 宿主 + 工作区 + 网站连接 + 精确 origin |
| Android | 模拟器/真机连接，具体驱动单独接入 | 宿主 + 精确设备身份 + 连接代次 + 应用包身份 |
| iOS | Simulator/真机连接，具体驱动单独接入 | 宿主 + 精确设备身份 + 连接代次 + bundle 身份 |
| 网站/业务服务 API | 已有可信助理插件，或原权限范围内的 MCP | 凭证所在宿主 + 允许的服务/目标/动作 |

设备发现只提供候选，不能触发安装应用、启动设备、读取登录态或自动授权。支持的动作逐项
声明：观察、截图、点按、输入、滑动、启动应用等；缺失能力明确拒绝，不能退成任意 shell。
执行前核对目标与代次，确认等待期间再次核对；认证留在设备上完成。断连后不自动改用另一设备，
也不重放结果不明的提交。真机/模拟器、桌面/手机网页分别报告验收结果。

## 启停与升级合同（后续管理层必须满足）

1. 读取元数据和依赖状态是无副作用检查；“已安装/可连接”与“已授权/业务验收通过”分开。
2. 宿主显式选择经审阅的实现、固定版本与来源，核对目标和能力，再按原确认门启用；模型不能安装或授权插件。
3. 每次调用从原工具运行层检查当前权限；审批至少绑定实现/目标/连接代次及具体动作，插件不能自己提高授权档位。
4. 停用先阻止新调用，取消并等待已有动作退出，最后清理与释放租约。已发出的外部业务请求不因停用自动撤销。
5. 忙碌时不替换实现。清理结果未知时保留占用和未知状态，不发布新驱动、不删除数据，不自动回滚重试外部动作。
6. 升级按新会话/显式重连生效；同一会话的系统提示保持稳定。原业务记录与凭证留在各自领域，卸载能力不删除任务证据或隐式清空登录态。

这些统一管理操作尚未写入新的 API/UI，也没有把现有 MCP/Skill 的启停流程改造成另一套注册表。
未来外部驱动如需要进程隔离，可评估受限子进程/MCP 传输，但须另验秘密隔离、目标权限、取消和清理；
本轮不放宽 Desktop local 会话的外部 MCP 规则。

## 防止循环和依赖膨胀

插件只提供单次有界操作，不自行创建“观察→判断→重试”的常驻 Agent 循环。长任务、定时工作
继续交给原 TaskRunner/调度；预算与取消作用于原执行，不因插件内部换工具或重连清零。
需要人工登录、权限未知、目标变化或结果不明时停止自动推进，交回原任务核对。当前浏览器
没有内部自动登录轮询/业务重试；模型回合仍受原预算约束，不能宣称已实现所有插件的统一硬预算。

不预先安装手机 SDK、浏览器包或所有平台依赖。先验证当前浏览器替换合同，再接一个 Android
模拟器 App；有第二个真实设备实现后，依据实际共性抽取 DeviceDriver。统一管理界面最后
消费原状态和合同；当前不做远程插件市场、任意代码热加载或通用插件调度平台。

离线验证覆盖替换实现后的原确认门、人工接管、独立 profile、跨驱动连接独占、能力不支持、
未知版本、驱动启动/清理失败及模型不能选择代码。假驱动不是第三方插件、真实手机或业务验收证明。
