# 私人助手能力与题库

2026-10-12。目标参照 Meta Muse 的长期记忆、持续跟进、目标推进和执行前授权，复用 VortoCode 的 General 会话、记忆写入策略、cron、任务单和项目工作台；不另建代理运行时。

[Meta 官方介绍](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)描述了跨应用行动、记住用户、关闭界面后继续工作，以及需要批准时回来询问。VortoCode 当前交互任务卡、记忆候选与定时事项已有对应基础；真实跨应用执行、长期目标自主管理和个人助理综合效果尚不能据此宣称达到 Muse。

## 当前新增能力

General 的交互助理新增当天对话记录、定时列表和指定作业的执行历史读取。即使此运行端的调度总开关关闭，这些只读工具仍可用；定时创建/修改工具仍只在调度实际开启时提供。通用范围仍没有文件、命令和 Git 能力。

汇报时区分聊天摘要、实际执行结果、提交验证和人工验收。定时列表显示调度总开关；历史来自原 RunLedger，保留范围为空不等于从未执行。派活工具明确 done 是执行结束待审查。

## 可直接运行的题集

原开发评测：10 个固定维护任务，默认入口不变。

```bash
python -m evals --list
python -m evals --via-agent --scenario pagination_boundary
```

新增私人助手题库：[cases.json](../evals/assistant/cases.json)，14 个原创中文场景：

- 记忆：偏好召回、用户当下信息覆盖旧资料、摘要窗口外的信息检索。
- 诚实性：不知道的信息、没有运行记录、执行结束尚未验收、失联状态。
- 持续跟进：当天记录、调度总开关、实际失败原因。
- 行动与授权：暂停排期、拒绝恢复、拒绝记忆写入、只提出任务单而不执行。

```bash
python -m evals --suite assistant --list
python -m evals --suite assistant --live --scenario schedule_failure --protocol native
python -m evals --suite assistant --live --protocol native
python -m evals --suite assistant --live --model <model> --repeat 3 --out evals/reports/assistant
```

助手题集的模型调用必须显式 --live。每题最多 5 个正常工具步骤、6 次模型请求、每次请求 2048 个输出 tokens 和整题 90 秒；限制包括空回复纠偏和收尾请求。本地取消/超时不保证上游生成与计费已经停止，不把这些限制表述为供应商硬预算。

每题新建临时合成资料和登记表，通过真实 build_session / MainAgent / 生产工具 handler 与权限门。仅暴露与题集有关的个人助理工具，不提供联网、浏览器、命令、真实项目下发或消息发送工具，不启动后台调度器；批准/拒绝由该题的固定策略模拟。原生工具协议和提示协议都可测试，公网数据能力需另测。

报告写入 gitignored 的 evals/reports/assistant/，记录输入、回复、工具轨迹、确认决定、状态断言、耗时、tokens、已知目录价格、源码指纹和题库指纹。未知价格为 null，费用不是供应商账单。助手题集与开发交付基线分开，不允许使用开发基线或矩阵直接比较。

评分同时检查必要工具、回复事实、明确的错误声称与状态变化。提议题必须实际只产生一张待确认任务单；拒绝写入后记忆必须保持不变；暂停/拒绝恢复后配置必须仍停用。超时、异常、没有结果或任一断言不满足都返回非零退出码。文本断言是有限的词组规则，不是完整语义裁判；看报告应同时抽查回复是否有无根据的推断。脚本模型单测只能验证 harness 与合同，不算模型能力成绩。

## 公共题库的适配顺序

| 题库 | 能测什么 | 在此框架中的接法 |
|---|---|---|
| [ToolSandbox](https://github.com/apple-aiml-research/ToolSandbox) | 有状态的工具操作、工具间依赖、多轮对话、中间与最终里程碑 | 将其工具环境对接 MainAgent；模拟联系人/提醒等数据，按最终状态和里程碑判分。不是简单把自然语言题喂进聊天。 |
| [LongMemEval](https://github.com/xiaowu0162/LongMemEval) | 500 道长期记忆问题，覆盖提取、跨会话推理、知识更新、时间推理与不知道时的回答 | 先用 oracle 子集验证回答与评分链路，再用 S/M 历史测试真实写入/检索。不能把整段历史塞进提示后的成绩当成记忆系统成绩。 |
| [GAIA](https://huggingface.co/datasets/gaia-benchmark/GAIA) | 通用助理的检索、文件理解、工具运用及多步推理 | 适合联网/文件能力验收；数据需要接受访问条款，不能公开复制其受限题目和答案。 |

本轮没有下载、复制或运行这些公共题库；本地 14 题不是它们的子集，也不对应其公开榜单成绩。没有 Muse 同条件评测结果，不能用本题集通过率作两者性能比较。

## 后续产品开发

先稳定测到的记忆、工具调用和结果汇报，再增加可审阅的长期事项：目标、约束、下一步、等待谁、下次跟进时间与证据入口。用现有任务/调度/记忆台账承载，行动之前复用确认门；不靠聊天文案推断目标完成，也不默认开放邮件发送、购买或删除权限。
