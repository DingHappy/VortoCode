# 手机客户端边界与仓库决定

日期：2026-10-25。决定：当前保留同仓库，按独立模块、协议和 CI 检查组织；暂不新建远端仓库。

当前产品决定：**同一 VortoCode 账号登录后关联自己的助手**。以下手动核对码链路保留为高级自托管/开发方式，不再是默认入口。同账号 Web 登录和当前运行端归属已接入；Desktop 已有需原生确认的关联设置卡片，云端助手列表尚待实现，实际边界见 [MOBILE_ACCOUNT_ACCESS.md](MOBILE_ACCOUNT_ACCESS.md)。

运行端新进展：本地账号核验、归属登记、短期只读授权及撤销已接到原设备授权存储；接口仅供可信原生/服务端桥使用。手机 Web OAuth 已接入本地源码，云端助手目录未接入，参见 [ACCOUNT_RUNTIME_BRIDGE.md](ACCOUNT_RUNTIME_BRIDGE.md)。

手机和 Desktop 是同一常驻助手的不同入口。任务、目标、会话、验收与调度记录继续由原服务端领域拥有。当前协议还在形成，同仓库可以在一次变更中核对两端，减少客户端与服务端版本不同步的风险。目录分离不表示必须一起打包或一起发布。

| 位置 | 本轮责任 | 边界 |
| --- | --- | --- |
| `src/gateway/mobile_devices.py` | 独立设备授权、到期、撤销及存储摘要 | 不保存会话/任务，不授予管理员权限 |
| `src/gateway/mobile_pairing.py` | 短时窗口、核对码、请求证明、幂等确认与取消 | 与设备授权共用文件及锁，不保存明文凭证 |
| `src/web/routers/mobile.py` | 管理员发放/撤销授权，设备只读 v1 投影 | 不运行模型、发消息、批准、调度或操控电脑 |
| `packages/mobile-client/` | 独立 TypeScript 通信包、协议校验与读取顺序 | 不导入 Desktop/Tauri/React，不自己持久化令牌 |
| `prototypes/mobile-assistant/` | 已确认的交互/视觉演示 | 保持模拟数据，不改成真实服务的管理员控制台 |
| `desktop/` | 现有桌面工作台 | 本轮不修改安装包或发布版本 |
| `mobile/` | 浏览器账号登录、配对、电脑管理与只读界面 | 独立 Vite 构建；不承担原生签名或通知 |
| `mobile/ios/` | SwiftUI 原生连接首页、设置及系统浏览入口 | 第一版复用 Web 登录与读取；没有原生聊天、审批、通知或 Android 工程 |

后续达到下列条件时再考虑独立仓库：手机有独立维护者和发布节奏；v1 合同、兼容性及端到端检查稳定；共享协议与通信包有清楚的版本发布方式；双方不再需要频繁同步修改领域规则。拆分时迁移客户端与相应检查，保留同一 Gateway 服务端，不复制任务库或核心执行实现。

## 本轮完成的授权基础

管理员接口沿用整站管理员鉴权，但必须明确配置 `VORTOCODE_API_TOKEN`；本机无令牌的兼容模式不能发放手机授权。手机设备接口只接收自己的 Bearer 凭证，不回退到管理员令牌、Cookie、query 参数或 X-API-Token。管理员的浏览器请求需要同源；设备接口需要 HTTPS，本机回环 HTTP 仅用于开发验收。

| 方法与路径 | 身份与效果 |
| --- | --- |
| `POST /api/mobile/devices` | 管理员提供 `name` 与可选 `ttl_days`（1–90，默认 30），返回实例 ID、设备记录与一次性可见的凭证 |
| `GET /api/mobile/devices` | 管理员读取设备元数据；不返回凭证或摘要 |
| `DELETE /api/mobile/devices/{id}` | 管理员撤销原设备；重复撤销保持原回执时间 |
| `GET /api/mobile/v1/bootstrap` | 设备核对版本、实例、设备身份与能力；写能力为空 |
| `GET /api/mobile/v1/snapshot` | 设备读取助手名称、主会话标识、个人目标摘要；不读取对话正文 |

授权记录放在原实例状态目录的 `.vortocode/mobile-devices/grants.json`，没有额外数据库或后台进程。令牌只保存 SHA-256 摘要；目录/文件在 POSIX 下分别为 0700/0600。发放与撤销使用跨进程锁和原子替换，损坏记录拒绝读取/覆盖，不自动重建。读取不写存储；每次请求重新核对撤销与有效期，无授权缓存。已进入处理的请求可以完成，撤销保证下一次请求被拒绝。

`instance_id` 是该授权存储的持久身份，不是硬件指纹。备份/克隆授权目录会保留它；设备迁移、丢失或数据恢复后的授权处理需要管理员明确撤销。当前最多保留 256 条授权记录（包含已撤销），达到上限拒绝新发放，不静默清理审计记录。

管理员预置授权仍可用。现已增加**两端核对码配对**与浏览器设备管理；二维码、原生 Keychain 存储和 Desktop 内嵌的管理卡片尚未实现。当前只在临时实例发放过测试设备授权，未给真实手机连接日常助手。

## 两端确认与手机只读页面

电脑访问 `/mobile/manage`，通过原管理员登录后开放 5 分钟窗口。手机访问同源 `/mobile`，使用 Web Crypto 生成自己的 256 位凭证和稳定请求 ID；服务只保存摘要。页面展示随机核对码，电脑输入相同码并确认只读范围后，才在原设备授权文件内原子保存一条授权。手机再次确认两端码一致，然后执行 bootstrap 和 snapshot。

| 方法与路径 | 身份与效果 |
| --- | --- |
| `POST /api/mobile/pairing-window` | 管理员开启/关闭短时窗口；重新开启会使原待确认请求失效 |
| `GET /api/mobile/pairings` | 管理员读取当前请求与公开核对码，不返回凭证摘要 |
| `POST /api/mobile/pairings/{id}/decision` | 管理员明确核对码、批准/拒绝与有效期；相同决定重试返回原授权，不延长有效期 |
| `POST /api/mobile/pairing/start` | 手机提交请求 ID、名称和自身凭证；必须有已开放窗口，每窗口最多 8 个新请求 |
| `POST /api/mobile/pairing/status` | 手机用同一请求 ID 和凭证证明读取状态，不借 Cookie 或管理员身份 |
| `POST /api/mobile/pairing/cancel` | 仅持有本请求证明的手机可取消；批准响应丢失时也会撤销同一设备，不影响其它设备 |

配对记录最多 64 条，旧记录过期后在后续窗口/发起操作中清理；已批准的设备授权按原 256 条上限保留。配对窗口、核对码和授权记录共用原跨进程锁与原子文件，不引入第二套授权数据库。配对记录到期不等于设备授权到期；已经连接的设备继续按其独立有效期核对。

浏览器手机凭证仅在闭包中，刷新/离开后清除，不进入 URL、localStorage、sessionStorage 或 Cookie。电脑管理沿用原 httpOnly 管理员会话。手机读取明确 omit cookies，不能借浏览器里恰好存在的管理员会话扩大权限。原生安全存储留待正式客户端适配。

构建入口与部署前提见 [mobile/README.md](../mobile/README.md)。本阶段界面覆盖账号登录、高级配对与读取，已确认的聊天/动态/目标/成果整体方案仍在独立原型中；没有给未接通的聊天或审批显示可执行按钮。

## 只读 v1 合同

两条设备 GET 返回 `schema_version: 1` 和 `instance_id`。bootstrap 同时返回设备记录、`scopes: ["assistant:read"]` 和 `capabilities: {reads: ["profile", "main_chat", "goals"], writes: []}`。

snapshot 的 `sources` 分别报告来源：

- `profile`：复用原助理资料的名称与默认名称规则，仅输出 `{name}`，不输出 SOUL、persona 或记忆。
- `main_chat`：复用原主会话登记，仅输出 `{sid}`；没有登记是 `sid: null`，损坏的已有登记是 unavailable。
- `goals`：复用 PersonalGoals，只输出 id、objective、status、next_action、blocker、revision，最多 100 条并提供 truncated 标识。不计算新的达成状态，不修改证据或验收。

成功来源的形状为 `{status: "current", checked_at: <带时区 ISO 时间>, data: ...}`；失败来源为 `{status: "unavailable", checked_at: null, data: null}`。一处失败不取消其余来源，也不变成成功空列表。不向客户端泄漏底层异常、文件路径或凭据。缓存历史由客户端管理并明确标旧，不由服务端伪造新的核对时间。

这些是各来源分别读取的观察结果，不是跨存储原子快照，也不是一个可用于批准的 revision。主会话不存在时不自动创建。手机的“助手服务可读”不代表画面连接或接管权限。

## 验证与下一步

本地检查包括设备过期/撤销、重启后授权、并发发放、损坏和符号链接拒绝、管理员/设备隔离、General 作用域、来源失效，以及读取前后文件不变。TypeScript 检查覆盖严格版本/实例、固定只读路径、禁止凭证进入 URL、取消/超时、迟到结果和历史状态。

`python scripts/check-mobile-contract.py` 在临时目录里用真实 Gateway 中间件和路由启动回环 HTTP 服务，关闭 lifespan，通过实际 TypeScript 客户端读取三种来源，再撤销授权并确认拒绝；同时验证两端配对确认、只读连接和撤销。测试凭证只经内存与私有 stdin 传递；验收后服务退出、临时目录销毁。

通信包新增独立 CI job；Python 领域和授权测试进入现有单测。CI 配置尚未推送运行，本机检查也不代表真实手机或远端部署已验收。

本轮本机结果：Python 相关回归 109 项、TypeScript 客户端 13 项通过；手机页面构建、类型检查、Ruff 和真实回环 HTTP 配对/读取/撤销链路通过。浏览器中的批准、读取、撤销、断网历史和恢复也已点验；截图通道超时，视觉截图验收未完成。详见 [验收记录](../mobile/ACCEPTANCE.md)。执行环境为 Python 3.14 / Node 25.2；CI 声明的 Python 3.10/3.12 和 Node 22 尚待 CI 运行验证。

后续顺序：原生安全存储与真实手机只读接入 → 聊天受理及事件回放 → 原对象绑定的回答/批准与跨端回执。生产接入前仍需真实 HTTPS/代理、真实手机、长期失联和服务升级兼容验收。本轮没有开放公网、部署、提交/push 或升级 Desktop。
