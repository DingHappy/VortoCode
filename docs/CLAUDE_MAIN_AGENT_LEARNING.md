# 从 Claude Code 学习主 Agent 提示与编排

2026-11-03。对照 VortoCode `dd4b8d9e` 的 MainAgent 与 ADR-014 任务小组。
研究对象是本机 Claude Code 2.1.317 的已发布制品；没有启动目标、模型、hooks 或读取私人会话。
本文归纳机制并给出原创实现选择，不复制厂商提示词。

## 学到的机制

| 机制 | Claude Code 的静态证据 | VortoCode 的取舍 |
| --- | --- | --- |
| 根据场景和工具组装提示 | 主块 `pI → Qdn → Ipr / Lpr`，段落有 id、scope、text；工具规则由当前集合生成 | 固定个人助手职责、入口身份、角色资料与实际工具指引分开。规则随工具增删更新，纳入恢复指纹 |
| 分清普通助手和协调器 | `_gr` 仅在 `Va()` 等条件下取 W7i；后者是可选协调器，不能当成所有 CLI 的默认策略 | 小事由主助理直接处理；大任务按 ADR-014 提议小组，在已有独立上下文协调 |
| 独立工作并行，依赖工作串行 | 普通工具段 `mpr` 明确区分无依赖与依赖；`nri` 的委派规则又按模型、套餐和可用能力选择 | 复用已有并发池和 `parallel` 限制；提示先查已有任务，独立工作可并派，上游核对后再派依赖工作 |
| 子任务有明确上下文合同 | Agent 的 fork 分支传父消息、父系统提示与精确工具面；fresh 分支使用独立上下文，但可转发筛选过且带来源的用户意图 | 当前成员保持每轮新上下文，只传原任务、交付标准和本轮合法返工要求。私人资料与工具权限不随文本扩散 |
| 启动、执行与交付分别回收 | `Agent.call → runEngine(wr) → Go` 判定前后台；启动回执不等于完成报告，`yse` 从执行记录生成状态与通知 | 原任务服务负责状态与额度；协调人读取真实结果、对照标准后接受或定向返工，最后交主人验收 |
| 恢复与取消有专门路径 | `SendMessage → z$r → on → Vr` 区分 live 入队与恢复；恢复读取旧 transcript，并核对重复恢复和用户停止 | 沿用任务状态、轮次和原恢复入口；历史请求、通知、摘要和批准文本不能恢复当前授权或重启已取消工作 |

这些机制共同决定编排。提示负责选择下一步，运行层负责实际的上下文、任务、工具、额度、权限和结果。
不能从存在一段提示词推断相应运行能力已经开放，也不能把可选多代理分支推广到所有账号。

## 本轮实际改善

### 主对话的当前目标与行动

主提示按「辨认本次结果与约束 → 简短计划 → 行动 → 读结果 → 下一步 → 汇报」组织。
小事直接处理；已授权且能继续时推进；需要主人决定时说明依据。
在办工作与小组工具的规则只随实际装配出现。General 的主动性说明不再承诺尚未登记的后台执行。

原有裁剪会把首条请求重新放回 user 消息。现在保留原文，同时标注为早期历史背景；
纪要说明可能已有修订，既有计划也须核对本次请求。最近用户消息仍保持原文，系统前缀保持稳定。
这改善输入合同，不声称模型已经在所有情形下理解了取消与纠正。

### 返工要求真正进入成员的新回合

发现并修复一条实际断链：`TeamService.review(rework)` 将 note 写入原协作记录的 followup 消息，
但成员每轮重新创建 Agent，旧 `member_prompt` 只取原任务和交付标准，未读取这条消息。

现在从原记录选最后一条当前整数轮次、kind=followup、sender 匹配原 owner 的要求，限长并复核脱敏，
标明它来自协调人且不构成主人新授权。旧轮次、错误来源、其他消息类型和非文本不进入请求。
不拼全部历史或上一轮交付。已有输入污点通过 MainAgent 的入口声明传递，避免被回合起点重置洗掉。

### 协调人核对和定向返工

原有事件唤醒、并发池、额度、轮次、互审、主人提问与最终验收继续负责执行。
提示补充派活的必要背景、范围、约束、交付依据和未知项；接受前读取实际结果，缺哪项就返工哪项。
成员 done 仍只表示交回；主人纠正优先处理，通知不代表授权；没有新信息时不重复同一失败做法。
不强制固定研究、审查顺序，不新增任务库、调度器或 DAG。

### 授权结果不冒充用户决定

统一模式升级结果：已授权、未获授权、没有通道、等待超时和通道异常。
原 bool 回调无法证明拒绝来源时，仅报告未获授权；异常不再说成用户拒绝。
本回合共用一次模式决定，包含并发请求；失败不执行，下一次真实用户回合才可重新请求。
模式重置会使旧决定失效，回合代次变化后到达的确认不能给新回合授权。
取消继续向上抛出，预算收尾也保留失败原因。工具回执和审计携带相应原因码。
确认门、能力与污点规则继续由原内核判定。

### 工具指引与调用合同继续对齐

后续从 VortoCode 源码确认两个输入缺口：旧式 `argument_schema` 的类型没有进入提示式目录；
恢复指纹也没有覆盖这部分合同和实际编排指引。现在两种协议使用同一导出合同，补齐常用
工具的布尔、数字、数组及必填参数。原生请求已经附带 schema，系统目录不重复整份 JSON。

检索、技能、记忆、委派与开发指引随实际工具集合出现；普通计划不再被一律写成开发任务。
只读与可并行分开，授权受阻不换工具绕过，结果未知的副作用先核对。两档模式的静态规则
都进入恢复身份，最后渲染过哪一档不再制造能力变更。具体范围见 [工具提示合同](AGENT_TOOL_PROMPTING.md)。

本次是基于已有静态研究机制的原创工程实现，没有新增对 Claude Code 制品的分析结论。
