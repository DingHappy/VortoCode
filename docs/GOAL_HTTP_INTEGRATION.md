## 后续检查：新建表单恢复（2026-10-24）

在同样的隔离真实 HTTP 环境补查新建表单，复现了此前未覆盖的问题：POST 已落盘、回读失败后，手动刷新能看到目标，但原输入仍留在新建表单。未编辑时重试沿用相同请求 ID，后端会幂等返回原目标；遗留表单仍容易让用户误以为没有保存，并在修改后另建一条目标。

现将请求 ID 绑定草稿状态。只在当前来源的有效列表包含本次已提交的 `personal-<request_id>` 时清空对应草稿，提示「已在列表找到这次新建的目标，原输入已清空」。失败或尚未找到记录时保留输入；后续编辑、切换客户端使旧提交关联失效，旧读取不能清空新输入。该行为不重试写入，也不把找到记录当作原请求取得成功回执或目标已达成。

## 复现

```sh
cd desktop
npx vite build --config qa/vite.config.ts
cd ..
python desktop/qa/goal-integration-server.py --assets desktop/qa/dist
```

终端输出专用临时 `root`、回环 `port`、PID 和后端源码哈希。打开 `http://127.0.0.1:<port>/qa/goal-integration.html`，从「全部目标」中新建测试目标；不要连接正在使用的真实服务。页面中的两个故障按钮只控制 QA 宿主，真实目标读写仍走生产接口。

停止宿主后，可复用同一目录与端口验证恢复：

```sh
python desktop/qa/goal-integration-server.py --assets desktop/qa/dist --root <上次输出的root> --port <上次端口>
```

`--root` 仅接受 `/tmp` 下的专用 `vorto-goal-integration-*` 目录，复用其中的源码快照和数据，不迁移或覆盖用户运行目录。固定令牌 `goal-integration-only` 只用于这个空白、回环、受限的测试实例，不是用户凭据，不得用于部署。
