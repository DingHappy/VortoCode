# Mac 本机常驻助手

2026-11-13：主人确认把 Mac 本机常驻服务纳入个人模式，并授权按源码学习结论落地。
模型配置采用独立快照：安装时明确确认复制，之后独立管理；退出 Desktop 的模型账号不会撤销该快照。

这不是所有用户级配置的隔离：现有全局指令仍读取用户目录的 `.vortoone/AGENTS.md`。
使用同一用户目录的临时引擎与本机常驻助手会在新会话/任务中读取同一文件，远端不自动同步。
P4 只在设置中标清这一范围，不修改 HOME 或迁移文件；模型快照仍保持独立。

本功能复用原服务器、Runtime、工作区租约、任务台账、专员和例行工作，不引入第二套执行或调度系统。
设置中的「电脑与连接」提供本机与另一台电脑两个入口。

## 三种运行方式

| 方式 | 生命周期与资料 |
| --- | --- |
| Desktop 本机引擎 | 保持原行为，随 Desktop 退出；不启动 IM、cron 或 heartbeat。用于原 General / Scratch / Project 工作区。 |
| 这台 Mac 的常驻助手 | 主人明确安装并启动，用户级 LaunchAgent 在登录后运行；Desktop 只连接，不拥有该服务进程。资料在独立 General 工作区。 |
| 另一台电脑的常驻助手 | 保持原登记与连接流程。Desktop 断开或退出不停止对方服务。 |

安装本机常驻不切换当前对话、不登记成默认助理、不移动旧资料。只有主人明确点击「连接」才进入原宿主选择流程。
原生准备的登记带待选标记；真实连接成功后才持久选中。即使原来没有别的常驻助手，失败的连接也不能成为下次自动选择。
本机与远端都持久保存明确选择；连接、保存选择和激活保持在同一次切换中，不能由迟到回调覆盖后续选择或重复打开其他宿主的会话。
若已连接但默认选择保存失败，在同一切换内断开仅属于这次选择的新连接并清空会话视图；保留原默认登记，提示重新选择，不自动连接其他宿主。若连接已经被更新的连接取代，不清理新连接。
连接失败不能把错误文字当成成功，也不能打开另一份主要聊天。
本机与远端各保留自己的聊天和配置，不自动同步或合并；远端断线继续重连原实例，不自动改派本机。

## 安装、启动与停止

- 安装前必须明确同意复制当前可用模型配置；原生确认说明常驻与 Desktop 账号退出之间的区别。
- 安装只准备程序与配置。启动才启用登录后运行；不承诺未登录、注销后或休眠期间执行。
- 定时任务由安装界面单独选择，默认关闭。IM、heartbeat、宿主命令、桌面及浏览器操作不继承或开启。
  General 可以按原规则运行显式启用的 cron；heartbeat 仍只属于 Project。
- 停止、更新程序或应用新模型前，核对当前配置代次、运行实例和七项活动计数：回合、排队输入、
  确认、后台任务、命令、终端、写请求。原生主人确认之后再次核对；活动未清零、身份变化或无法核对时保留服务。
- 停止是显式停用，不因再次打开 Desktop 自动启动。程序和资料保留，主人可以再次启动。
- 若进程已停止但登录项删除失败，显示“登录项待清理”并提供重试；只有核实未加载且登录项属于本实例时才移除，不把残留自动启动项描述为已完成停用。
- 关闭窗口、退出 Desktop 和停止常驻服务是不同动作。原 Desktop 子进程的监护机制不变；常驻服务不进入该进程清理列表。

活动读取是新鲜观察，不是跨客户端的原子静默租约；核对后到系统停止前仍有短暂竞态。
不能把此预检表述为“任何并发下都绝不会中断活动”。原任务的中断、重启核对及批准失效规则继续生效。

## 稳定程序与独立配置

程序复制整个内置 onedir runtime（包括内部库与资源），发布到受管的版本目录，不依赖 App 内会被替换的资源路径。
复制拒绝越出源树的链接，配置代次切换采用原子指针。更新程序保留同一资料目录和原模型快照；
「应用当前模型配置」是另外一次明确操作，不能伪装成实时同步。
新版本启动发生异常或超时时，只有明确未加载且对应登录项已清理，才回退旧指针；结果不明或清理失败时保留新指针与匹配的登录项，等主人核对。

受管目录包含以下内容：

```text
local-resident/
  service.json
  releases/<runtime-tree-id>/...
  generations/<configuration-revision>/service-config.json
  assistant/.vortoone/...
  logs/...
```

运行文件、配置路径、服务 label、监听范围与资料目录由原生端生成；网页层不能指定命令或任意环境变量。
启动程序先验证支持本机常驻协议，避免把旧构建误装成可用版本。

配置文件只允许当前用户读取（0600），配置目录为 0700，拒绝链接或不受支持的 schema/字段。
原生生成主人访问令牌，保存在私有配置并供原 Keychain 连接流程使用；不进入 LaunchAgent 参数、界面或项目登记表。
运行前仅加载允许的模型环境快照，清除继承的旧开关，阻止 dotenv 重新装入权限。
每次进程启动生成新的运行代次；固定为 General，不设置 Desktop sidecar 身份。
本机服务只监听私有 Unix socket，不监听网络端口。连接文件位于系统临时目录下按用户和资料实例派生的短目录，避免长用户目录超过系统 socket 路径限制；资料目录不迁移，重启后由服务独立重建连接目录。目录为 0700、socket 为 0600；
管理检查、HTTP、WebSocket、账号关联和 Codex 观察员都使用同一私有通道，连接失败不回退到 TCP。
只有此受管 UDS 监听器装配的应用带有进程内可信传输标记；无客户端 IP、普通 HTTP、请求标头或参数不能提供该标记。账号管理继续要求原主人令牌与同源核对。

服务登记沿用 `kind=remote` 与 `repoRoot=@assistant`，通过原 HTTP / WebSocket 原生代理注入主人令牌。
登记中的虚拟 origin 仅用于兼容原身份索引，不是可访问的服务地址；不能据此派生其他端口的项目连接或 SSH 取分支。
专员批准仍走原 owner 写入路由及 digest、nonce、轮次、实例、TTL 和审计合同。
本机连接不等于获得批准权限；新增入口不修改确认门、污点规则或无人值守默认拒绝。

## 验证分层

离线测试覆盖配置隐私与允许字段、实例更新、活动和身份核对、完整程序复制、链接边界、操作并发与迟到响应、
连接失败不切会话，以及界面的真实状态和可用动作。

这些测试不能代替签名版 App 上的安装、登录启动、Desktop 正常/异常退出、系统睡眠与唤醒、
服务崩溃重启、程序升级失败回退、Keychain 连接和真实模型验收。真实验收须使用独立测试资料并获得对应操作授权；
本 PR 不安装常驻服务、不更改电源设置、不发版或部署。
