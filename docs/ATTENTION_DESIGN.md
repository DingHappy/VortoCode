# 注意力优先的信息呈现

2026-11-01。用户确认的产品方向：助手先整理、核验和判断，用户主要接收结论、建议和必要决定。本文约束整个 Desktop 的默认呈现，不限定某个网站或业务流程。

## 设计原则

1. 主界面先呈现处理后的信息。默认回答发生了什么、影响是什么、下一步建议是什么。普通问答仍直接回答，不把每句话转换成任务单。
2. 正常过程安静推进。工具调用、普通回执、重复进度和历史对话按需查看；不因新记录到来自动打开面板、切页或抢走阅读位置。
3. 必要决定带着上下文。提出建议前先调查和比较；需要用户确认时说明对象、范围、后果、推荐理由和其他选项。已有确认门不放宽，展示层不生成批准。
4. 影响决定的不确定性必须保留。来源失联、结果不明、未验收和未部署不能被摘要抹平。没有读到不等于没有事项。
5. 依据随时可追溯。摘要、通知、对话与列表引用原有对象和记录；展开即可查看原文、步骤、时间及来源，不建立第二套业务台账。
6. 多执行者先向总助手汇总。总助手核对冲突、去除重复并形成可行动的结论；不把多个 Bot 的长篇汇报简单拼接给用户。

## 呈现层级

| 层级 | 默认内容 | 进入方式 |
| --- | --- | --- |
| 主交流空间 | 结论、影响、建议、必要决定；清楚标注尚未完成的边界 | 默认进入 |
| 工作摘要 | 待处理、异常和最近结果；进行中仅给简短提示 | 用户主动打开，存在待处理/异常时入口提示 |
| 依据与记录 | 原始回执、对话、工具步骤、结果、来源覆盖和核对时间 | 从摘要展开 |
| 管理与诊断 | 项目、执行电脑、模型、连接、配置、权限和完整日志 | 固定可达的管理入口 |

页面职责与导航仍需统一，但不以增加常驻看板或更多一级入口实现本方向。所有日常页面遵循同一呈现规则；管理页面为主动检查保留完整内容。

## 打扰规则

| 情况 | 目标行为 |
| --- | --- |
| 正常执行、普通成功回执、重复进度 | 后台保留记录；不抢焦点、不反复提醒 |
| 已形成可用交付、重要变化 | 整理为一次有依据的结果，保留未验收/未部署等限制 |
| 需要授权、关键取舍或人工补充 | 汇总后提出明确决定；绑定原对象，不代替用户批准 |
| 失败、中断、来源失联、提交结果不明 | 明确提示需要核对；不得因旧状态显示已结束而隐藏 |
| 用户正在阅读细节或处理决定 | 保持当前视图、输入与焦点；新信息不替用户切换页面 |

去重只使用可靠的对象、轮次、版本与来源身份。不得通过相似标题或文本猜测合并两次独立授权。展示是否需要注意、执行是否完成、用户是否已读和业务是否验收是不同事实。

## 当前实现：第一批呈现改造

- 主人待办使用当前连接与工作区中明确的小组成员关系区分决策人：成员结果、内部失败与内部验收收在小组和完整历史中，整组交付仍交主人验收。成员明确向主人提问时保留主待办；归属未读到或有冲突时保留原入口，不按标题猜测或自动处理记录。
- 从「需核对」进入会展开重点摘要、定位异常区并移动键盘焦点；普通后台更新不会触发这次导航。重点摘要放在例行时间线之前。
- 后台任务首屏先显示简短标题、当前状态与动作，完整原要求折叠。小组待验收/已验收时默认打开「交付与原文」，按任务与轮次查阅服务端已保存的结果；总结、证据与成员原文分开，不自动认定哪个历史结果是最终稿。阅读、复制均不验收或执行其中指令。

- 助理模式启动/切回后不再默认打开侧面板；用户从原任务入口打开工作摘要。常规后台工作不在顶栏展示进行中数量或状态点；待处理、异常和来源未知保留入口提示。
- 待处理在主要聊天顶部唯一汇总，默认收起。动态面板提供返回该汇总的链接、所有已读取的异常及最近三条结果，完整记录由用户主动打开。后台任务、派活结果、简报、定时执行结果和恢复通知保留原状态文案，不改称已验收完成。
- 普通聊天回复、Codex 受理回执、过时动作和日常运维消息放在全部记录中。失败和等待确认优先于这类显示分类；来源失联即使保留 running/done，也进入需要核对。
- 助理头像和身份改为紧凑行；模型与电脑入口收在可展开的运行信息中。连接失败说明与恢复按钮保持可见。
- 连接资源默认是一行入口；尚未读取不直接渲染为告警，实际人工接管、动作待核对、清理待核对或读取失败仍显式提示。展开后保留执行位置、账号标签、授权限制和读取时间。

以上是既有记录的确定性展示投影，不增加模型推理、后台轮询、业务数据库或通知发送。最近结果的三条限制不作用于待处理与异常。完整记录不自动切回摘要；切换助理数据来源后重置到摘要。旧记录仍存在，界面不推断哪些旧异常已被用户解决。

## 后续范围

本批没有新增多 Bot 结果合成、语义冲突核验、推荐方案生成、跨来源实体去重、已读/已解决标记、通知合并或推送节流。这些需要分别设计来源证据、时效、预算和送达语义；不能把少显示几行当作信息已完成核验，也不能为了简短吞掉未解决问题。

## 验收

- 无待处理且来源完整时，普通进度不占据默认主区；来源不完整不声称没有工作。
- 所有已读的待处理、失败、中断及失联记录可见，不受最近结果数量限制影响。
- 用户可主动查看完整记录与原始依据，仍通过原确认卡处理动作；查看、展开与筛选不增加批准次数。
- 后台新记录不抢走当前详情、备注输入、焦点或完整记录视图。
- 深浅主题、窄窗口和键盘操作可用；离线保留读取时间与上次记录提示。
- 以非必要打断次数、用户追问次数、为理解结论需要打开的详情数量和遗漏待决事项为后续观察指标，暂不声明已取得改进数据。
