# VortoCode 任务协作与架构收敛 PRD

版本：0.1 · 日期：2026-10-03 · 状态：规划基线，尚未整体交付

本文规划任务机制、Agent 之间的交互和相关架构重构。实现事实以当前源码与测试为准；
“已实现”仅表示本地代码已有该机制，不表示已安装发布或通过真实模型、原生界面验收。
产品入口沿用 [Desktop 产品规格](./DESKTOP_PRODUCT_SPEC.md)，机制现状见
[Agent 与任务协作机制](./AGENTS.md)。

## 1. 要解决的问题

用户希望交给 Agent 的工作可以持续推进：任务有归属、结果有证据、完成后有人检查，
遇到问题能交还给原执行者。当前已有委派、后台执行、验收和持久交接，但这些路径尚未统一：

- 同回合委派会回到主 Agent；独立后台任务结束后，仍需下一次用户对话启动处理。
- 服务研究已能结构化提问并由任务卡/API 回答；模型回合内委派与主 Agent 直接回答尚未接入。
- 后台 `done`、委派 `accepted`、交接 `handled` 与 Goal `achieved` 容易在界面上混淆。
- 输入队列、唯一回合及事件流已提取；会话生命周期与连接适配仍集中在 realtime 路由；
  Desktop 任务数据、操作与面板已独立，握手适配已提取；跨域刷新、会话和项目切换编排仍部分集中在 App.tsx。

本项目的目标是让任务从提交到交付形成可恢复、可解释的闭环，并让新增协作能力有明确归属。

## 2. 用户与成功体验

主要用户：使用 Desktop 在本地项目中持续开发、研究和审查的个人开发者。
CLI/TUI 继续共享运行机制；Web 沿用同一 Gateway，不为本阶段另建运行内核。

典型场景：

1. 用户提交“分析认证模块并给出修复建议”。主 Agent 创建研究任务，记录目标与验收要求。
2. 子 Agent 提交结果；主 Agent 检查证据，接受或说明缺项并返工。
3. 用户提交耗时开发任务后切到其他项目。原项目继续运行，结果归入原会话。
4. 若用户选择“完成后检查并汇报”，原会话空闲时执行一次有预算的检查；
   未选择时结果保持待处理，下一次用户对话提示读取交接。
5. 子 Agent 遇到无法确认的需求时，明确提出问题，等待有权限的人回答，随后恢复原任务。
6. 用户可以停止、切换项目和重启；重新打开后能看清任务停在哪里、下一步需要谁处理。

## 3. 目标与范围

| 优先级 | 目标 | 用户可观察的结果 |
| --- | --- | --- |
| P0 | 收敛架构与状态语义 | 同一任务在任务卡、会话、收件箱中的归属和状态一致 |
| P0 | 可靠完成交接 | 结果重启后可找回；旧确认不会吞掉新结果 |
| P1 | 显式授权的自动检查 | 后台完成后可自动核对并汇报一次，不抢占用户回合 |
| P1 | 执行中提问与回答 | 问题有 ID、轮次和答复记录，回答后恢复原任务 |
| P2 | 有依赖的异步协作 | 前置结果验收后才推进依赖任务，并发与费用有界 |

本阶段不引入固定角色组织、任意 Agent 互聊、多租户协作、第二套任务数据库或通用工作流 DSL。
PR、推送、合并和外部发送继续遵守已有权限与确认门。

## 5. 状态与领域合同

任务复用 `.vortocode/tasks/<id>.json`。已有字段保持兼容，新增字段必须有默认值。
身份由 runtime 和会话提供，模型输出不能指定新的任务所有者。

| 状态维度 | 当前状态 / 计划状态 | 语义 |
| --- | --- | --- |
| 执行 | queued / running / done / failed / cancelled / paused / interrupted | 执行是否结束；done 不保证交付质量 |
| 委派审查 | not_submitted / pending / accepted / rework_requested | 主 Agent 的审查结论，不替代可验证证据 |
| 完成交接 | 无当前版本回执 / 有当前版本回执 | 是否已处理该结果，不修改执行与验收状态 |
| Goal | 沿用现有 Goal 状态与完成闸门 | 是否满足目标验收要求 |
| 服务研究问答 | open / answered / cancelled / expired | 问题独立状态；执行增加 blocked，不能冒充 completed |
| 自动接续（计划） | pending / claimed / completed / blocked / cancelled | 一次授权接续的生命周期，不覆盖原任务状态 |

每个修改请求携带任务 ID 和精确轮次或结果版本。版本不匹配、身份不匹配、非法状态必须拒绝，
返回可操作的重读提示。相同确认重复请求不新增消息或触发模型执行。

## 6. 功能要求与验收

### F1. 任务创建与结果提交（P0）

- 合同包含原始目标、执行角色、验收要求、所属会话、轮次和资源限制。
- 存储成功后才能开始执行；结果持久化后再向客户端发布通知。
- 模型失败、空结果、取消或中断保持各自状态，不用普通文本伪装成功。
- 返回结果包括产物定位、已验证证据、未验证内容与阻塞；证据缺失明确保留。

验收：写盘失败不执行；重复启动不创建第二执行者；迟到的旧轮次结果不得覆盖新轮次。

### F2. 审查、返工与交接（P0）

- 委派结果接受或返工时必须记录理由；返工回到原角色并保留原合同。
- 已验收的任务不追加范围，新增工作另建任务。
- 后台终态结果进入所属会话未处理收件箱，处理回执携带精确结果版本。
- 失败与中断也需要交接，不能因为没有成功产物而消失。
- 处理回执只表示主 Agent 记录了处理结论，不宣称用户已看到或认可。

验收：重启保留未读与回执；结果更新后重新未读；跨会话拒绝读取与确认；
确认失败写盘保持未处理；重复确认不改写首次处理记录。

### F3. 后台完成后的自动检查（P1）

提交后台任务时提供两个选项，默认第一项：

- “完成后通知我”：保留目前行为。
- “完成后自动检查并汇报一次”：显示执行范围、预算上限，用户明确选择才写入授权。

首版自动检查只使用只读、plan 能力；禁止派生子 Agent、修改代码和执行有副作用的命令。
需要继续开发时形成建议与阻塞原因，等待新的用户要求或已有有效确认，不自行扩大授权。

调度要求：

1. 前台输入优先；当前回合、人工确认或用户停止期间不得插队。
2. 合并同会话待处理结果，一次接续不为每条完成事件分别创建模型回合。
3. 接续认领先持久化，再调用模型；同一结果版本最多启动一次自动尝试。
4. 首版不在进程重启后自动重试已认领但未完成的回合，标记 interrupted/blocked 并展示给用户。
   不承诺跨崩溃的 exactly-once 模型调用。
5. 自动检查失败或取消不写处理回执，原交接仍可由用户回合处理。
6. 用户撤销或点击停止后保留结果；恢复自动处理需要明确操作，重连不视为授权。

拟定首版硬限制：每个授权最多一次接续、最多 6 个工具调度步骤、0 个子 Agent、
120 秒活动时长、最多 8000 个请求输入与输出 token 的累计预算。实现前须对齐现有
step 与 usage 的计量方式，并对上下文和输出 token 做请求前检查/上限控制。
若 provider 无法支持所需计量或限制，自动接续保持关闭并说明原因。
人民币/美元金额只在有可信价格与用量时展示；未知价格不得显示为零费用。

验收：重复事件、两窗口、重连和服务重启均不导致重复自动尝试；
预算耗尽、超时、撤销和 provider 失败都有可解释状态；原任务的执行结果不被覆盖。

### F4. Agent 执行中问答（P1）

- 子 Agent 可创建结构化问题：question_id、task_id、round、问题、建议选项、所需回答者与期限。
- 主 Agent 有足够信息且在授权范围内时回答；否则转交用户，显示在已有决策/任务界面。
- 问题以持久消息记录；回答不通过 UI 文案推断，必须带精确问题 ID 与轮次。
- 等待回答时任务进入 blocked，不持续调用模型轮询，不占执行并发槽。
- 重启后从合同、问题和答复重建上下文；旧问题答复不得恢复新轮次。
- 回答提供信息，不授予文件、Shell、网络或对外发送权限。

验收：同一问题只能有效回答一次；重复同一回答幂等，冲突答复被拒绝；
过期、取消、跨会话、旧轮次和写盘失败不启动恢复执行。

当前首版限定 HTTP 只读服务研究，由所属会话的用户/受信业务入口回答。主 Agent 可读取问题，
直接回答工具仍待接入。每次回答使用下一轮原有执行预算，总计最多三轮，最多两次提问；
第三轮不再装配提问工具。采用 24 小时问题期限，未新增自动执行授权或独立问答预算。

### F5. Desktop 呈现（P0 → P1）

复用任务卡、原会话、决策中心与全局 Inbox，不新增独立“Agent 社交”页面。

- 卡片显示目标、执行者、轮次、执行状态、待验收/已验收、结果和待处理问题。
- 有回执时显示“交接已处理”及处理说明，与“已验收”分开。
- 自动接续显示是否授权、是否正在检查、已用预算与停止入口。
- 行动始终回到任务所属项目/runtime/会话；项目切换期间的旧响应不能覆盖新项目状态。
- 执行按钮需由服务端可操作性字段驱动；前端不自行从文案推导可恢复、可验收或权限。

验收：窗口刷新、多 runtime 切换、连接失效和未保存输入时，结果不串项目、草稿不被覆盖。

## 7. 架构约束与重构顺序

沿用 [Desktop 拆分方案](./DESKTOP_APP_ARCHITECTURE.md) 的 Context、域 hook 和 reducer 方向，
不引入新状态库。纯搬迁与行为改动分批验证，避免一次重写全部运行路径。

| 边界 | 负责 | 禁止依赖 |
| --- | --- | --- |
| Agent 回合 | 模型、上下文、工具与权限 | Desktop、WebSocket、页面导航 |
| 工具装配 | 将领域能力绑定到当前 Agent 身份 | 客户端生命周期 |
| 协作服务 | 委派合同、消息、轮次与审查 | LLM 与实时路由 |
| 完成收件箱 | 读取原台账、计算结果版本、持久处理回执 | 委派服务的私有实现、模型调度 |
| 会话 actor（已提取） | 唯一回合、FIFO/优先项、停止与恢复 | 具体 WebSocket 实例作为任务身份 |
| 会话事件层（已提取） | seq、持久 journal、补收与订阅者 | 模型实例与任务执行策略 |
| 自动接续调度（待实现） | 授权、认领、预算、恢复对账 | 绕过会话 actor 独立启动前台回合 |
| Desktop 任务域（数据与面板已提取） | 请求、订阅、快照、选中项与任务动作 | 推导服务端业务状态或权限 |

提取先保留旧调用入口作为薄适配器，逐步迁移调用者。禁止叶模块反向导入 main_agent 或 realtime。
现阶段一个仓库/runtime 保持单写进程；线程锁不宣称跨进程事务保障。
多进程、多机器共享台账需另立存储事务设计，不把 JSON 原子替换当成完整事务。

## 8. 分阶段交付

| 阶段 | 交付范围 | 完成闸门 |
| --- | --- | --- |
| S0 当前基线 | 委派合同、审查返工、持久收件箱、任务卡 | 已有本地代码；真实模型与原生点击仍需验收 |
| S1 架构收敛 | 收件箱脱离委派私有 API；提取 session actor 与事件层；Desktop useTasks/TasksPanel | 原行为契约通过；领域模块无反向导入；多窗口/FIFO/恢复/项目切换验证通过 |
| S2 有界自动接续 | 提交时授权、只读检查、一次认领、预算、停止与恢复对账 | F3 故障矩阵通过；真实模型费用记录与 Desktop 授权点击有证据 |
| S3 执行中问答 | blocked、问题消息、答复与任务恢复 | F4 身份/版本/取消/重启矩阵通过；一次完整提问—答复—恢复演示 |
| S4 依赖协作 | 显式 depends_on、验收依赖、有限并发与队列公平性 | 依赖环拒绝；前置失败不推进；任务与费用上限不突破 |

顺序按依赖推进，不以日历日期承诺。每阶段应可独立审查、回滚和发布。
S1 的首个落地切片是收件箱解耦；其余拆分不因本文创建而视为已完成。

## 9. 兼容、恢复与故障矩阵

- 老任务无 collaboration / handoff_receipt 时按原任务类型处理，缺回执的终态 dev 保持未处理。
- 无 owner 的旧任务保留在全局任务列表，不猜测应送给哪个会话。
- 成员字段损坏时安全降级或显示错误，不自动获得授权；新字段采用显式类型验证。
- 持久状态是恢复依据，WebSocket 通知只是投递；断线不能丢失任务结果。
- 协议/API 变化同步更新契约测试和路由清单；只读快照不得泄漏运行凭据。
- General 继续无仓库能力；Scratch/Project 之间不复制权限和任务历史。

必须覆盖：重复/乱序事件、两窗口同时发送、旧结果迟到、结果变化后旧确认、
写盘失败、模型超时、超预算、用户停止、确认等待、重连、服务重启、项目切换和原 runtime 失联。

## 10. 度量与验证

新增度量仅记录任务 ID、结果版本、状态原因、时间与用量，不记录敏感正文：

- 未处理交接数量与存续时长；结果持久化到首次处理的时间。
- 自动接续尝试数、成功/失败/取消/预算阻塞数、重复启动数。
- 每任务调度步骤、token、活动时间与人工等待时间，价格未知时成本为 unknown。
- 问题等待时长、恢复成功率、返工轮次与超过三轮的数量。

确定性验收目标：测试矩阵中重复自动启动、跨会话读取、旧版本覆盖均为 0；
所有写盘失败保留可恢复状态。质量与效率指标先采集基线，不预设“提高百分之多少”。

验证分层：领域状态机单测 → 装配/协议集成 → Desktop reducer/hook 测试与构建 →
真实模型任务 → 原生 Desktop 点击与重启/切项目验收。不同层证据不得相互替代。

当前相关自动化入口：`tests/unit/test_task_collaboration.py`、
`tests/unit/test_completion_inbox.py`、`tests/unit/test_web_agent.py`、
`tests/unit/test_gateway_tasks.py`、`desktop/src/lib/taskCollaboration.test.ts`。
人工验收记录进入 [Desktop 验收清单](./DESKTOP_ACCEPTANCE.md)，PR 中列出实际执行的命令与限制。

## 11. 待阶段实施时确定的事项

1. 自动检查的 token 预算如何映射到各 provider 的 usage 与 max-output 约束；不支持时禁用。
2. blocked 子任务如何释放并重获当前 TaskRunner 并发槽，避免挂起 coroutine 长期占槽。
3. 收件箱总输出的分页/长度限制与老任务规模基线；无需在本阶段迁移数据库。
4. Desktop 拆分时当前运行中的项目切换和草稿保护应归哪个域；依照现有架构方案盘点后提取。

这些事项属于后续交付依赖，不能以默认自动开启或未经验证的恢复承诺代替实现。

## 12. 服务入口补充（2026-10-03）

下派能力已增加 HTTP 入口，详见 [任务下派 API](./TASK_DISPATCH_API.md)。它可作为内部业务入口的
执行后端：请求包含 session、request_id、目标、验收要求与执行限制；即时返回 task_id，
调用方随后查询、审查或返工。第一版支持只读研究，开发仍走既有 `/api/tasks`。
合同和幂等信息一起落盘；网络重试不重复执行；重启不自动重试模型调用。

## 18. 会话生命周期与容量保护切片

前台回合和检查共用 SessionActors 的任务槽位与清理包装器，取消早于第一个执行时隙
也会完成收尾。尚未执行的前台输入恢复到 FIFO 头部，Web 通知原请求输入已保留；
已进入执行的输入不自动重放，避免再次调用模型或工具。恢复窗口为该输入预留一个位置，
队列总容量仍为 20，重复请求在满额时仍按幂等处理。立即执行继续优先于 FIFO。

清理期间会话保持忙碌，重复停止更新最终停止原因；旧回合收尾不得清空新回合或取走输入。
后台检查状态由同一任务登记推导，不再维护第二份任务所有权表。

SessionTable 满额时跳过活动回合、检查清理、优先输入、队列和待确认会话。空闲的稳定
SID 会话先保存成功，再构建新会话，最后释放旧资源；保存失败尝试其他空闲候选，
新会话工厂或恢复失败则保留原会话。没有安全候选时拒绝创建，不扩大容量或丢弃状态。
WebSocket 使用原 agent_error 说明原因，1013 关闭并清理连接和订阅；已有会话仍可访问。
明确删除已停止的空闲会话时同步清除 actor 的优先输入与停止标记，避免复用 SID 继续
已删除的输入；执行中及收尾中的会话继续拒绝删除。

本切片仅保护单进程中的生命周期；立即执行优先项仍是内存状态，临时 ws-id 无磁盘恢复。
普通会话保存仍是尽力而为，不宣称所有输入已经可靠落盘、断电恢复或多进程共享锁。
自动检查继续关闭；下一步仍是验证严格 provider、显式授权与完成事件装配。

## 19. 交接与检查记录完整性切片

交接回执必须包含匹配的结果版本、非空处理说明和有时区的有效处理时间，才表示已处理。

尝试 ID，两个空身份不能互相匹配。

的记录。异常文件保留原样，不自动改写为另一个任务，也不参与认领、回执或启动恢复。

所有记录保存在原任务 development 合同，无新数据库、调度池或模型轮询。

提问先保存 running 阶段的待处理问题，再通过通用 ToolTurnYield 停止同批后续工具和模型
请求。隔离工具清理未提交工作树后，原 TaskRunner 才持久保存 blocked、通知并释放执行槽。
已有 landed 块保留；当前块未提交改动被清理，答复后重建上下文并重新实现该块。未证明
清理的崩溃记录恢复为 interrupted 并关闭问题，不能展示为已正常阻塞。

用户可在任务卡回答，业务入口可用 POST /api/tasks/{id}/answer，Web/Desktop 主 Agent
也可先读 task_status，再用同一 task_answer 提交明确的信息。首次回答先保存再排队，
沿用同一任务 ID 和计划；前台不 await 后台开发。错误归属、问题或轮次、过期、取消、
计划/块/分支变化、权限收紧、共享池满或工作树尚未清理均拒绝，失败不消耗问题。
相同答复重试返回实际现状，不重复模型或 Git 操作；不同答复不能覆盖第一次记录。

答复保存后的计划摘要在实际执行前再次检查，项目权限在答复前和每块执行前重载。
回答是信息输入，不是外向授权。开发问答复用固定合同：每个实现 Agent 最多 16 步、
关闭自动继续、每块最多两次修复；同一血缘最多两次提问、三轮执行，第三轮不提供提问工具。
手动恢复继承问答历史、根任务、轮次、污点和限制，不换任务 ID 重置问答次数。

为明确提问后的清理边界，注入问答的后台计划块沿原依赖顺序串行执行；独立无绑定的
CLI/IM/模型回合内开发不新增此能力。blocked 保留为决策注意项，不能验收或记交接处理。
取消关闭问题；重启保留正常 blocked，已保存答复的残留 queued/running 转 interrupted，
重复回答不重跑。开发 done 仍由持久集成与落地证据判定，完成后有独立交接处理回执，
不会自动达成 Goal、审查通过或发布 PR。

本地验收包括 prompt/native 真实主循环配假 LLM、隔离 Git/测试、存储与权限失败、
计划版本和工作树清理、有限轮次继承、主 Agent 共用答复及任务卡失败重试。打包 runtime
用回环确定性假模型验证主 Agent/开发 Agent 全流程；证据与剩余运行层见
DESKTOP_ACCEPTANCE.md。真实模型与打包原生 Desktop 点击仍需独立验收。

下一阶段推进父子依赖任务的提交/等待/结果消费合同与资源预算，先定义持久依赖和失败
传播，再扩展并行问答协调；继续沿用原台账和 TaskRunner。模型回合内委派暂停、跨进程
事务、Git/计划跨资源原子提交和合格生产 provider 自动检查仍未实现。

## 25. 只读研究依赖任务与显式推进切片

业务入口可在原 POST /api/delegations 合同中提交 depends_on，每项固定同一会话的服务研究
任务 ID 和精确轮次。最多 8 项直接依赖、8 层深度、32 个不同前置任务和 128 项遍历；
拒绝自引用、环、错误归属、非服务研究及损坏合同。依赖属于请求幂等指纹，调整依赖需新
request_id；旧无依赖请求保持原指纹。依赖任务的 waiting 和初始合同一次保存成功后才
返回，不创建挂起 coroutine，不占执行槽，不因前置完成或重启自动发起模型。工作区最多
100 个等待任务，继续复用 TaskLedger、CollaborationService 与 TaskRunner。

所有直接前置任务必须在指定轮次 done 且 review=accepted，之后由用户核对具体结果，再
通过任务卡、POST /api/delegations/{id}/release 或 Web/Desktop 主 Agent 的 task_release
显式推进。前置尚在执行或待验收返回冲突并保留 waiting；前置失败、取消、中断、返工，
或归属/轮次/合同变化在显式推进时保存下游 failed，不启动模型。当前没有后台自动失败
传播，也不自动验收上游或处理交接回执。

首次有效推进将完整结果 revision 和有界输入保存为 consumed，再以同一任务 ID 进入原
队列。每项输入包含任务 ID、轮次、结果版本、最多 500 字符任务目标、最多 2000 字符结果、
截断标记和污点。输入只是上下文，不扩大权限。原共享池在实际执行前重新检查结果版本、
验收、归属和已消费祖先；原协作 start 也检查，防止直接调用绕过。删除依赖记录、损坏
处理状态或改变排队后的前置结果都不会启动模型。

重复同轮推进仅返回当前状态，即使原任务已完成、取消、重启中断或进入后续轮次，也不
再次排队。问题/回答、返工沿用已消费的版本与原三轮预算；消费前失败必须创建新合同。
重启保留 waiting；推进保存后残留 queued/running 沿用 interrupted 规则，旧 release
重放不自动执行，需核对证据后显式 followup。单进程锁与原子文件不是跨进程事务保证。

Desktop 下派表单可选择当前会话的前置研究任务，固定选择时的轮次；刷新后轮次变化不会
静默改绑。任务卡展示依赖、等待、失败、可推进与消费记录。主 Agent 先用 task_status
核对状态及结果，再调用 task_release；前台不 await 后台模型。CLI/IM/TUI 未注入共用
服务时不提供推进工具。领域合同核对集中在 task_dependencies.py，路由与前端不推导成功。

验收覆盖等待/验收、多前置、重复请求、版本失效、损坏记录、范围/角色/容量/存储失败、
取消与重启、图边界、传递祖先、真实主循环 prompt/native 工具及消费后问答。打包 runtime
另以回环假模型验证主 Agent 查询/推进和子任务结果消费，Desktop 组件用真实 HTTP 接口
验证选择、验收及重试，详细证据见 DESKTOP_ACCEPTANCE.md。

此切片仅适用于只读服务研究依赖。当前图规模、每任务每轮最多 12 步/600 秒及最多三轮
不表示整条任务链的累计 token/费用硬预算。下一阶段先建立整条链的预算与失效协调，
再扩展自动推进、研究/开发混合依赖和并行问答。生产自动检查保持关闭，模型回合内委派
暂停、跨进程事务和真实 provider/native Desktop GUI 验收仍是独立边界。

## 26. 任务链累计执行额度切片

只读下派入口可选 chain_limits，明确包含 tasks、rounds、steps、timeout_seconds；默认界面
合同为 8 项任务、12 轮执行、64 步配额和 1800 秒超时配额。绝对上限分别为 32、96、
1152、57600，不能用布尔值、缺字段、默认补齐或额外字段改写合同。当前是累计执行
配额，不是 token/费用硬封顶：steps 是原 Agent 主循环的单轮步骤配置，超时按原执行器
每轮上限预留；收尾、工具批次、provider 隐式请求及精确费用不由这份配额计量。

预算保存在原根任务 chain_budget，成员只保留固定根身份。根记录保存有限成员与每个
任务/轮次的预留，累计值从这些记录计算，不增加计量数据库、模型代理或执行池。根
合同及本次成员身份在首次任务保存前确定：即时根任务预留第一轮；等待依赖的根或成员
只占累计任务数，不预留执行轮次，也不占 TaskRunner 槽。

依赖任务自动继承前置任务中唯一的预算根；同链多个前置只认领一次，额外无预算前置
仅作为上下文。不同已有预算根不能合并，继承任务不能提交新的 chain_limits 重设总量。
无预算前置之后可显式建立新根，额度从这个新任务开始覆盖，不能声称计量了前置历史。
没有 chain_limits 且前置均无预算的旧合同保持原行为；独立新任务可建立自己的预算根，
这不是会话或 Goal 的全局费用控制。

推进、返工和回答在新轮次持久排队前预留同一根额度。所有维度都有余额才保存；余额
不足返回冲突，不消耗答案、不改变旧轮次/等待状态、不调度模型。任务取消、失败、重启、
步骤未用完或提前结束均不退款；等待取消也不退累计任务数。相同请求、推进和答复重放
不新增成员或预留，原任务最多三轮/两次问答的限制继续生效。

跨记录顺序是先保存根成员/预留，再保存子任务或轮次转换。第二次保存失败时保留
保守预留、不执行；相同 request_id/任务轮次重试复用原身份，不重复扣额度。已认领但
尚未生成任务文件的请求不能改成不同合同。根自身转换也必须保留最新预留，不能被旧
任务快照覆盖。实际执行与原协作 start 再次核对根归属、固定合同、成员与当前轮次预留；
缺失、重复、超限、错误类型或预算链接丢失均拒绝执行。依赖仍执行原结果版本核对。

HTTP、Web/Desktop 主 Agent 的已有 task_status/task_release/task_followup/task_answer 和
任务卡共用原服务。根计量变化不创建新交付版本，不替代验收或处理交接。Desktop 下派
可启用默认总额度，选择有预算的前置时展示继承状态，任务卡展示累计预留与总量；额度
拒绝保持补充/回答草稿。接口返回 token_cost_hard_limit=false，不把估算 usage 当成硬计量。

本地验收包括图内共享、所有维度封顶、预算继承/合并/重设、保守预留与两次保存失败、
重复操作、取消与重启、合同损坏、HTTP 严格字段、prompt/native 实际 Agent 问答及原
步骤限制。打包 runtime 用回环假模型验证主 Agent 推进和预算耗尽；浏览器使用真实
组件/HTTP 与假 LLM 验证预算选项、重试和草稿保留，证据见 DESKTOP_ACCEPTANCE.md。

后续先补执行期间依赖变化的结果失效与停止协调，再扩展自动推进。token/费用硬封顶
仍需要合格 provider 的可靠计量/输出限额/无隐式请求合同，不能因为执行配额存在就
开放生产自动检查。开发/研究混合依赖、跨进程事务和真实模型/native Desktop GUI 仍待
独立实施与验收；这份单进程文件记录不承诺抵御恶意篡改或回滚整个持久台账。

## 27. 执行期间依赖失效与显式停止切片

本切片补齐“已经消费的前置结果在执行或交付后发生变化”的处理。原 dependency 输入
快照和结果保留为历史，失效记录保存在同一 dependencies 中，不增加任务状态数据库、
反向索引、后台轮询或执行池。

只读服务研究装配一个 execution_check 回调；主循环只调用回调，不依赖任务领域。
检查发生在 prompt/native 模型请求前后、流式正文输出前、压缩请求前后、工具准入与
返回后。异步 hook 返回后再次核对，不能因为等待 hook 而执行过期工具。检查沿用有界
依赖图和固定消费版本；失败先持久记录失效，再拒绝后续调用。最终 finish 在共享锁内
重新核对，注入的其他执行器也不能提交基于失效输入的成功结果。

resolution=invalidated 保留 requires/inputs/released_round，并记录固定任务、owner、
当前轮次、具体原因及有时区时间。记录一旦生成，即使前置恢复原值，旧下游合同也不能
继续执行、验收、回答或被新任务消费。新工作需选择有效前置重新下派，原额度不退款。
损坏合同不能被视为有效，存储失败不报告失效保存成功，也不继续模型或工具执行。

POST /api/delegations/{id}/reconcile 与 Web/Desktop 主 Agent task_reconcile、任务卡共用
原 DispatchService。核对有效时保持原状；失效时先保存 marker，再通过原 TaskRunner
请求取消。返回 stop_requested 只表示请求停止；在途状态保持到执行器退出、清理结束。
重复停止不再次中断清理，槽位在该窗口保留；首时隙前取消和吞掉取消的执行器也会
收敛到 failed，迟到结果不成为成功提交。无在途执行的 queued/blocked 失效直接结束；
有效 blocked 问题保留，失效结束关闭问题且不消费下一轮。

清理已返回但终态保存失败时，投影仍为 stop_pending，表示停止尚未获得持久确认，
不能据此声称执行仍活跃或清理已完成。恢复存储后重复核对只补记终态，不重跑模型。

已经 done 的任务不改写执行历史：旧 result 和 review 均保留，投影 result_valid=false。
任务卡标明“依赖已失效 · 历史记录保留”，隐藏验收、返工及回答入口；提供核对/停止
或记录失效和重新下派提示。marker 纳入交付 revision，旧交接回执不能吞掉这次失效
通知，当前交接处理仍不代表结果有效或 Goal 达成。主 Agent/交接摘要展示相同失效提示。

这是一份检查点与显式停止合同：外部变更在下个检查点或显式核对时被观察，不承诺
变更瞬间停止全部任务。没有全图事件扫描或新调度器；历史任务未被核对前仅在读取
投影中显示失效。已经发出的 provider 请求可能继续计费，取消或超时不证明远端立即
结束，也不退款。同步工具与清理需要自行返回；不会强杀线程或任意扩大权限。

本地验证包括实际 prompt/native Agent 的在途请求/工具失效、压缩/流式路径、最终提交
门、严格 HTTP、动态 owner 的主 Agent 工具、两次保存失败、首时隙取消、重复停止与
槽位保留、已验收历史/交接版本、问答关闭、传递失效和重启。打包 runtime 与浏览器
假模型证据见 DESKTOP_ACCEPTANCE.md；未声称真实模型费用、原生 Desktop GUI 或发布。

下一阶段先建立有界反向依赖发现与事件触发协调合同，再评估自动推进。合格 provider
的 token/费用硬预算、自动检查授权与开发/研究混合依赖仍保持独立门槛。

## 28. 依赖事件刷新与流式中断补漏

排查发现两个可复现的问题：没有链额度的前置变化只更新自身卡片，下游的 ready/失效
投影需要手动刷新；额度刷新若被另一个普通任务事件打断，旧响应虽被拒绝，却没有
后续读取。另一个缺口在流式执行：推理片段没有检查，底层客户端的展示异常隔离还会
吞掉原生正文检查失败；退出异步迭代也没有显式关闭本地生成器或 SDK 响应。

TaskFeed 对服务研究事件读取原任务快照，由服务端投影所有下游依赖和共享额度，
包括无预算链、中间节点没有加载的场景。不在界面计算依赖有效性或执行自动推进。
事件突发合并为一个在途读取和一个待刷新标记；读取期间的新 upsert，包括无关任务，
都会要求补读。原连接、重置代次、请求序号和事件版本门仍拒绝迟到结果；完整事件
快照丢弃待补读。失败只保留现有数据，新的事件或手动动作才能再次请求，不做轮询。

LLM 流适配使用通用 StreamInterrupted 区分执行检查与展示失败，不依赖任务领域。
正文与推理输出前核对；没有推理展示回调时仍核对推理片段。底层客户端继续隔离普通
展示异常，但显式中断必须上抛；Agent 还原原始检查失败（包括持久化错误），不得被
视为显示失败继续读取后续片段。正常结束、执行中断、读取错误和取消均尝试关闭流；
关闭失败记录告警并保留原失败。旧的非流式与不支持推理回调的客户端仍沿用原降级。

本切片不增加任务数据库、服务端反向索引或调度器。前置事件只触发权威投影重读，
持久 invalidated marker 与实际停止继续走检查点/显式 reconcile。原始结果、验收、
交接与 Goal 分开；流关闭尝试不证明远端生成或计费结束，未结清用量也不能当成零。

验证包含真实 LLMClient 配 SDK 形状的离线流、检查异常原样传播、无推理观察者、展示
故障、取消/读错误、关闭失败及异步生成器收尾；TaskFeed 覆盖事件突发、无关事件竞态、
无预算/缺失本地中间节点、断连重置、完整快照与失败重试。真实浏览器用现有 TaskCard、
GatewayClient、HTTP 和 WebSocket 验证自动投影刷新与显式核对；冻结 runtime 回环假
provider 复核原停止/历史交接路径。详细证据见 DESKTOP_ACCEPTANCE.md。

后续仍需服务端有界反向依赖发现和事件停止协调，以发现没有活跃客户端的历史失效；
客户端刷新不替代该能力。自动推进、合格 provider 硬预算与生产自动检查仍待独立验证。

## 29. 有界反向发现、事件协调与离线失效补查

前两切片已经保护执行检查点和客户端投影，但没有活跃客户端或执行检查点的历史任务
仍可能只有读取时显示失效，旧交接回执也没有新的持久 revision。本切片把有界发现与
原核对/停止连接起来，使服务更新、启动恢复和已有所属用户回合能够记录这些失效。

领域实现集中在 gateway/task_dependents.py，读取原 TaskLedger，在共享 TASK_STATE_LOCK
内构建临时反向关系，核对后丢弃；没有第二份台账、持久索引、调度器、文件监听或轮询。
一次最多读 512 个目录项（包括非 JSON，另探测一项判断截断），每条记录最多 262144 字节。
反向发现最多 32 个下游、8 层、128 次边访问；环去重、来源自身不包含在结果中。
从 requires 和固定 dispatch.depends_on 的有界引用发现损坏不一致合同，再由原权威核对
拒绝修改损坏记录。快照不可读、跳过记录、身份/合同损坏、超界或保存失败均明确报告
complete=false，不把找不到或部分成功当作全图有效。尚无稳定分页和目录排序保证。

公共 GET /api/delegations/{id}/dependents 固定来源 owner/当前精确 round，只返回同 owner
下游的 ID、轮次和状态，不保存、通知或取消。POST reconcile-dependents 使用相同发现，
逐项重读下游身份/轮次，已消费或失效合同调用原 DispatchService.reconcile_dependencies。
先成功持久 marker 才请求原 TaskRunner 取消；分支保存失败独立报告并继续其他已发现分支。
批量 202 可以包含 complete=false/errors，不能当作所有分支成功；complete=true 也不
表示执行器已经退出或终态落盘。停止、清理保留槽位、迟到结果和重试仍遵守第 27 节。

服务协作更新、主 Agent 对服务任务的审查适配和原 TaskRunner 更新触发同一领域协调。
内部按来源 ID 发现，来源 owner 变化也能找到其旧下游；公共接口则维持当前 owner 范围。
通知传输失败不阻止领域核对，批次内嵌套更新不再次扫描。等待任务只通知原 readiness/
failure 投影，不保存状态、不 release、不预留额度、不执行模型。接口的管理员 token
仍是可信 runtime 控制面；session 不构成多租户身份认证。

启动先执行原恢复，再核对消费过的合同及仍在途的失效任务。已有所属用户回合在读取
交接提示前执行同一有界核对；先只读发现，无候选时不构造后台池。需要操作但工作区
与原池不匹配时，不修改任一台账，前台继续并提示覆盖未知。General/无任务工具入口
不装配核对。损坏或部分覆盖提示要求先读取权威任务状态，不注入结果正文。

已 done 的历史保留 result、review、原消费快照和额度；新 marker 改变交接 revision，旧
回执不覆盖新的失效通知。重放和来源恢复原值不清除 marker，不再生成重复失效消息，
不重跑模型、不退款、不自动确认交接，也不把交接、验收或 Goal 合并成一个状态。

直接磁盘修改没有服务事件，需在检查点、启动、已有所属用户回合或显式核对时观察。
超界目录和图仍可能存在未覆盖分支，不承诺立即全图停止；取消本机等待不证明远端
请求停止生成或计费。能力报告增加 reverse_discovery/event_reconcile/startup_audit/
turn_audit 与 reverse_limits，automatic_release 仍为 false，生产自动检查仍关闭。

本地回归覆盖历史已验收/已处理失效、传递链、等待投影、在途清理与槽位、首时隙取消、
问题关闭、marker/终态保存失败、通知故障、owner/轮次隔离、工作区不一致、启动/用户回合

## 30. 大台账稳定分页与累计覆盖证据

第 29 节的原扫描每次从目录开头取前 512 项，没有游标，长期重复也不能证明覆盖过后面的
记录。本切片提供独立于该事件前缀路径的显式分页合同。事件/启动/用户回合仍沿用原有界
核对，不自动启动分页循环、模型、等待任务推进或授权检查。

### 固定范围与快照

来源固定 workspace、owner、task_id 和精确当前 round。目录范围包括原 tasks/ 下所有目录项，
但反向图与操作只包括同 owner 的 API 服务下游，不能称整个工作区任务图已完成。
一次清单最多 8192 项，按文件名 UTF-8 字节升序，非 JSON 项也占名额；超界/不可读直接
unknown，不把不完整清单排序后假装可分页。每页最多 512 项/16 MiB，每条最多 256 KiB，
累计扫描正文 64 MiB。清单排序不依据 mtime，因此同名任务更新不会悄悄改变分页位置。

快照记录 dev/ino/mode/size/mtime_ns/ctime_ns，并在每页前后和状态查询复核完整有界清单。
分页期间新增、删除、替换或更新任何记录，及来源/下游 owner/round 变化，均令旧覆盖
unknown 并停止继续；恢复旧文本或 mtime 不清除此状态。记录内容读取还核对前后身份和
SHA-256，损坏/超大/符号链接不能当成有效任务。发现坏记录时可继续完成只读清单覆盖，
图范围保持未知，批量 reconcile 不执行；需要修复后用新请求核对。

这是共享锁下的单进程观察合同：lstat 匹配说明本次观察没有发现变化，不是文件系统或
跨进程事务，不能证明未被观察到的临时变化、底层回滚或恶意伪造没有发生。字节预算
计分页扫描的正文读取，检查点与原单任务依赖验证仍有各自边界。完成报告仅对报告的
观察时间有效；后来变化会在继续/状态查询时变为 unknown。

### 图与操作分页

读完固定清单后才构造反向关系和固定候选顺序。最多 1024 个下游、8192 次边访问、8 层，
循环去重、来源自身排除。预算耗尽只认已发现范围，graph_complete=false，最终仍不完整；
不能因为当前页有 32 项就断言只有 32 个下游。候选逐页最多 32 项，discover 返回引用且
任务只读；reconcile 每项重新核对原 owner/round/内容版本，再调用原 DispatchService。

本次核对允许更新已操作记录的预期指纹，但必须保留身份、输入、结果、角色、原合同、
历史验收和额度，且其他记录/目录成员不能变化。外部变更或副作用改变其他记录则停止
继续并保留 unknown。先保存 marker 才请求原 TaskRunner 停止，清理与持久终态仍遵守原
边界。分支保存失败可继续其他已发现有效分支，累计失败使最终 unknown。done/result/review、
原 inputs 与交接证据保留；历史 marker 不解除，等待任务不自动 release，不新增费用。

只有固定清单读完、整个允许图已发现、所有候选页已处理、没有跳过/损坏/失败/耗尽，且
最终预期指纹复核成功，complete 才为 true。page_complete 只确认一次页请求已返回，不
替代这些条件。discover 完成不代表已核对；reconcile 完成也不代表执行停止、结果验收、
交接已处理、持久交付或 Goal 达成。

### 游标、累计证据与恢复

TaskLedger 在 task_scans/ 保存有界覆盖检查点，任务正文仍只在 tasks/。检查点包括固定
清单、来源合同、候选引用/指纹、确认区间和最后一页操作摘要，不保存结果副本，也不
构成持续同步的全局索引或第二套调度器。检查点原子替换，整体校验和与摘要链独立校验。
每个最多 8 MiB，最多保留 32 个；不静默删除已有覆盖凭据。该生成态纳入原忽略规则。

request_id 固定 owner/source/round，mode 和 page_size 纳入合同，不同合同复用同身份
拒绝。游标绑定扫描身份、序号和随机凭据；篡改、跨范围、猜测及过旧游标拒绝。仅缓存
最近输入的一次重放，重试复用同页结果，不增加序号、覆盖区间、消息或模型调用。
每次推进记录前后清单摘要、页前后区间和结果摘要，并串入 evidence_digest；snapshot_id
固定初始范围，covered_digest 固定已确认身份/轮次前缀。客户端可累计序号与摘要，磁盘
检查点保留完整有序收据用于复核，不把不同快照的计数相加。

每次最多 1024 个推进页，耗尽保持 incomplete；小 page_size 不能借无限请求扩大预算。
状态查询不推进、不核对任务，复核有效性并返回最新游标。重启不自动恢复各页；显式
恢复校验原检查点与实际台账。恢复过程导致任务状态变化时旧快照 unknown，不能自动
重基准。任务已修改但检查点保存失败，不报告页面确认或跨任务原子成功；旧检查点
看到变化后 unknown，新请求可以核对既有 marker，不重跑任务。损坏/缺失检查点不猜进度。

### 客户端与验收

Desktop 原任务卡提供显式开始/继续/恢复/检查/重新开始；UI 消费服务端范围和有效性，
保留原请求互斥与连接隔离。尚未发现完整下游范围时不显示 0/0 完成；成功显示“上次
覆盖核对已完成”和观察时间。网络失败保持原游标，错误不能被旧成功遮盖；来源、轮次、
请求、扫描/快照身份或计数失配拒绝提交，迟到响应不能写入切换后的连接。

合同测试覆盖大于 512 项、70 个下游分批、分页期间增删改/恢复 mtime、owner/round变化、
源身份变化、清单/记录/图/页预算、损坏/符号链接、同页副作用、单页重放、重启继续、
累计摘要复核和保存失败。冻结 runtime 与真实 TaskCard/GatewayClient 使用临时大台账
验证覆盖呈现、响应丢失、有效性变化和恢复，证据见 DESKTOP_ACCEPTANCE.md。

真实 provider 硬预算、自动检查授权、自动 release、跨进程事务仍未开放。下一阶段优先
处理覆盖凭据的显式保留/归档管理和外部变更观察，再评估自动推进；不能把本切片的
覆盖完成用作这些能力的生产准入证据。

## 31. 覆盖凭据的显式保留、归档与容量释放

第 30 节的活动检查点仍最多 32 个。本轮新增独立的显式“保留历史归档”和“释放活动
检查点”动作：先将完整覆盖元数据、原检查点摘要和有序收据保存为不可覆盖的历史文件，
回读核验成功后，用户才可用该归档 ID/摘要及固定检查点版本显式释放原活动文件。
归档本身不释放容量，列表/导出/核验不推进扫描，不改任务、结果或执行池。

归档固定工作区指纹、owner、来源 ID/轮次、scan_id、snapshot_id、原检查点版本、
request_id、观察及归档时间、覆盖/失效状态和摘要链。归档时另观察原范围是否已变化；
保留原检查点和该次观察，不回写进度或解除失效。归档始终 historical=true、
current_coverage=false、resumable=false；当时 complete 仅是历史记录，不能替代当前核对。
归档不证明任务停止、验收、交接处理、持久交付或 Goal 达成。

同归档 request_id/合同重试返回同一文件；不同合同复用身份拒绝。归档写入、同步、原子
替换及回读核验失败，活动文件不删除。释放前再次验证历史文件、摘要及活动检查点版本；
活动进度或观察记录变化则拒绝，需重新保留当前版本。删除失败保留归档，重复释放/重启
后可重试；活动文件已经不存在时，仅在对应归档仍完整时确认释放。释放后的旧扫描请求
不可重建或恢复，必须使用新的扫描 request_id。跨 owner/source/round/workspace 拒绝。

历史文件不保存任务结果正文，也不是第二套任务数据库。最多 128 个，每个最多
8 MiB + 64 KiB；目录枚举和历史列表分页有界。达到归档上限拒绝新增，不扩大上限，
不删除任何历史文件；可导出和独立只读核验。本轮不提供历史删除/重新导入，外部长期
归档与存储迁移需另行设计，不能把浏览器下载成功当作外部持久保存证明。

活动/历史列表只展示固定 owner/source 的资料，保留旧轮次。不可读的活动资料仍占容量，
但不可安全归档或释放；界面给出明确未知提示，不提供绕过删除。历史资料损坏保持
unknown 且不允许释放。导出保留完整校验封套与收据，可在当前任务已变化或不存在时
只读核验；核验只证明文件内部 SHA-256 与收据链一致，不是外部签名或当前覆盖证明。

客户端沿用原 TaskCoverageActions/GatewayClient/请求隔离；容量及管理入口显式加载，
历史区域单独标记，归档响应不能写入活动覆盖。归档重试保持同一 request_id，释放绑定
归档及原版本；连接、owner、来源或轮次变化后的迟到响应丢弃。外部变更观察仍使用原
显式继续/检查边界；后续先处理外部变更观察及长期证据迁移，不启用自动推进、模型
检查或新 provider 权限。实现与验收结果分别记录于 DESKTOP_ACCEPTANCE.md。

## 32. 活动覆盖的显式外部变化观察

复现问题：第 31 节资料列表只返回上次状态；在列表加载后由其它入口修改 tasks/ 文件，
旧 complete 仍是上次证据，不能据此确认当前范围。新增原任务卡内的显式所选观察，
仍由 TaskLedger/task_scan.py、共享锁和 DispatchService 提供，不新增监听器、轮询、
全局索引、任务数据库或执行池。资料加载本身仍不观察，不静默触发观察或核对。

每次选择 1 至 4 个活动检查点，固定工作区指纹、owner/source、各自轮次、scan_id、
snapshot_id、页序号和原检查点摘要，并回显本次 request_id。检查点读取共享 16 MiB
预算（可多读 1 字节检测超限）；损坏资料的实际读取也计入该预算。目录最多 8192 项，按第
30 节原 namespace/lstat 合同连续观察两次，供本次所有可读取项共享。有效性仅对应
观察时刻，双次观察不能证明持续稳定、内容签名、跨进程事务或未发生短暂变更。

可读取项先核对归属与原版本，跨归属/轮次/工作区拒绝；缺失、损坏、版本过期或预算
耗尽逐项 not_observed，不猜测范围，也不重建已释放检查点。预算外和未选择的项没有
当前观察证据。目录超限/不可读、两次清单不同或与原期望不同时，原检查点锁存 unknown、
无继续游标；之前失效的证据不因文件恢复而解除。仅更新观察时间与必要的失效状态，
原 snapshot、序号、偏移、候选、范围、累计摘要和收据链不变。任务正文、旧结果、
done/review、交接、交付和 Goal 均不修改，不调用依赖协调、停止路径或模型。

各活动保存沿用原原子检查点操作，非跨记录事务。单项失败没有 report 或持久成功回执，
其他合法项可完成观察；响应 observation_state=observed/partial/unknown 只表示本次选择
观察的处理范围，与覆盖 complete/incomplete/unknown 分开。observed 的检查点可以仍然
incomplete 或 unknown；恒为 pages_advanced=0、task_graph_reconciled=false。失效只表示
原快照不再可用，不证明具体哪个任务应失效或已经停止；仍须显式重新分页核对任务图。

本次 request_id 用于响应关联，不建立第二份幂等日志。响应丢失后旧摘要重试若已变化，
该项 not_observed/checkpoint_changed；先显式重载版本再观察，不猜成功或重放页。重启
保留已保存的观察与失效，未保存的项保持原证据；不自动观察或推进。观察时间更新会
改变活动摘要，旧归档原文仍保留，但不能据旧摘要释放活动，需先保留当前版本再释放。
归档历史不进入本次目标，永远不能转为当前有效覆盖。

客户端使用原 GatewayClient/useTaskAction 的互斥与连接/任务/轮次隔离；最多四项的
显式勾选、逐项成功/未确认及所选统计均可见。成功回执校验原摘要/快照/序号与未推进
计数后才更新活动区域；匹配当前卡片扫描时同步其状态，不写入历史区域。迟到响应
不能提交到新连接；失败保留“上次”证据并显示当前未确认，不把未选择项算入已观察。

下一阶段优先设计归档历史达到 128 个上限后的长期迁移合同：外部保存凭据、独立只读
核验和显式迁移/释放关系。仍不将浏览器下载当作外部持久保存证明。本轮不开放历史
删除/导入、持续外部监听、自动推进、自动模型检查或新 provider 权限。验收分层见
DESKTOP_ACCEPTANCE.md，原生未验收及此前失败记录保留。


## 33. 长期迁移前的历史文件回验

第 32 节后，历史满 128 项仍保持明确拒绝新增。本轮落实迁移的第一项必要能力：
原客户端可以选择已导出的 JSON 原文只读回验，并提供不依赖当前任务/工作区台账的
离线命令。浏览器下载、读到文件或内部摘要一致均不能证明外部资料已持久保留，故本轮
不删除历史、释放历史容量、导入/恢复活动状态，也不创建迁移数据库、任务池或自动操作。

固定两种摘要：archive_digest 校验历史证据结构和完整收据链；file_digest 为所选原文
UTF-8 字节的 SHA-256，file_bytes 为原文字节数。空文件、非 UTF-8、BOM、重复 JSON
字段、NaN/Infinity（含超大指数转为非有限数）、截断、摘要/链/范围损坏及超过
8454144 字节均拒绝。HTTP 在正文
流入时限制累计缓冲，不能依赖 Content-Length；拒绝重复/额外查询合同字段。原文
上传不经 JavaScript Number 重编码，纳秒整数保持原精度。空白排版变化可以保持相同
历史结构摘要，但原文摘要不同，不能混用两种凭据。

HTTP 固定原 workspace、owner、source/round、archive_id、archive_digest 和所选
file_digest；响应回显全部绑定、验证观察时间和字节数。只核验本次收到的副本，不读取
原活动或服务器归档，原来源已变化/删除或归档已损坏时仍可回验副本。跨归属/轮次/
工作区/版本拒绝；不猜归档身份，不把上传的文件写回台账。失败为 unknown，没有成功
文件回执；重复读取返回同一原文摘要和历史身份，新验证时间不新增扫描页或持久记录。

`vc coverage-verify <file>` 离线读取有界普通文件，不跟随末端符号链接，不读取目录/
FIFO/超长文件；读取前后及当前路径身份变化时拒绝。不依赖 cwd 台账、不导入 provider
或启动 HTTP，也在环境/日志初始化之前返回，不写配置日志。可提供原归档/归属/来源/
轮次/工作区/原文摘要期望值；未提供时仅验证文件内部一致性，输出列出实际检查过的
期望字段，不能称为来源信任、外部签名或当前工作区有效覆盖。

durable_copy_confirmed=false、capacity_released=false、imported=false。回验不证明
任务停止、验收、交接处理、持久交付或 Goal。文件回执仅在界面/命令输出展示，本轮
不保存另一份永久凭据，也不借此解除原历史容量上限或旧扫描的释放/不可重建合同。

标志。沿用 GatewayClient/useTaskAction 互斥；换文件清除旧成功，文件读取期间换文件
或连接/任务/轮次变化的迟到响应不能提交。网络失败可重新核验同一文件，不追加任务
或覆盖证据。活动资料和历史资料仍分别呈现，不将文件成功回写为当前活动覆盖。

## 34. 显式本地保留与保存凭据核对

本轮只实现长期迁移的保存步骤，不释放历史容量。`vc coverage-preserve <export.json>
--directory <专用目录>` 在调用者明确选择的既有本地目录保留原文字节，文件同步、
目录同步并回读后才生成固定保存凭据；不接受 HTTP 下发任意服务器写盘路径，不自动
创建目录。拒绝末端符号链接、非目录、.git/.vortocode 内目标；固定目录设备/inode 和
原文件身份。使用原 TASK_STATE_LOCK，目标目录另用非阻塞文件锁避免多个本地 CLI
争用容量。此锁不提供分布式租约、恶意文件替换或跨任务事务。

文件名固定归档 ID/原文摘要；使用独占临时文件、无覆盖发布、fsync 和回读。目录最多
128 组，每组原文最多 8454144 字节、凭据最多 65536 字节，目录观察最多 512 项
（另可读取一项检测超限）；
坏文件及只有原文的中断组均占容量，无静默删除。原文已保留但凭据保存失败时不确认
成功，保留原文和原台账；同原文/目标重试完成凭据，已存在不同内容或损坏凭据拒绝。
同组成功重试核验并同步已有文件，返回同凭据身份/时间，不覆盖、更新或另建一组。

凭据固定 workspace/owner/source/round、archive/scan/snapshot/checkpoint、原文 SHA/字节、
累计链/收据序号、覆盖与失效摘要、保存观察时间、目标目录及设备/inode/文件名。SHA
和完整原文共同支持只读核验；凭据是本地保存操作的记录，不是第三方签名或持续存在
保证。离线核验可显式重新读取凭据和同目录原文；浏览器只上传所选原文与凭据的原始
文本，服务器只核对内容一致，不访问凭据内路径，也不证明服务器看到了目标存储。
客户端仍固定来源/归属/轮次/快照和两个文件代次，换文件清除旧成功，连接变化丢弃迟到
响应。原保存失败、损坏和旧轮次资料保留，重启不自动重试、同步或释放。

成功状态区分保存 `synced_and_read_back`、本地只读 `read_back_now` 与上传
`receipt_and_uploaded_bytes_consistent`；
仅本地显式重新读到目标才能 storage_observed_now=true。两者均不确认独立故障域、
云端副本、未来保留、电源故障或外部签名，durable_copy_confirmed=false、
capacity_released=false、imported=false，恒为历史而非当前覆盖。不能用凭据推导任务
停止、验收、交接处理、持久交付或 Goal。32/128 原台账上限和旧扫描不可重建合同不变。

下一切片仍需有界退役身份与迁移记录的保存/再迁移，以及针对目标存储故障域的准入
与显式历史释放合同；不能凭本轮上传一致或用户复制成功直接删除服务器历史。
自动检查、自动推进、provider 权限和暂缓原生验收的边界不变。

## 35. 有限扫描退役身份（2026-10-04）

已复现：活动释放后移走原目录中的归档，同一旧扫描请求可重新创建检查点。本轮先补齐
长期迁移前的身份边界，不迁移或删除历史归档。显式活动释放先确认原归档，再在原
TaskLedger 的 task_scans/retirements/ 保存固定扫描退役凭据，文件同步、目录同步和回读

文件和坏名称占容量，无静默淘汰、覆盖或自动扩大。容量不足不释放活动文件。

凭据固定 workspace、owner/source/round、原请求/mode/page_size、scan、归档/检查点摘要、
原观察时间、snapshot/累计摘要链/序号/收据数、覆盖/失效摘要和退役记录时间。它只验证
