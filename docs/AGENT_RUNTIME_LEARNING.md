## 本轮完成

- 原生tools请求不再要求正文只输出JSON；只读独立调用并行、写/依赖调用顺序要求保留。
- 永久不支持tools后，同一回合提示式请求立即重建system协议；瞬时错误不新增兜底请求。
- 保留兼容端点正文JSON解析、历史转换、流式抑制、确认门和能力通知。
- 两种静态协议加入恢复行为指纹；回退开关变化不改变能力身份。
- 固定模板按协议/模式稳定；日期、Git、计划仍走已有动态消息路径。

### VortoCode 的下一版设计基线（待视觉确认，尚未实现）

1. **稳定双栏骨架**：左栏以新对话、项目与最近会话为主；任务中心作为独立次级入口。
   右侧详情默认关闭，发送消息不自动展开，用户打开后保持选择。后台事件用状态提示，
   不抢占页面。当前 App.tsx 发送路径仍自动打开 info，这是待修改项。
2. **对话内单一进度入口**：运行时显示当前步骤、已完成/总步骤及耗时；工具调用默认
   汇总为可展开行。计划缺失显示“执行中”，不编造阶段或百分比。详情查看原活动、
   子任务的精确身份与状态；不在多个区域重复同一组步骤。
3. **结果优先**：回复正文保持干净，链接、文件与改动提供明确入口。失败和等待审批
   在所属轮次可见；确认卡仍复用原回执和监管门。全局看板不进入会话详情。
4. **输入框层级**：附件、模型为常用入口；权限有明确名称；上下文平时仅显示百分比，
   点击弹出简短说明，未知显示未知、估算明确标注。effort 仅在已核验支持时显示
   可调选项；斜杠菜单只列当前可用动作，不借用其他产品尚未接入的能力。
5. **统一视觉系统**：采用低对比背景层级、清晰正文、统一线性图标、少量强调色。
   以间距和字号组织内容，减少卡片套卡片、大片空白和长期占位说明。布局尺寸是
   本项目的设计选择，不宣称来自官方：导航约 240px，正文最大宽约 820px，按需
   详情约 320–400px；窄窗口详情改为覆盖层，不能压坏输入框。

## 长任务框架复核与实施顺序（2026-10-30）

用户同意继续学习并落实到常驻项目推进助手。这轮的决策是先让已有链路可靠，
不继续堆编排角色。常驻助理负责收集、派发、跟进与汇报，开发仍走原隔离工作台；
Goal、轮次完成、动作受理、用户验收和部署继续分别判断。下表是已查阅官方资料后的
工程选择，不表示引入其 SDK 或掌握其内部实现。

### 本轮实施：先修材料完整度

离线复现发现，第一条用户消息只保留前 400 字符，同轮后续 userMessage 未传给监督模型；
618 字符样例末尾的“只写文档、不改代码、不运行测试”因此不可见。这证明材料丢失，
不是已发生越权的生产事故证据。当前修复保留有界的同轮用户文本，标明范围、遗漏、
截断和版本；不完整不调模型、不给额度、不给自动推进建议。材料变化使旧建议失效。
合同与测试边界见 [CODEX_REVIEW_CONTEXT.md](CODEX_REVIEW_CONTEXT.md)。

PR #668 的 Goal 跟进合同已合并；PR #669 的 Goal 进度界面仍独立待审。本轮从包含
#668 的 main 开发，不依赖 #669，不把待审界面或本地源码当作已部署功能。

### 后续开发顺序与停止条件

1. 本轮：完整度、同轮补充、指纹与旧建议失效，离线验证后独立 PR，保留人工合并门。
2. 下一阶段：检查现有 Goal/交接能否明确保存已确认约束、延期与非目标，以及这些内容
   在多轮接续、观察员压缩和版本变更后的来源。先定义快照有效性与真实消费入口，
   不直接建新的任务库；当前 `complete` 只覆盖本轮可见文本，尚不解决全部历史约束。
3. 再做固定轨迹对照：范围缩小、权限拒绝、无新证据、压缩与恢复、同轮补充、版本失效、
   副作用未确认。对比保留/移除某个可选评估环节是否改善质量与成本，不能仅增加循环次数。
   复用原 evals/audit；合成回归只能证明合同，不换算成真实模型或官方 benchmark 分数。
4. 真实模型小样本评测单独列请求数、输入/输出边界及预计费用，获准后才发起；本轮为零。
   没有新证据、达到累计判断上限、状态不可核对或需要权限时，保留原因并等待人工处理，
   不因重启、重新交接、模型自评或新增角色重新发放额度。

研究与代码提交不包含安装、服务重启、上线或真机验收；这些保持独立交付证据。

## 固定轨迹第一批：撤销后不能复活旧交接（2026-10-31）

复用已有 pytest/e2e，将观察、确认、判断、撤销、重新交接、重读恢复与动作状态串起来。
回归发现普通交接缺少独立授权版本，判断期间撤销再交接仍可能采用旧判断。本轮先修这个
实际反例，并覆盖“检查后、写入前又变化”的窗口；不新增评估角色或重复评审循环。
实现、旧记录兼容及运行命令见 [交接版本合同](CODEX_HANDOVER_GRANTS.md)。

这一步落实的是固定行为轨迹和确定性边界检查。原私人助手评分与标准集计划不变；没有
运行真实模型、没有新供应商请求或费用，也没有得出模型能力提升或可移除权限门的结论。
可选质量编排的消融仍需独立样本与同条件模型实测，不能以这批合成回归替代。

## 固定轨迹第二批：记录损坏和容量不能抹掉未知结果（2026-10-31）

新增离线反例表明，动作记录读取失败被当作空状态，以及按数量裁剪全部状态，会损坏后续
审批、恢复和迟到回执的事实依据。本轮让读取失败明确停止写入，只裁剪已结束历史，
未解决记录满额则拒绝新增；临时存储错误通过 503 保留观察员回执，恢复后不重发执行。
合同、兼容性和无法自动恢复的边界见 [动作记录与恢复](CODEX_ACTION_STORAGE.md)。

继续复用原 pytest/e2e、观察员和报告来源，没有新增长期记忆系统、恢复 Agent 或评分平台。
本轮验证的是状态事实与副作用边界，不是模型质量改善，也没有据此增加真实模型请求。

## 固定轨迹第三批：超时不能变成继续推进的依据（2026-10-31）

反例显示 sending 超时转 unknown 后，原监督候选筛选把它当作不再阻挡推进，并调用模型
生成新提议。本轮保持传输未知的事实，让所属会话等待回执，保留逐条人工控制；其他会话
照常跟进。旧版“不确定失败”也统一参与暂停、容量保护、待办、查询和迟到回执处理。
合同见 [结果不明的跟进边界](CODEX_UNCERTAIN_FOLLOWUP.md)。

不增加新的判断角色或自动修复循环；未知时不消耗新的判断额度，已经尝试的判断不因结果
失效退款。巡视提醒按未知集合去重，早晚报直接资料版，不为重复叙述未知状态调用模型。
没有把时间流逝、重新交接或一句泛泛的人工确认当作执行成功/失败证据。
