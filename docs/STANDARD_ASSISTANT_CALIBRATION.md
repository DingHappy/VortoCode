# 私人助手公开标准集校准

复现示例中的 `BENCH_ROOT` 为自行选择的公开题库与依赖缓存目录，运行前请设置该变量；不是固定机器路径。

本轮范围固定为 ToolSandbox 原题 5 道、LongMemEval V1 cleaned S 原题 20 道，各运行一次。它是后续优化的初始校准，不是完整榜单成绩，也还没有构成修改前后对比。自拟14题保留为工程回归。

## 执行边界

- ToolSandbox 固定官方仓库 revision `c8571d7854316d2e1c5f288e59fe1e34e53f6dd1`；使用原工具、原虚拟数据库、原用户模拟器提示和官方 milestone/minefield 评分。VortoCode `MainAgent` 通过原生工具协议执行，模拟器模型替换为当前端点的 `mimo-v2.5-pro`。选题覆盖状态依赖、时间换算、多轮信息、歧义和缺少必要工具；仅选择本地虚拟工具，不操作用户联系人、消息或设备。
- LongMemEval-S 从完整 haystack 历史导入实际 `SessionStore.messages`，以实验性的 SQLite FTS5 后端检索；这是原始会话存档检索，不将历史自动升格为稳定事实。导入没有 LLM 调用，回答模型看不到答案、证据会话标签或 `has_answer`。题型分层固定20题，ID按固定哈希排序选择。
- 检索最多16个命中及其相邻记录，回答上下文约8k代理tokens；reader一次回答，judge一次评分。题目和官方裁判模板不改写。当前端点没有官方列出的裁判模型，因此使用 `mimo-v2.5-pro` 配合原模板，结果明确标记为**替代裁判校准**。裁判不是独立模型，不等同官方同条件分数。
- 一百万tokens是本地预留/停止预算，每请求最多2048输出tokens、最多160请求，SDK关闭重试。估算采用 `cl100k_base × 1.5 + 输出预留`，不是供应商强制硬上限。缺失usage或请求异常后停止，保留未结算预留；逐次原子保存报告，不能把中断算成功。
- 依赖、公开题库和虚拟环境放在 `${BENCH_ROOT}/`。新检索后端仅用于本轮实验，尚未接入已安装桌面版的正式记忆入口。源码状态和已安装服务分开记录。

## 复现入口

```bash
TIKTOKEN_CACHE_DIR=${BENCH_ROOT}/token-cache \
PYTHONPATH="$PWD:${BENCH_ROOT}/ToolSandbox" \
${BENCH_ROOT}/venv/bin/python -m evals.standard \
  --toolsandbox-root ${BENCH_ROOT}/ToolSandbox \
  --longmem-data ${BENCH_ROOT}/longmemeval_s_cleaned.json \
  --judge-prompt-source ${BENCH_ROOT}/evaluate_qa.py \
  --tokens 1000000 --live
```

环境包版本另存 `${BENCH_ROOT}/requirements.lock.txt`。运行报告在 `evals/reports/standard/`（git忽略）；包括题ID、数据和裁判模板SHA、源码SHA、请求用途/真实usage、逐题输出与官方轨迹。数据许可、正式依赖分发与桌面入口集成需在产品化时另行处理。

## 如何用于后续优化

分别看 ToolSandbox 状态相似度、minefield触发，以及 LongMemEval 各题型的答案正确率。不要将工具任务分数、记忆答案和token成本混成一个加权总分。当前25题仅用于发现失败类型；调试后应保留独立未使用的题ID，再固定模型、裁判、协议、检索预算和环境做前后各至少两遍的正式回测。

原始记录检索、更新/日期处理和工具执行是当前优先改进方向；AppWorld跨应用任务放在下一阶段。实际结果见本文件后续记录。

## 首次校准结果

运行报告：`20261013T033950930465Z.json`（本地运行记录，未发布）。25题全部完成，运行中源码SHA保持一致，耗时392秒。71次请求，供应商usage均完整，共 **256,509 tokens**，低于100万本地预算。没有生成修改后的能力成绩，也没有自动晋升产品基线。

请求配置是 `mimo-v2.5-pro`，但71次响应的模型字段全部为 **`mimo-v2.6-pro`**。这只能说明端点返回的标记，不能据此验证供应商内部实际权重。后续比较必须保留请求模型和返回模型两个字段，避免把路由变化当成代码改善。

这20道固定题没有抽到abstention题。单次、小子集、同模型裁判结果仅作校准，不能宣称完整LongMemEval成绩或显著改善。当前测试的是API端点，不是3090 Ti或本地27B的速度/准确率。

## 改进顺序与回测边界

1. **跨会话证据补全**：优先改检索，对需要列举/计数的问题扩大相关会话覆盖；保留原始会话ID、日期和片段来源，控制总上下文预算。使用本地混合检索/重排时，把构建成本另行记录。
2. **日期与更新关系**：规范化时间字段，区分事件发生时间与对话日期、累计次数与单次描述；有冲突时检查原始记录，而非仅按最后一条片段覆盖事实。
3. **执行与表达**：处理依赖状态与时间依据；英文问题用英文简洁回复。评分仍用原官方规则，不围绕目标答案改提示。
4. **正式前后比较**：冻结新的未参与调试题ID，补齐abstention覆盖；同数据、模型及实际返回模型、裁判、执行/检索限制，前后各至少两遍。以官方指标分别比较，并保留全部失败与tokens，不自动用本轮80%当晋升阈值。AppWorld随后追加。

首次报告为格式v1，其依赖锁另存在运行目录。校准后的格式v2增加显式执行限制、依赖版本和实际返回模型汇总，并在每次请求前后保存明细；这项记录改动未再发送模型请求，不能声称已有新的改进后成绩。

## 服务端过滤与计量边界

一条原始公开 LongMemEval 请求在当前 MiMo 上游的官方 Token Plan API 直连中返回 HTTP 200、content_filter 且缺少 usage。确认该响应可由上游独立产生，具体触发规则未知。未修改原题或历史来绕过过滤。SDK 与 aiohttp 非流式路径、正文流与工具流均将过滤标记转为明确错误并停止；过滤前已显示的部分文字无法撤回。

标准回测将供应商阻断与能力失败分开记录，缺失 usage 保留未知预留，不当作零消耗；这轮正式留出对照未完成，不能宣称语义检索提高准确率或节省实际费用。当前发布入口只提供 baseline/compact，语义执行后端及其依赖待独立集成。

相关工程合同包括版本、预算、完整覆盖和逐题比较门；单测、部分题集及替代裁判成绩均不等于完整公开榜单成绩。运行记录和供应商排查材料未随仓库发布。
