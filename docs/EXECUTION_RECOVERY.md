# 执行失败与备用接手合同

2026-10-30。`agents/backends/recovery.py` 在共同执行合同之上提供纯决策，现接入实验性外部 CLI、开发自修复与审查重试路径。它不启动进程、不调用模型、不存第二套任务台账，也不授予审批或预算。

## 决策

调用方必须提供可信适配器刚取得的权威观察及预期执行身份，并负责授权、来源时效与原预算。解码一份外部快照不因此获得执行权限。

| 已确认的事实 | 决策 | 适配器行为 |
| --- | --- | --- |
| 身份一致、FAILED、有明确错误、effect=not_started、没有结果、未明确禁止重试，且确认执行者不可用 | fallback | 有已授权的内置备用工厂时才接手一次 |
| 身份无法匹配、终态失败无法确认、错误依据缺失、effect=possible/unknown，或“未开始”却携带结果 | inspect | 不自动切换或重跑，交人工核对 |
| 未开始但属于普通错误，或错误明确 retryable=false | fail | 不授予备用接手，保留失败，由原入口按其合同处理 |

限流、登录失败、鉴权失败或错误文本只用于识别可用性，不能证明此前没有执行。当前 CLI 适配器将已启动进程的失败保守标为 possible，读审查任务也使用相同规则；不能仅凭“只读”推定没有调用费用或其他副作用。

## 现有路径的处理

- 未找到 CLI、确认进程未启动时，仍可由原工厂创建内置 Agent，沿用原工作目录、工具、权限与调用方预算。备用对象不能再是另一个外部 CLI 适配器，避免递归切换。
- 已启动的 CLI 遇限流、退出错误或其他需核对的结果时，抛出 `RecoveryRequired` 的外部执行异常；适配器报告保留原执行身份和副作用状态，并明确 `retryable=false`。原生失败报告仍可从 `last_run` 核对。
- 此类结果不会让执行者进入“后续自动选内置 Agent”的冷却路径。只有确认未开始且实际允许接手的情况才设置原有冷却。
- 隔离实现和依赖接力收到该信号后停止当前调用内的自修复重试，不用先前一份绿结果掩盖后来的未知尝试。
- 对应审查视角不再自动重试；其他视角已确认的问题保留。首轮存在需核对的执行时，不自动修复；复审出问题时不清除原发现。审查不完整继续沿原 incomplete 回调记录，不冒充已通过。
- 普通成功和普通失败保持原清理规则。需核对的隔离/接力/审查工作区保留，供原任务或执行记录核对。相同工作区 ID 已存在时拒绝创建，不自动删除旧目录。人工检查之后才能显式清理。

未知结果不被改记为“确定未执行”。进程确认退出也不能证明此前没有文件、网络或费用副作用。已有会话控制仍保持不自动 fallback、不重放写请求的更严格合同。

## 验证与范围

回归使用纯快照、临时 Git 仓库、假 CLI、模型替身与注入的 reviewer/worker，覆盖执行身份、状态和副作用组合，未开始的安全接手，启动后的限流与普通失败，递归接手拒绝，工作区保留/复用拒绝，以及开发和审查内层重试的停止。测试不调用真实 CLI 账号或真实模型。
