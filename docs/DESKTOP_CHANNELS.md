# Desktop 个人频道：第一步

2026-11-14。按主人选定的个人界面与频道方向，先将频道接入真实会话，再迁移其余界面。完整视觉目标仍见 [设计 PR #883](https://github.com/DingHappy/VortoOne/pull/883)；本 PR 直接基于 main，不依赖原型分支。

## 已实现的行为

- 在当前已连接的个人空间创建有名称和可选说明的频道；同名创建返回明确错误。
- 频道是原有 SID 会话的展示元数据 `channel: {version: 1, topic: string}`，仍保存在原会话文件。空频道也持久化，服务重启后可以重新列出、打开。
- 创建只写会话记录，不构造 Agent、调用模型或占用活动会话名额。打开后沿用原 WebSocket、Agent、历史、附件、确认和停止流程。
- 侧栏将频道与主要聊天、普通旁聊分开；搜索可匹配频道名和说明。删除复用原会话删除路由，先确认删除对话记录。
- 输入沿用原 `targetKey + sid` 草稿池。频道之间、运行端之间隔离；草稿生命周期仍与现有 Desktop 一致，并未新增跨重启或跨设备的草稿同步。
- 创建与删除绑定当前连接的目标租约。发送前与回执后均核对原连接；目标或连接代次变化即停止接受旧回执，不自动重试，也不跳到另一个空间。

## 数据与权限边界

新增 `POST /api/agent/sessions` 只接受名称、说明，复用原 API 鉴权和当前运行端目录。客户端不能传入 SID、目录、岗位或权限；路由基线已更新。首次写入使用原会话存储的持久保存路径；失败不返回成功回执。

说明只用于界面展示，不加入模型系统提示、历史或工具配置，不授予专员任何权限。原确认门、污点规则、无人值守默认拒绝和原会话连接作用域保持不变。旧会话没有此字段时照常读取；未知版本或夹带额外字段的元数据不被当作频道。

名称创建限 1～30 字、说明限 300 字。频道本身不意味着多人群聊、自动共享专员历史或创建后台任务。
