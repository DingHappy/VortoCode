# 网站连接与手机操作

2026-10-31，源码实现与后续路线。这里的凭证指网站登录和 Cookie，不是模型 API Key。
本轮从宿主环境凭证边界修复分支继续，独立于模型 Keychain 草稿 #682；没有迁移任何真实凭证。

## 当前可用范围

网站连接复用原 MainAgent、工具运行层与 `INTERACT` 确认门；只在用户显式启用浏览器操控的
Desktop Web 会话提供。IM、CLI、无人值守及远端 runtime 不因此取得本机登录态。
模型只提出工具请求，执行仍在浏览器所在宿主。没有新增任务队列、调度器、跨主机连接或云端 Cookie 同步。

| 能力 | 当前实现 | 仍需验收或开发 |
| --- | --- | --- |
| 桌面网页 | 独立 Chromium 目录、网站连接、人工登录接管、页面读取及逐次确认的点击/输入/滚动 | 真实浏览器、网站登录和业务交付验收 |
| 手机网页 | CDP 设置 390×844 视口、缩放、移动 UA、触摸点击与滚动 | 目前以假 CDP 传输验证命令；不是实际 Android、iPhone 或 Safari |
| Android 原生 App | 路线：Android Emulator/真机 + Appium UiAutomator2 | 设备发现、适配器、设备租约、权限对话框、取消及真实 App 验收均未接入 |
| iPhone 原生 App | 路线：Mac/Xcode + Appium XCUITest，分别支持 Simulator 与符合配置要求的真机 | 同上，真机还涉及签名与设备配置；没有承诺能操作所有 App |

手机网页模拟不覆盖系统设置、应用安装、通知、短信或原生权限弹窗。模拟器也不能证明真机的
SIM、相机、蓝牙、支付或应用风控行为；这些按真实设备与具体 App 单独验收，不绕过其认证。

## 使用流程

1. Desktop 设置中开启“浏览器操控”，重启当前本机引擎。
2. 在可使用写工具的模式提出连接网站，调用 `browser_connect`，传 HTTPS 地址、简短账号标签
   与 `device_mode=desktop|mobile`。主人确认后才登记；不要把密码、Cookie 或验证码写进标签或聊天。
3. `browser_connections` 查看本工作区连接，`browser_open(url, connection_id)` 使用指定连接。
   每次带登录态导航都确认网站、账号标签和页面将交给模型处理，私密 URL 路径/参数不会回显到确认文案。
4. 专用窗口首次启动即处于人工接管状态。主人在窗口内完成登录、扫码、SSO 或验证码，核对实际账号。
   `browser_login` 请求主人确认恢复；仍在登录页、跳到其它 origin 或登录状态无法核对时继续暂停。
5. 恢复后可读取页面及截图；点击、普通表单输入、滚动逐次确认。会话过期/敏感表单出现后再次人工接管，
   不自动轮询登录页、重试提交或反复弹出登录请求。模型仍受原回合/工具预算约束。
6. `browser_close` 关闭本会话浏览器。`browser_disconnect` 经确认撤销助手连接并关闭本会话对应窗口，
   **保留本机登录目录**，不等于退出网站、删除 Cookie 或撤销网站服务器授权。

不传连接 ID 且当前没有连接时，`browser_open` 使用临时匿名目录；不加载历史共享
`~/.vortocode/browser-profile`，也不扫描或导入日常浏览器。已有窗口不自动切换网站账号，先明确关闭。
关闭匿名窗口后删除其临时目录；已登记的专用目录可跨启动保留，但人工恢复确认不会跨启动保留。
若授权窗口中拒绝导航，则没有打开页面；拒绝登录恢复则保持暂停，可明确关闭。

## 归属、容量与清理

`src/browser/connections.py` 只存本机授权元数据：连接随机 ID、工作区规范路径摘要、精确 HTTPS origin、
账号标签及网页模式。位置是 `~/.vortocode/website-connections/connections.json`，不在项目内；
文件 600、目录 700，拒绝不可信权限与符号链接。损坏、未知字段、重复 JSON 键直接拒绝，
不会从旧目录猜测账号。每次操作重新核对当前工作区授权，确认等待期间撤销也不能继续点击。
同 origin 下的两个账号使用不同连接 ID 和不同目录；账号标签不是站点返回的真实用户 ID。

每个连接使用 `profiles/<id>` 专用目录，Chromium 自己保管登录状态。目录独占复用既有
`ProcessLease`，直到浏览器确认退出才释放；清理失败保留占位，禁止继续使用，须明确重试关闭。
原 runtime 退出路径在任务清理后关闭浏览器、最后释放运行端租约。启动期间关机不会再打开目标网站。
进程上限 8 个活跃/启动/待清理浏览器，注册表上限 64 条、128 KiB；不排队，不淘汰已授权连接。
连接上限按同一宿主注册表总量计算，列表仅投影本工作区。撤销不清 Cookie；已撤销目录不会被自动重新发现。

这不是抵御同用户恶意进程的秘密保险箱。宿主工具仍受既有 OS 沙箱与文件访问边界约束，
文件权限不能保证所有同用户进程无法读盘。不同机器没有会话共享或自动迁移。

## 页面内容与人工接管

`page_privacy.py` 的生产 JS 不读取表单 `.value`。在投影标题、正文、URL 或元素标签之前，
可见密码、OTP、已知 token/secret 字段会使整个页面暂停；常见登录与安全/支付路径也暂停。
URL 输出只保留 origin，隐藏路径、查询、片段和 userinfo，避免回传登录回调参数。
人工接管期间不执行页面读取、截图、点击、输入或导航；恢复仅检查站点与敏感表单，再请主人核对账号。
`user_confirmed` 只代表主人确认，**不是已独立验证站点账号身份**。

Agent 仍禁止操作原受限域名及内网地址。已登记连接跳入 SSO 时只让真人查看，Agent 不读取账号站点；
恢复需返回授权的精确 origin。其他越界页面暂停；受限的非 SSO 目标在检查时回到空白页。
这沿用既有导航后检查，不是浏览器网络层的请求拦截或对所有子资源的 SSRF 隔离。

可见 iframe/frame 时拒绝截图，顶层 DOM 投影不遍历其内部；当前不承诺识别 shadow DOM、
所有自定义扫码流程或普通正文中显示的秘密。顶层表单识别与截屏之间仍可能有异步页面变化，
因此不能把启发式过滤当作任意页面脱敏保证。专用会话只用于主人同意交给模型处理的网站。
页面内容继续标记为不可信外部内容，不取得确认权；不接受模型代填密码或验证码。

点击/输入在等待确认后重新核对授权、页面 URL 与目标元素。不自动重试失败动作，但当前没有
网站业务提交的持久幂等回执：网络断开或浏览器崩溃后的结果不明须人工核对，不能推断失败后重新提交。
撤销阻止后续动作；其它会话已经发出的请求不会因此被网站撤回。

## 原生设备下一步

沿用原工具运行层和任务状态，各设备适配器只负责发现、连接、观察、单次动作、取消与清理。
先显式绑定宿主/设备/应用与 owner，不按设备名称猜测授权；每台设备同一时刻一个执行者。
设备租约、连接代次和主人确认绑定目标，不能从 Android 自动切到 iPhone，也不复制手机登录态到云端。
用户认证留在设备上完成。断连、权限未知或提交结果不明时停止自动推进，回到原任务请求人工核对，
不再创建第二套轮询循环。

实施顺序为 Android 模拟器单 App → Android 真机 → iOS Simulator → iPhone 真机。
每一步先验证目标身份、主人确认、拒绝、断连、取消与清理，再用一个具体 App 跑完整业务流程。
本轮未安装 SDK/Appium、启动模拟器、连接手机、读取真实网站凭证或发起付费模型请求。
