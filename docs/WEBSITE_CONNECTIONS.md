# 网站连接与手机操作

2026-10-31，源码实现与后续路线。这里的凭证指网站登录和 Cookie，不是模型 API Key。
本轮从宿主环境凭证边界修复分支继续，独立于模型 Keychain 草稿 #682；没有迁移任何真实凭证。

## 当前可用范围

网站连接复用原 MainAgent、工具运行层与 `INTERACT` 确认门；只在用户显式启用浏览器操控的
Desktop Web 会话提供。IM、CLI、无人值守及远端 runtime 不因此取得本机登录态。
模型只提出工具请求，执行仍在浏览器所在宿主。没有新增任务队列、调度器、跨主机连接或云端 Cookie 同步。

浏览器传输现通过 `BrowserBackend/BrowserDriver` 接口装配，生产默认仍是原 Chromium CDP；
宿主代码可替换经审阅驱动，授权与人工接管留在原工具层。不同驱动独立存登录态，同一连接共用租约。
设备插件、统一管理和当前未实现项见 [可插拔能力设计](PLUGGABLE_CAPABILITIES.md)。

| 能力 | 当前实现 | 仍需验收或开发 |
| --- | --- | --- |
| 桌面网页 | 独立 Chromium 目录、网站连接、人工登录接管、页面读取及逐次确认的点击/输入/滚动 | 真实浏览器、网站登录和业务交付验收 |
| 手机网页 | CDP 设置 390×844 视口、缩放、移动 UA、触摸点击与滚动 | 目前以假 CDP 传输验证命令；不是实际 Android、iPhone 或 Safari |
| Android 原生 App | [已有会话插件](ANDROID_SESSION_PLUGIN.md)：本机 Appium 绑定、原生 UI 与确认点按，默认关闭 | 发现/会话创建、输入/滑动和真实模拟器/App 验收待补；系统弹窗交还真人 |
| iPhone 原生 App | 路线：Mac/Xcode + Appium XCUITest，分别支持 Simulator 与符合配置要求的真机 | 同上，真机还涉及签名与设备配置；没有承诺能操作所有 App |

手机网页模拟不覆盖系统设置、应用安装、通知、短信或原生权限弹窗。模拟器也不能证明真机的
SIM、相机、蓝牙、支付或应用风控行为；这些按真实设备与具体 App 单独验收，不绕过其认证。

## 使用流程

原生 Desktop Agent 回合已接入[任务内网站接管卡](WEBSITE_HANDOFF.md)：需要人工处理时，
当前工具直接等待卡片确认，不再需要模型追加一次登录调用。同回合拒绝/核对失败不会反复弹卡；
新用户消息可再次请求。以下工具名保留作为高级调用合同，普通用户不必输入工具名。

1. Desktop 设置中开启“浏览器操控”，重启当前本机引擎。
2. 在可使用写工具的模式提出连接网站，调用 `browser_connect`，传 HTTPS 地址、简短账号标签
   与 `device_mode=desktop|mobile`。主人确认后才登记；不要把密码、Cookie 或验证码写进标签或聊天。
3. `browser_connections` 查看本工作区连接，`browser_open(url, connection_id)` 使用指定连接。
   每次带登录态导航都确认网站、账号标签和页面将交给模型处理，私密 URL 路径/参数不会回显到确认文案。
4. 专用窗口首次启动即处于人工接管状态。主人在窗口内完成登录、扫码、SSO 或验证码，核对实际账号。
   接管卡请求主人确认恢复；高级调用仍保留 `browser_login`。仍在登录页、跳到其它 origin 或登录状态无法核对时继续暂停。
5. 恢复后可读取页面及截图；点击、普通表单输入、滚动逐次确认。会话过期/敏感表单出现后再次人工接管，
   不自动轮询登录页、重试提交或反复弹出登录请求。模型仍受原回合/工具预算约束。
6. `browser_close` 关闭本会话浏览器。`browser_disconnect` 经确认撤销助手连接并关闭本会话对应窗口，
   **保留本机登录目录**，不等于退出网站、删除 Cookie 或撤销网站服务器授权。

不传连接 ID 且当前没有连接时，`browser_open` 使用临时匿名目录；不加载历史共享
`~/.vortoone/browser-profile`，也不扫描或导入日常浏览器。已有窗口不自动切换网站账号，先明确关闭。
关闭匿名窗口后删除其临时目录；已登记的专用目录可跨启动保留，但人工恢复确认不会跨启动保留。
若授权窗口中拒绝导航，则没有打开页面；拒绝登录恢复则保持暂停，可明确关闭。

## 归属、容量与清理

`src/browser/connections.py` 只存本机授权元数据：连接随机 ID、工作区规范路径摘要、精确 HTTPS origin、
账号标签及网页模式。位置是 `~/.vortoone/website-connections/connections.json`，不在项目内；
文件 600、目录 700，拒绝不可信权限与符号链接。损坏、未知字段、重复 JSON 键直接拒绝，
不会从旧目录猜测账号。每次操作重新核对当前工作区授权，确认等待期间撤销也不能继续点击。
同 origin 下的两个账号使用不同连接 ID 和不同目录；账号标签不是站点返回的真实用户 ID。

每个连接使用 `profiles/<id>` 专用目录，Chromium 自己保管登录状态。目录独占复用既有
`ProcessLease`，直到浏览器确认退出才释放；清理失败保留占位，禁止继续使用，须明确重试关闭。
原 runtime 退出路径在任务清理后关闭浏览器、最后释放运行端租约。启动期间关机不会再打开目标网站。
进程上限 8 个活跃/启动/待清理浏览器，注册表上限 64 条、128 KiB；不排队，不淘汰已授权连接。
连接上限按同一宿主注册表总量计算，列表仅投影本工作区。撤销不清 Cookie；已撤销目录不会被自动重新发现。

这不是抵御同用户恶意进程的秘密保险箱。宿主工具仍受既有 OS 沙箱与文件访问边界约束，
文件权限不能保证所有同用户进程无法读盘。不同机器没有会话共享或自动迁移。

## 页面内容与人工接管

`page_privacy.py` 的生产 JS 不读取表单 `.value`。在投影标题、正文、URL 或元素标签之前，
可见密码、OTP、已知 token/secret 字段会使整个页面暂停；常见登录与安全/支付路径也暂停。
URL 输出只保留 origin，隐藏路径、查询、片段和 userinfo，避免回传登录回调参数。
人工接管期间不执行页面读取、截图、点击、输入或导航；恢复仅检查站点与敏感表单，再请主人核对账号。
`user_confirmed` 只代表主人确认，**不是已独立验证站点账号身份**。

Agent 仍禁止操作原受限域名及内网地址。已登记连接跳入 SSO 时只让真人查看，Agent 不读取账号站点；
恢复需返回授权的精确 origin。其他越界页面暂停；受限的非 SSO 目标在检查时回到空白页。
这沿用既有导航后检查，不是浏览器网络层的请求拦截或对所有子资源的 SSRF 隔离。

可见 iframe/frame 时拒绝截图，顶层 DOM 投影不遍历其内部；当前不承诺识别 shadow DOM、
所有自定义扫码流程或普通正文中显示的秘密。顶层表单识别与截屏之间仍可能有异步页面变化，
因此不能把启发式过滤当作任意页面脱敏保证。专用会话只用于主人同意交给模型处理的网站。
页面内容继续标记为不可信外部内容，不取得确认权；不接受模型代填密码或验证码。

点击/输入在等待确认后重新核对授权、页面 URL 与目标元素。不自动重试失败动作。
网站连接现有[结果不明阻断](#操作结果不明与恢复)：这不是网站业务提交的持久幂等回执，
网络断开或浏览器崩溃后的结果不明须人工核对，不能推断失败后重新提交。
撤销阻止后续动作；其它会话已经发出的请求不会因此被网站撤回。

## 操作结果不明与恢复

2026-11-01 补充：沿用原 BrowserSession、专用目录租约和人工接管确认门。每次导航、点击、
输入（含回车提交）和滚动，在派发前保存一个待核对标记；收到动作及所需页面读取回执后清除。
标记只包含格式版本、随机派发 ID 和动作类型，不保存网址参数、页面、账号内容、输入或 Cookie。
已登记连接使用 `profiles/<id>/.vortocode-pending-action.json`，权限 600，仍在原连接独占租约内，
不同受信任驱动共享该阻断。没有新增任务队列、后台循环或自动重试。

- 传输/读取异常、取消、关闭期间返回及授权变化保留标记。后续导航、点击、输入与滚动直接拒绝，
  不再弹重复操作确认；当前页面在原隐私边界允许时可只读核对。资源总览显示“上次操作待核对”。
- 已登记连接重启/重装配后仍阻断。重新打开只启动空白专用窗口，不导航到原目标 URL，避免
  重复触发有副作用的 GET；主人在窗口内核对原网站/账号/操作结果。
- 原 `browser_login` 接管卡明确提示上次操作结果不明。主人确认后重新检查原站点、授权、
  敏感表单与本次标记身份，才解除阻断；拒绝、取消、仍处于 SSO 或核对失败不清除。
  原同一真实回合最多一次接管的规则不变，新模型请求不能刷新额度。
- 关闭窗口或撤销连接保留已登记连接的标记；这仍不等于网站退出或服务器侧撤销。损坏、
  符号链接、权限异常及不兼容记录拒绝使用，不猜测或自动删除。
- 浏览器适配器异常及待核对阻断返回原工具协议 `ok=false`，工具运行层记录 failed，
  不再把异常提示当成成功；取消继续传播为 cancelled。CDP 页面就绪等待到期也明确抛出失败，
  不再静默当作已就绪。其它原有正常文本回复合同保持不变。

这是派发回执的防重放围栏，不是“签到成功”的业务证明。正常动作回执后仍需网站特定的
“当前账号、今日签到状态、成功证据”核对；人工解除也不证明原动作成功或失败。它不能在网站
服务器上撤销已发出的请求，也不跨新建连接识别同一个实际账号。临时匿名窗口只在当前
BrowserSession 保留内存阻断，不能承担跨运行端重启的已登录任务；此类任务应先登记网站连接。

离线故障回归见 `tests/unit/test_browser_uncertain_actions.py`：超时、取消、读回失败、登录页、
导航/输入/滚动、关闭重开、新工具会话、拒绝/错误站点/撤销、待核对文件损坏和原 ToolRuntime
失败事件。`tests/e2e/test_browser_uncertain_delivery.py` 用原 MainAgent 和脚本模型连续请求两次
提交，核对只发出一次动作、两次工具事件均为 failed、最终保留待核对状态。
尚未由唐帕真实登录态验收；常驻端接入与后台定时操作仍不在本次实现范围。

## 首个日常任务：唐帕签到

用户指定 `https://www.tangpt.top/` 作为试点。2026-11-01 人工辅助浏览器检查时，首页已有
登录态，签到入口显示“签到已得 10000”；未再次点击。该观察来自 ego-browser，不是
VortoOne 的专用连接，也不证明后者已持有登录态。没有复制 Cookie 或保存账号身份资料。

下一切片先做有人在场的单次任务，验收至少覆盖以下分支：

| 页面情况 | 所需行为与证据 |
| --- | --- |
| 未登录/登录过期 | 交还专用窗口登录；不在对话中收集密码/验证码，不反复弹卡 |
| 已登录但实际账号未核实/不符 | 暂停提交，请主人绑定并核对期望账号；不能用连接标签代替网站身份 |
| 已签到 | 读取站点当前签到状态并结束，不点击签到入口、不重复请求提交 |
| 未签到 | 取得原确认后只提交一次，重新读取当天签到状态；动作回执不是业务成功 |
| 登录/签到状态不明确 | 保持未知，不按按钮文本缺失推断未签到，也不按没有报错推断成功 |
| 提交后断网/超时/取消 | 保留上面的待核对标记，只核对结果；人工恢复不自动重放 |

站点日期口径、账号字段与成功/未签到证据须在真实专用连接验证，不把一次首页文案当作
已经实现的站点适配器。不要为查看签到记录而盲目打开可能同时执行签到的入口。
常驻电脑需另有明确的浏览器能力准入、可见窗口和人工接管验收；不能伪装本机 Desktop
环境变量来扩大宿主权限。先完成“同一宿主重启复用、账号核对、过期恢复、真实单次签到”，
再沉淀技能及评估窄范围自动执行；不能仅新建 cron 提示就声称每天自动签到已经可用。

### 已实现：唐帕只读状态核对

`browser_site_status` 在原浏览器工具里提供，不新增连接、任务循环或持久账号资料。
只接受当前已打开的精确 `https://www.tangpt.top` 站点；其他站点返回不支持和未知，不导航、
不猜测同类 NexusPHP 站点规则。它沿用原授权、页面隐私检查、人工接管及外部内容污点。

2026-11-01 通过 ego-browser 只读核对：首页有唯一退出链接，其最近的表格单元格包含唯一
账号链接和签到入口，入口文案为 `[签到已得10000, 补签卡: 88]`。没有点击入口；实际账号
资料、Cookie、表单值及页面全文未写进本仓库。生产投影只读取该顶部区域的可见账号名、
站内数字用户 ID 和有界签到文案，避免误取论坛、排行榜里的其他用户；敏感表单先暂停。

| 返回状态 | 含义与后续行为 |
| --- | --- |
| `page_reports_signed` | 完整匹配已观察的奖励文案；报告页面显示已签，不再点击签到入口 |
| `page_offers_checkin` | 仅精确匹配常见入口文案；这些未签文案尚未经本站真实未签页面验收，不能推断今日未签或自动提交 |
| `unknown` | 缺失、冲突、页面改版、多个账号或无有效登录标志；暂停提交并人工核对 |

`account` 来自网站可见页面，不来自连接标签；`account_verified=false`、`business_verified=false`、
`site_date=null` 明确保留未验收边界。`observed_at` 只是宿主观察时间，不是站点签到日期。
核对前后检查原 URL、连接授权及浏览器所有权；变化则丢弃结果。读取不会清除待核对标记；
即使页面显示奖励，上次结果不明的动作仍须主人明确核对恢复，也不会自动重放。
原敏感路径识别同时覆盖 `login.php`、`signin.html`、`mfa.aspx` 等常见扩展名；即使没有
可识别的密码输入框也先交还真人，不读取登录正文；不按 `login-guide.php` 等子串误判。

验证包括 Python 状态分类、用 Node 执行生产 DOM 投影的夹具、原 ToolRuntime 与 MainAgent
脚本模型的只读交付。实际站点本轮只核对顶部区域结构与已签文案，未证明 VortoOne 专用
浏览器、真实账号登录/过期恢复、站点日期、未签提交或常驻端的完整链路已可用。

## 原生设备下一步

沿用原工具运行层和任务状态，各设备适配器只负责发现、连接、观察、单次动作、取消与清理。
先显式绑定宿主/设备/应用与 owner，不按设备名称猜测授权；每台设备同一时刻一个执行者。
设备租约、连接代次和主人确认绑定目标，不能从 Android 自动切到 iPhone，也不复制手机登录态到云端。
用户认证留在设备上完成。断连、权限未知或提交结果不明时停止自动推进，回到原任务请求人工核对，
不再创建第二套轮询循环。

实施顺序为 Android 模拟器单 App → Android 真机 → iOS Simulator → iPhone 真机。
每一步先验证目标身份、主人确认、拒绝、断连、取消与清理，再用一个具体 App 跑完整业务流程。
本轮未安装 SDK/Appium、启动模拟器、连接手机、读取真实网站凭证或发起付费模型请求。
