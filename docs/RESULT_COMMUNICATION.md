# 助理的结果沟通合同

用户需要先看到处理后的结论，再决定要不要查看过程。主界面的摘要与后台通知沿用同一方向：
先说当前结论，说明会影响判断的证据缺口，只在必要时给下一步，完整记录按需展开。

## 当前落地范围

`scheduling/assistant_watch.py` 的派活结束通知使用原任务单和交付验证记录，不再截取原始输出的末尾充当摘要。
General 助理的静态沟通规则使用相同顺序。规则只在会话装配时加入，不随每轮材料改变系统提示词。

- `done` 只表示执行结束。自动验证通过仍待人工审查，不能据此声称已验收、已合并或已部署。
- 无法连接、仍有错误记录、交付证据读取失败，优先于已有的通过记录呈现。
- 验证失败、验证过期、缺少当前提交验证，分别说明对应缺口和核对动作。
- 验收对照沿用已有的一次模型复盘，标明是助理判断。通知先展示未对上和未确认项，最多三条，
  同时保留全部标准的分母、剩余条数及 Desktop「动态」入口。原始标准和复盘记录不重排、不覆盖。
- 原始任务输出和模型自由总结都不能代替验证记录。旧版对照也要按原始标准重新匹配，缺项和无依据的通过降为未确认。
- 有认领记录的复盘，展示时必须仍匹配任务材料和交付提交；失配则提示人工核对，不自动再次调用模型。
  提交身份加入绑定后，旧指纹无法对应的记录会保守地停止展示对照，原始记录仍保留。
- 用户需要回答的问题称为「选项」；没有事实依据时不把备选项写成推荐。

通知中的下一步是基于已记录状态的核对建议，不执行验证、返工或发布。现有批准按钮仍只创建 draft PR，
不表示接受建议或通过验收；执行授权、人工目标验收与 GitHub 合并权限沿用原有路径。

## 边界与后续

这批只改变结果的组织和已有复盘的有效性检查，没有新增模型请求、任务库、执行循环或自动重试。
未接入真实模型或真实网站验收；离线测试只验证材料优先级、展示保守性、原记录保留及调用次数边界。

跨 bot 的语义归纳、重复事项合并、已读与已处理、通知聚合仍需后续独立设计。
不能把这批确定性的状态摘要当成已完成的语义总结系统。
