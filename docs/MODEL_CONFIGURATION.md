# Desktop 模型配置保存与启动回执

模型配置由这台 Mac 的原生层保存，常驻实例单独管理。这里不增加任务台账、调度器或自动重启规则，也不改变原生确认和工具权限。

## 保存事务

`profile_store.rs` 统一管理配置快照和写入：

1. 读取快照时带上不含凭据的 `revision`。旧配置缺少版本时只在缓存中补上；正常保存时才迁移文件。
2. 前端保存可携带 `expectedRevision`，原生层在确认与联网探测前拒绝过期表单。省略参数的旧调用方仍会受到后续原生事务校验。
3. 确认与模型探测期间不持有配置锁。
4. 提交时持锁比较快照版本与磁盘基线。期间其他写入或外部文件改动会使本次提交失败，不覆盖新配置，也不自动重试。
5. 校验、规范化、原子保存成功后才替换缓存并分配新版本；只更换 Key 同样产生新版本。清除配置也更新进程内版本，防止旧请求把已清除的内容写回。

版本由时间、进程与进程内序列组成，供身份比较使用，不是凭据哈希或安全令牌。磁盘基线包含完整配置但仅保留在原生层；状态返回不含 Key。文件权限沿用 600。

这里提供单实例 Desktop 内的并发保护及外部改动检测，不声称提供跨进程文件锁。外部编辑器仍可能在最终检查和原子替换之间写入；应在客户端退出后手动编辑配置。

## 运行时回执

Desktop 给每次启动注入模型版本及独有的启动身份。共享运行时完成启动后冻结回执，关闭时撤回。`GET /api/health/quick` 保持原健康字段，附加可空的 `model_configuration`：

```json
{
  "schema_version": 1,
  "revision": "opaque-model-revision",
  "launch_id": "opaque-launch-identity"
}
```

这里只包含非敏感的身份元数据，不包含配置内容、端点、Key 或文件位置。未配置、旧运行时或无效元数据没有回执。运行中的环境变量变化不会修改已冻结的回执。

原生命令 `get_model_configuration_state` 只访问已托管的回环地址，不接受网页传入的目标地址。读取有两秒超时，禁止代理与重定向；读完后重新核对当前进程身份和已保存版本，期间新启动但尚未读到回执的引擎显示未知。

返回合同 `schemaVersion: 1`，每个工作区分别报告：

| 状态 | 依据 |
| --- | --- |
| `applied` | 健康、回执版本受支持、启动身份和启动版本吻合，且等于当前已保存版本 |
| `pending` | 健康且启动回执吻合，但仍是旧的已保存版本 |
| `unknown` | 无法连接、尚未就绪、旧运行时、缺少回执或身份不吻合 |

设置页仅在可见时读取，失败清除旧成功状态；版本变化或分类切换使旧响应失效。界面提供汇总、各工作区明细和只读重试，不批量重启后台工作区。

回执证明引擎携带该版本完成启动，不证明供应商在线、模型已推理、工具可用、任务验收或部署完成。浏览器/桌面权限仍使用各自的配置合同，不能借模型回执宣称这些权限已经生效。

## 验证

- Rust：实际并发竞争只有一个成功；Key 变化、清除、旧快照、磁盘失败、外部改动、旧文件迁移与无 Key 状态回传。
- Python：回执冻结、结构限制、缺失兼容、生命周期就绪与清理，以及原有健康接口。
- 前端：新旧版本、无引擎、混合状态、无效或未来合同；合成页面验证失败重试、延迟响应与冲突草稿保留。

新协议需要重新构建 Desktop 和内置运行时。仅修改源码不会更新已经安装的客户端。
