# Codex 动作记录完整度与恢复

2026-10-31。复用原 `actions.json`、动作文件锁、观察员回执缓存与原 HTTP 入口。
没有新数据库、调度器、恢复执行器、API 或自动授权。

## 发现的反例

离线复现中，损坏 JSON 被 `load_actions` 当作空列表，下一条提议覆盖了原文件。
另一条已标为 unknown 的动作，在其后连续创建 100 条提议后，被原来“只留末尾 100 条”
的保存逻辑截掉。这两个结果来自临时合成记录，不能推断已经发生生产丢失。

现在文件不存在、旧格式显式空数组或合法新版空台账表示空列表。读取失败、损坏 JSON、非法台账、混入非记录、
重复 ID、缺少核心身份、未知 kind/status、非法消息文本或显式无效时间都停止读取和写入，
保留原文件，不筛选出部分“看起来正常”的记录继续执行。
旧记录可缺少后加的材料指纹和交接字段，但执行仍须通过原版本/授权校验，不在读取时补授权。
合法附加字段原样保留；这不是对所有历史格式或任意文件篡改的自动修复。
新版将原数组置于同一文件的版本对象内，与各会话动作版本一起提交；兼容、上限和部署切换
要求见 [动作版本合同](CODEX_ACTION_CAUSALITY.md)。对外列表及 HTTP 入口不变。

## 容量与原子保存

保存后最多 100 条。只有 sent、确定未发出的 failed、cancelled、expired 属于可淘汰历史，按原记录顺序
优先淘汰较早的已结束动作；proposed、approved、sending、unknown 全部保护。
容量被未解决动作占满时拒绝新提议，旧文件不变，不靠删掉未知结果换取可用空间。
用户取消仍待批准的动作、或真实迟到回执明确结果后，可以按原规则释放容量。
没有新增强行遗忘 unknown、猜测失败或批量重发入口。
旧 failed 原因含“无法确认/可能已送达”时仍属未知结果，不能淘汰；统一语义与暂停合同见
[结果不明时的跟进](CODEX_UNCERTAIN_FOLLOWUP.md)。

原子保存沿用同目录临时文件和替换，失败返回明确的存储错误；未提交认领则不能执行 RPC。
临时文件在可清理时移除，原文件不被部分 JSON 覆盖。该机制不承诺掉电后的 fsync 保证、
硬盘损坏恢复、跨机器恰好一次或完整历史归档。

## 读取、回执和用户可见性

- 动作 GET、批准、取消、认领、回执遇到存储不可用返回 503，不能用 200 空数组或
  409“确定拒收”代替。409 仍用于过时授权或非法回执格式等确定的请求拒绝。
- 原观察员已对 503/网络错误保留未报告回执。存储恢复后只按原 ID 补报结果，不重新执行；
  进程重启可能丢失观察员内存缓存，服务端仍保留 sending/unknown 等待核对，不伪造结果。
- 回执 `ok` 必须是布尔值，`uncertain` 省略时兼容为 false，否则也必须是布尔值。
  字符串 `"false"`、数字、缺少 ok 不能被转成成功或失败，原记录保持不变。
- 进度报告与动作存储分别处理：动作清理不可用时仍能接收进度与原顺序游标，进度查看照常。
  动作列表保持错误状态；不能因此执行旧动作。
- 助理查询会说明动作记录不可用。早晚报在这一情形直接用确定性资料版，不调用模型，
  既不压成“没有待处理事项”，也不拖垮其他来源的已知进展。
- 原监督器在无法读取动作事实时停止本轮判断，不发放新的推进或执行授权。

## 恢复与验证边界

本轮不自动重建、从临时文件猜测恢复或覆盖运行中数据。没有历史文件备份时，已被旧版本
裁剪或覆盖的记录不能由本修复凭空找回；文件被完整删除也不能与首次使用自动区分。
人工核对并恢复原记录后，保留的迟到回执才有可校验的原动作身份。

离线单测验证损坏/部分损坏/身份重复拒绝、所有写入口保留原文件、四种未解决状态满额
拒绝、四种已结束历史可淘汰、迟到回执仍可定位、原子替换失败与临时清理、严格回执标志、
进度独立与早晚报不虚报。

`tests/e2e/test_codex_action_storage_recovery.py` 通过实际 ASGI 路由和原观察员代码验证：
损坏记录返回 503、进度继续接收、临时写入失败不触发 RPC、存储恢复后只补报不重做。
恢复动作由测试显式模拟人工从已核对备份恢复，不是产品自动修复能力。
