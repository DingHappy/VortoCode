# 今日工作

产品主线是常驻助手持续跟进个人研发工作。助理面板的默认「今日」页回答四个问题，历史对话与原动态保留在下方可展开区域。多核心属于底层演进，当前概览复用已有数据，不建立另一套任务台账。

| 问题 | 当前来源与含义 |
| --- | --- |
| 今天有哪些事 | 今天更新的目标/任务/有工作记录的 Codex 会话，加上此前尚未结束或未验收的事项；条目保留来源标签 |
| 推进到哪里 | 项目任务的计划块进度、个人目标下一步、Codex 精简报告；目标推进不代表 Agent 正在自动执行 |
| 哪些已核实完成 | 当天更新、状态为 achieved、每个标准的最新关联证据均 passed、kind 为 personal_acceptance 且 source 为 user_confirmation，无失效原因的个人目标 |
| 什么需要我决定 | 任务拟下发/提问/失败/待验收/提交不明、到期或阻塞目标、Codex 原生等待与待批建议，以及当前对话的操作确认 |

## 完成与验收

- 对话结束、任务 done、模型写“已完成”、PR 链接都不直接进入已核实完成。
- 任务单的当前 HEAD 与 verified_head 一致、verification=passed 且核对时间有效，只显示“当前提交验证通过，交付与目标验收仍需核对”。
- 目标已核实完成表示用户逐项确认了目标标准，不代表本系统独立证明生产部署、真实设备或商业结果。用户仍应在原验收依据中说明边界。
- 验收记录缺失、错绑标准、最新一次未通过、模型来源或失效证据都不能计入。
- 目标、标准及最新证据引用必须有有效标识；标准身份不能重复，最新引用必须唯一匹配一条证据。空引用不会匹配没有 ID 的记录，重复证据不能用于凑齐完成条件。格式无效的目标来源明确标为不可用。
- 今日工作与目标详情共用逐条验收判断：只统计关联唯一、来自用户明确确认、仍有效且通过的最新依据。详情不再直接用存储中的通过数量或 achieved 状态宣称已核实；依据不完整时显示「达成记录待核对」「通过记录待核对」。详情读取失败或失联后，旧达成记录同样保持待核对。
- 昨天完成和未来日期的完成记录不计入今天；按 Desktop 本地日历日划分。
- Codex 新心跳不把旧空闲会话当成今天的新工作。正在执行的旧会话保留；空闲且没有轮次的会话不作为事项。
- 此前停下但未撤回的任务，以及已标为达成但验收证据不完整的目标，跨日继续列为待处理；不会只因到了第二天而从概览消失。已有用户验收完整的过去完成目标仍不计入今天。

## 读取与失联

- 目标与 Codex 进度分别读取，一个失败不阻塞另一个。沿用现有 /api/assistant/goals 与 /api/codex/status，无新增后端路由。
- 目标来源共用只读快照校验，核对身份/版本、渲染字段、带时区的有效日期、进度与标准数量、嵌套证据和提醒记录。任一记录格式异常时拒绝整份新快照，保留同来源历史并禁用目标修改，不解除已受理操作的版本核对；Codex 来源仍独立更新。附加字段保留，未知状态名称可读但不自动推断为运行、完成或可批准提醒，详情中的相关写入禁用。
- 两个来源接入现有只读快照读取层：本机读取 15 秒超时且可中止，远端继续使用原生传输时限；并发的相同读取合并，失败后允许后续核对，不自动重试写入。
- 可见时每 30 秒核对，隐藏时降频；手动与自动读取合并在途请求。
- 窗口切换主机/范围、断开或卸载后，迟到响应不能覆盖新来源。读取失败保留同来源历史，但标为待核对。
- 个人目标验收页的快照也绑定本次连接：同一客户端断线重连后，旧内容只供查看，必须完成新连接的读取后才能修改。读取中显示核对状态并禁用修改；失败后允许手动刷新。页面保持挂载且来源、目标版本一致时保留未保存输入；关闭页面或切换客户端不恢复旧草稿。
- 新建目标的请求 ID 随草稿状态保留。提交或回读失败时保留原输入；当前来源的有效列表读到本次请求对应的目标后清空原输入，并提示已在列表找到记录。后续新输入不会被旧读取清空；回执丢失的提示仍保留，不自动重新提交，也不把找到记录计为目标完成。
- 目标详情与今日工作共用两分钟读取时限。详情长期打开后，独立时钟使过期快照转为待核对；本机时间回拨到读取时间之前也不能作为当前状态。过期会禁用新建、进展、验收及提醒写入，保留刷新入口和同版本草稿，整体达成与逐条通过记录均显示待核对。所有写入在点击时再次核对来源与时限，防止时钟更新间隙误提交；时钟不发起网络请求，成功刷新后才重新计时。
- 目标页的重复刷新共用同一次在途读取；写入受理后另起一轮核对，不能复用提交前发起的读取作为成功依据。旧连接或已被替代的读取结束，不关闭当前读取的核对状态。原快照传输层的超时与合并边界不变，版本核对继续拒绝过旧的共享响应。
- 快照与展开的详情绑定客户端和本次工作范围；同一客户端切换范围也不沿用旧数据或已展开动作。新来源出现同名 ID 时必须重新展开，不能把旧选择自动定位到新来源。
- 过期与日历日判断使用独立时钟更新，不等待网络刷新结束。可见时每秒核对时间、隐藏时降频，并在恢复前台时核对；时钟更新不发起 API 请求。单个来源返回后立即更新时间，不被另一来源的迟滞阻挡。
- 目标来源与任务核对超过 2 分钟不作为当前完成依据。Codex 报告另按现有观察员的 30 分钟失效边界判断，报告时间可在详情查看。
- 新版 Codex 观察员在原接口提供共同执行快照：今日工作优先读取其状态和进展，核对核心/会话/轮次归属，并同时检查服务接收时间与源观察时间。未来时间或超过 30 分钟的源观察不算当前状态；新心跳不能刷新旧观察。
- 旧版观察员没有 execution 字段时兼容旧字段；新版快照显式不可用、协议不支持或身份不符时保留待核对，不回退成旧字段中的运行/结束状态。其他有效条目继续展示。
- Codex 查询摘要和巡视同样核对新版快照的归属与时效；未知观察不触发模型判断或拟继续/停止建议。等待提醒按来源、轮次和类型分别计时，长时间失联后重新观察，不沿用旧提醒的计时和已发送标记。
- 新版观察员通过现有接口协商有序上报：前序游标、代次和序号在接收端核对，迟到旧包不能覆盖新状态，重复包不刷新报告时间。旧循环被新代次接替后停止上报；细节和旧版兼容边界见 [观测顺序与重传](OBSERVATION_ORDER.md)。这不是断线期间全部事件的补收。
- 部分数据未取得时明确显示覆盖不完整，计数只代表已读取记录，不作“今天没有任何待办”的全局保证。

## 动作边界

- 概览行只导航：任务单回到原卡，目标回到验收页，当前确认定位原确认卡。概览不提供新的批量批准或自动完成按钮。
- 目标导航携带目标 ID，并绑定当前客户端和工作范围；验收页只展示指定目标并将焦点移到该卡。找不到时明确提示，不默认选择其他目标；用户可主动查看全部目标。切换来源清除定位，直接打开目标页也显示全部目标。读取复用现有目标列表接口，无新增路由。
- 目标写入已受理、后续读取失败时保留输入，并提示先刷新核对；同一客户端的目标页控制器阻止继续写入，刷新仍可用。只有列表包含相同目标、版本不早于写入响应且身份不重复时，才解除待核对；旧读取不能覆盖新一轮核对。读取成功只证明已看到受理版本，目标完成仍由原有逐项用户验收规则决定。
- 在途请求与已受理目标的 ID/版本保存在按客户端弱引用隔离的临时记录中；关闭目标页或同一客户端重连不释放在途写入。新页面先等待原写入返回，再读取目标并核对已受理版本，不补发写入。旧页面离开后，迟到回执仍保留核对版本，但不向旧界面报告成功。其它客户端的同名目标不共用此记录。
- 同一客户端开始或结束一笔写入后，其它目标页此前发起的读取失效；旧响应不能解锁新操作。仍在查看的页面会提示刷新核对，不停留在无法手动恢复的加载态。
- 目标页分别提示等待提交结果、已受理待核对、未取得成功回执。写入抛错或响应身份无效时，先读取当前列表才允许下一次主动写入；读取成功不会清除未取得回执的提示，也不会被当作上次提交成功。关闭再打开页面仍保留该提示，直到用户明确发起下一笔操作；没有自动重试或补发按钮。
- 操作提示携带原目标 ID，只从同一客户端已读取的列表中查找名称，并提供「核对这条目标」的只读入口。入口按 ID 定位并核对客户端、连接与工作范围；离线时禁用。目标未取得时不借用另一目标或第一行的名称，列表中缺失时明确提示，不自动跳到其它目标。导航不补发写入、不代替验收，也不抹去未取得成功回执的提示。
- 临时记录不保存目标正文、输入或凭据，不是目标台账或持久重试队列。新的客户端对象、窗口重新加载与进程重启不继承该记录；传输报错也不能单凭一次读取证明原写入的成败，不承诺跨这些边界的重复提交保证。
- Codex 原生审批/回答仍到 Codex 处理；助理拟的发话/停止建议展示原文与外部内容提示后，沿用原批准接口。
- 对话和概览中的同一 Codex 动作共用现有同步操作门；切换主机后不刷新或写回旧来源。
- 已核实目标之外的任务结束与提交验证，继续作为待验收事项展示。
- Codex 动作 proposed 仍待用户审阅；approved 与 sending 持续列为送达待核对，当日 failed 列出失败依据，历史终态失败留在原记录。确认送达 sent 不计入完成；待核对卡不增加再次发送、自动重试或代替批准的入口。

当前验证包括投影/读取合同测试、静态渲染测试与合成数据浏览器交互。它们不等于已安装 Desktop、真实常驻主机、真实 Codex 会话或原生 UI 的端到端验收。

另有当前源码组件、原 GatewayClient、真实 FastAPI 接口与临时磁盘数据的 [HTTP 联调记录与复现方法](GOAL_HTTP_INTEGRATION.md)，覆盖提交故障、版本冲突、逐条验收、服务进程重启和幂等重放；仍不代替原生 Desktop 或真实模型/Codex 验收。

## 离线恢复检查页

`desktop/qa/goal-recovery.html` 使用真实目标组件和操作控制器，客户端数据全部合成，仅演练「保存进展」。它不连接运行端，不发送模型请求，不批准通知或验收。运行：

```sh
cd desktop
npx vite --config qa/vite.config.ts --host 127.0.0.1 --port 5195 --strictPort
```

打开 `http://127.0.0.1:5195/qa/goal-recovery.html`；该入口也纳入现有 QA 构建，产物仍在 `qa/dist`，不覆盖 Desktop 的 `dist`。

- 默认「提交后丢失回执」：修改下一步并保存，确认正在等待结果；关闭再打开目标页，然后完成写入。页面应读取已保存的内容，并保留「未取得成功回执」提示；再次打开仍保留，写入请求与已保存计数均为 1。
- 切换来源：另一客户端的同名目标不显示前一来源的提交提示；返回原来源后仍核对原记录。
- 列表中另一目标排在原目标之前。提交原目标后，在回执返回前点击「查看另一目标」，再完成写入；提示仍应标明原目标，点击「核对这条目标」只定位原目标，写入计数不增加。开启「隐藏原目标」并刷新后，核对入口应显示尚未读取到对应记录，点击后明确显示未找到；只有主动查看全部目标才显示另一目标。
- 选择「正常回执」，开启「延迟读取」和「旧版本读取」，再明确保存一次并完成写入。返回旧读取后仍应保持已受理待核对；关闭两个开关后刷新，读取最新版本才恢复修改。两次明确保存只产生两次写入。
- 开启「显示今日工作」，在「目标数据」中选择「合成完整验收」，分别刷新两个视图，应看到完整依据与完成计数 1。切换为日期/进度异常后刷新，页面应保持可操作的刷新入口、历史目标禁用修改，完成计数降为 0；恢复正常数据后可继续读取。
- 「达成但缺少依据」应在详情显示待核对、核实数量为 0，今日工作不计入完成；「未知状态」应保留条目并禁用修改。所有验收依据均为合成注入，不是实际用户验收。

「读取失败」用于在途读取的恢复检查；关闭检查页会丢弃合成数据，不提供真实写入、重启持久性或原生 Desktop 验收证明。
