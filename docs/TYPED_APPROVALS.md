# 审批卡类别与风险

ADR-012 阶段 B 的第一步。类别沿用可信工具传给内核确认门的 `kind`，不从模型文案或客户端提交的字段推断。

| 类别 | 服务端风险 | App 批准钥匙 |
| --- | --- | --- |
| `read` / `own_data` / `draft` | `normal` | 日常设备钥匙 |
| `write` / `execute` / `deliver` / `interact` / `irreversible` | `high` | 需 Face ID 的批准钥匙 |
| 缺失或未知类别 | `high` | 需 Face ID 的批准钥匙 |

这是卡片的签名级别，不是工具权限。`gate.decide()`、能力档案和现有工具围栏继续执行；`owner_device` 没有因此获得命令、任意文件写、操控或外发工具。污点撤销预授权的规则保持不变，普通卡在污点回合也必须由人决定。

## 传输与决定

- 内核调用支持类别的终端回调时保留 `kind`；只接收文案的旧回调照常使用，回调自身的 TypeError 不重试。
- Desktop 的 `agent_confirm` 和重连快照附带 `operation_kind`、`risk`、`required_key`、`approval_scope`；新增字段可选，旧客户端继续按原协议响应。Desktop 仍用当前会话的确认通道，`required_key` 的 Face ID 约束只用于 App 签名接口。
- App 服务端拟卡，摘要 v3 绑定回合、卡片、文案、类别、风险、钥匙要求、污点、可选范围和次数/时间上限。签名接口既复验设备签名，也核对当前摘要；所选范围签入原请求体，提高钥匙要求不允许客户端降级。拒绝敏感卡可用日常钥匙。
- 卡片创建时记录服务端时间。审批到达时再次核对期限，不能利用异步超时回调尚未运行的间隙批准过期卡。批准、拒绝、过期或取消后不能再覆盖终态。

## 原审计与界面

复用 `.vortocode/audit.log`，不增加审批库。内核决定附加可信类别、风险、钥匙级别、决定来源和范围。自动放行标为 `preauthorized` / `existing_trust`；人工卡为 `user` / `once`；系统拒绝为 `system` / `none`。

App 人工决定、超时和取消只由卡片闭合记录一次 `approved`、`denied`、`expired` 或 `cancelled`；内核回调只补记 `preauthorized` 和 `system` 决定，保留自动放行及系统拒绝的审计。记录只有卡片或回合 id 与有限元数据，不复制正文或工具参数。工具执行记录仍独立保留，批准不代表执行完成。

Desktop 确认卡与审核记录展示类别、风险/来源和范围；iPhone 卡片展示类别、风险、本次范围与污点提示。旧历史缺少字段时显示待核对；未知手机风险或钥匙级别按加强确认。旧服务 `normal` 且无新增钥匙字段的卡继续兼容日常钥匙。
