# Desktop 模型凭证存储

2026-10-31，源码实现，尚未发布或迁移真实凭证。范围仅为 macOS Desktop 管理的默认模型及
自定义供应商 Key，沿用原 `profile_store` 配置事务、版本/CAS、原生确认和运行时注入。
不新增凭证数据库，不改变账号、远程连接、IM、Git 或外部 CLI 的原生登录存储。

## 配置与凭证分开

- 新建模型配置使用 `credentialStorage.version=1` 的引用格式；JSON 中默认与供应商的
  `apiKey` 均为空字符串，实际 Key 存入 `com.vortocode.desktop.models` Keychain 服务。
- 一个不可变条目保存该配置版本的 Key 集合，内部按默认服务/供应商 ID 绑定精确端点。
  读回时核对这些绑定；改端点或供应商身份不能借用原 Key。引用也限定于原配置文件位置，
  复制 JSON 到另一个路径会拒绝读取，不作为跨主机凭证迁移方式。
- 原生层只把 Key 提供给原模型客户端与受控运行时环境；状态接口只给存储模式和待清理数，
  不把 Key、摘要或 Keychain 引用交给网页。供应商/工具权限、子进程过滤仍沿用原规则。
- 无 Key 的本机模型不创建 Keychain 条目。系统存储不可用时，新 Key 保存失败，不回退成
  明文文件；其它平台的系统存储后端尚未实现。
- Release 使用原 `llm-profile.json`。Debug 改用 `llm-profile.dev.json`，Keychain 服务另加
  `.dev`；开发版不自动读取/导入正式版文件或凭证。两者显示各自的配置路径。

引用格式仍包含模型、端点、分工和原版本元数据，并按 600 保存。元数据文件不包含新
Key 的明文；读取、加载和模型推理仍会在原生/运行时内存中持有使用中的 Key。

## 旧配置显式迁移

旧格式保持可读。只查看状态、启动客户端或自动刷新模型列表，不会搬动旧 Key。旧格式
在用户确认迁移前，原有保存操作继续沿用明文格式；本切片没有把现存主机认定为已迁移。

设置 → 高级 → 配置文件 → 模型凭证存储：

1. 刷新只读取配置元数据，不访问 Keychain，不调用账号或模型服务。
2. 旧格式显示“迁入本机钥匙串”；必须已有当前模型版本并经过原生窗口确认。
3. 应用确认在原配置锁外进行，随后持原锁重新核对内存版本和磁盘配置；过期/外部编辑拒绝。
4. 先记录新条目的清理身份，再写入 Keychain 并读回核对；核对成功后原子切换 JSON 引用。
5. 迁移保留原模型配置版本，不重启本机或常驻引擎，不向云端上传或探测模型。

若确认期间配置版本改变，界面要求回模型设置重新载入；只刷新存储元数据不会重置已
拒绝的提交版本，也不会丢弃模型草稿或重发迁移。

Keychain 自身可能需要系统解锁/确认。迁移没有更新已安装应用；源码需要构建后才会出现
此入口。旧配置在引用切换完成前仍可恢复；失败时不把未核验的新 Key 当作已保存。

## 失败、清除与清理回执

清理记录保存在原配置文件的 `credentialStorage.pendingCleanup`，只含本配置范围内的
不透明引用。最多 32 条，读取配置最多 8 MiB；不自动淘汰记录来接纳新凭证。

| 故障位置 | 行为 |
| --- | --- |
| 新 Key 写入/读回失败 | 不切换引用，保留原配置；尝试清理新条目，未确认的删除留在原记录 |
| 引用切换失败 | 不删除仍使用的旧条目；新条目清理也可重试 |
| 切换成功后旧副本删除失败 | 新配置继续有效；保留待清理引用并在设置中显示，不把保存说成未发生 |
| 清除配置时删除失败 | 先原子撤下当前引用，保留无活动配置的清理记录；不再从该配置加载旧 Key |
| 清理记录保存失败 | 保留较早的记录，下一次可幂等核对，不删除当前引用 |
| 进程在阶段之间退出 | 依据原文件里的活动引用/清理记录恢复；读取不自动删 Key，不重试模型请求 |

“重试清理”同样需原生确认、当前版本核对，不自动循环。它只删除已不被当前配置引用的
本机旧副本，不撤销供应商 Key。原子文件保存失败会清理本次创建的临时文件，清理无法
确认时报告错误；不删除其他写入者的临时文件。

这里没有跨进程文件锁或跨 Keychain/文件系统的断电原子事务。仍需单实例 Desktop，
外部修改遵守原配置 CAS 边界；不声明防止同用户恶意程序访问所有宿主资源。
历史 JSON 备份、旧临时文件、磁盘快照及运行中进程的 Key 副本不随迁移消失；迁移也
不等于上游 Key 轮换/吊销。仅备份引用 JSON 不能恢复已删除的 Keychain 条目；完整备份、
跨主机恢复和降级合同尚待实现，不应让旧客户端编辑新引用格式或手工修改引用。

Keychain 锁定、条目缺失或损坏时，引用格式拒绝加载，不借用其他供应商 Key。当前需
恢复相应 Keychain 条目；独立的“凭证丢失后显式重建配置”入口尚未实现，不能把格式
迁移称为完整的凭证丢失恢复方案。

## 验证边界

模型凭证原生单测强制使用内存后端，覆盖多供应商、旧格式只读/显式迁移、写入与核验
失败、引用切换失败、清理失败/重开/清除、容量与损坏、端点/配置位置绑定，以及迁移
确认后的版本竞争和外部编辑。真实文件系统测试还覆盖失败保存时的临时文件删除。
前端覆盖状态投影、显式操作、版本缺失、丢失回执、并发/迟到结果与入口展示。

原生编译/单测可以只在测试环境关闭 Tauri 资源打包：

```sh
TAURI_CONFIG='{"bundle":{"active":false,"resources":[]}}' cargo test --lib --offline --no-default-features
TAURI_CONFIG='{"bundle":{"active":false,"resources":[]}}' cargo check --offline --no-default-features
```

这不伪造 sidecar，也不验证安装包资源、真实 Security framework 权限窗口或已安装客户端。
完整验收仍需签名构建后，以专用测试凭证核对实际 Keychain 保存/拒绝/解锁/删除与恢复；
不得用这些内存替身测试声称用户真实 Key 已经迁移。
