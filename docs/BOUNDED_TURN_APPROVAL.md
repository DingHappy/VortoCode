# 本轮同类授权

ADR-012 阶段 B 的有限范围切片。Desktop 和 iPhone 的确认卡可选择「允许一次」或「本轮同类允许」。权限记录页仍只读，记录里出现 `turn` 不表示现在还有有效授权。

## 范围与期限

只有可信工具声明的 `own_data`（主人自己的可撤销事项、提醒、记忆提议）与 `draft`（不离开本机的草稿）可提供范围选项。一次选择只覆盖当前类别，不同时授权另一类别。每类最多 10 次，含当前这次；从真实 `MainAgent.run_turn` 开始计时，最长 600 秒。额度用尽后只能逐次确认，重复选择不能补充额度。

这一步只覆盖一轮真实调用，不是整个目标、任务链或主要聊天。回合退出（包括异常或取消）或到达 600 秒期限均令范围失效；后台任务继承了 ContextVar 也不能在回合结束后复用。回合里一旦接收外部内容、不可信入口或带外部出处的历史，范围立即撤销，本轮即使清理污点标记也不能重新建立。

`read`、任意文件写入、执行、外发、操控、不可逆及未知类别没有这个选项。工具能力档案、白名单和撤销登记继续执行；范围不能解锁手机原本没有的工具。既有 trust 档位保持原语义；未消耗临时范围时的普通预授权仍单独标为 `existing_trust`。

## 内核与宿主

临时状态只保存在安全内核 `agents/scoped_approval.py`。`gate.py` 将有效范围作为 `decide()` 的预授权输入，实际类别、次数、期限、污点和生命周期均由内核核对。可信回调可返回带范围的 `ApprovalDecision`；旧布尔回调只代表一次。并发等待共享计数锁，多个初次批准也累计在同一上限内。

工厂默认关闭范围。当前只由本机 Desktop sidecar 和 App 主人回合显式开启；CLI、IM、无人值守、研究员和委派路径没有开启。仍需当前真实回合、可询问真人且属于已知允许档案。客户端传来的范围字符串不能创建授权对象。

## 原通道与签名

Desktop 沿用当前会话的待批 Future。确认事件和重连投影增加可选的 `scope_options`、`scope_limits`；响应可带 `scope=turn`。响应仍核对原卡身份和发起会话。未知或未提供的范围、错误身份、内容变更及范围批准审计无法持久保存时仍拒绝；原 audit.log 必须成功持久记录。

用户明确批准过一张仍有效的卡、且选择的是该卡原先提供的本轮范围时，若等待期间范围过期、次数耗尽或被污点撤销，只批准当前这一次，不建立、恢复或补充范围。内核记录实际范围为 `once`，后续动作仍须另行询问；App 和 Desktop WS 共用该内核规则。App 卡片记录用户已签名提交的范围选择，不据此宣称范围最终建立或当前仍有效。签名、钥匙级别、当前卡片的期限和持久审计要求均不降低。

App 沿用手机网关与常驻助理两处签名核验。卡片摘要 v3 额外绑定选项、每种范围所需钥匙和次数/时间上限；所选 `scope` 与 `key_kind` 一起签进原请求体。建立本轮范围必须用批准钥匙（Face ID），即使单次低风险卡允许日常钥匙。旧客户端省略 `scope` 仍仅批准一次。过期或内容变化的卡、错误钥匙和旧卡重放不能建立授权。

两端只在服务端明确提供完整且不超过本版上限的范围元数据时展示按钮。发送成功仍不等于审批回执或动作完成；断线和结果不明时不自动重发批准。

iPhone 对话卡现补齐 [回执与只读核对](MOBILE_APPROVAL_RECEIPTS.md)：提交结果不明时锁定按钮，显式查询后才能重新选择；已确认的回执不因读取仍返回 pending 而开放重发。Face ID 等待结束后、发送前再次核对登录、回合和原卡，旧签名不迁移到新身份。

## 历史与后续

复用原 audit.log 的 `approval_scope=turn`。初次范围选择与后续内核自动放行分开记录，后者来源是 `preauthorized`；卡片批准与实际工具执行仍是不同事件。审计仅保存元数据，不持久化范围、额度、Future 或可恢复授权。重启、重连、重新登录和读取历史均不恢复范围。

跨回合任务范围、定时任务范围、连接器范围、永久授权、可编辑权限管理与历史归档仍待后续切片。离线回归、Swift 合同和模拟器编译不代表真实 Face ID、已安装客户端、真实模型操作或线上部署验收。
