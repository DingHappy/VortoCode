# 从任务交付起草个人技能

2026-11-01。源码切片，基于资源总览分支；未合并、安装或部署。复用原助理派活台账、
PersonalSkills、General 管理入口与原版本启用规则，不增加任务库、模型调用或后台学习循环。

## 操作流程

在“定制 → 技能 → 个人技能”的“从任务起草技能”中，手动选择来源和新技能 ID，或使用
已有 ID 提议更新。按已记录的任务目标与验收清单生成可编辑检查表，不从执行日志推断
操作步骤。请人工补充适用范围、可复用步骤与停止条件，再保存为待审草稿。

待审草稿不会创建或替换 `SKILL.md`，也不会修改现有版本的启用状态。审核页面展示任务 ID、
项目、提交、交付观察时间、目标基准版本，以及名称、说明和正文的完整 unified diff。
接受后保存为**停用**版本；沿用原“审阅正文 → 已审阅，启用此版本”，须再次单独确认。
拒绝不会替换、回滚或停用当前技能。

首版只支持当前助理实例的 General 个人范围。记录提出/审核时间和 `instance_operator`，
含义是经当前实例认证的操作人；并未识别独立账号，不能据此声称双人复核、owner/manager
权限或跨 bot 共享审核已经实现。提案不扩大工具权限、文件权限、外发权限或网站/设备授权。

## 来源与版本合同

仅从原台账读取，不联网刷新项目，不读取凭据、项目文件、任务私有日志或模型总结。
来源须同时满足：

- 原任务状态 `done`、最后同步 `current`，没有任务/交付错误、污点或恢复子任务歧义。
- 有远端任务身份；交付快照的完整提交 OID 与验证提交相同，验证通过且带时区时间。
- 当前提交的改动覆盖已知，计数类型严格、无缺失，全部 hunk 已接受；零改动也须有明确快照。

这只是**已记录且已审阅的交付**，不证明当前远端仍在线、真实上线、业务收益或目标已验收。
观察时间一直展示。新读取来源和应用提案都会核对原台账；已有来源后来变为断连或发生
状态/结果/提交/验证/审阅变化时，应用被拒绝。需要实时核验时，先在原任务入口手动刷新。

来源摘要绑定原任务身份、原运行目标、目标/标准、结果摘要的哈希与提交审查证据；结果内容不复制到
提案。纯观察时间刷新不改变来源摘要。目标技能绑定完整原始文件 SHA-256，提案决定还绑定
提案 ID 和记录版本；浏览器不能自报来源证据或绕过旧版本冲突。

源文字经过原持久摘要策略的脱敏及显式注入过滤；它仍是待审材料，不是可信系统指令。
提交草稿若命中疑似凭据规则则拒绝落盘。差异中的旧版本疑似凭据只在展示中脱敏并提示。
这些启发式规则不是对所有秘密或恶意指令的识别保证；已启用指令仍沿用原非可信 Skill 加载边界。

## 存储、并发与中断

`workflow/workbench/skill_learning.py` 使用原派活事务锁，再取得原 PersonalSkills 文件锁，
在同一原始事务观察内核对来源并处理目标版本。所有技能保存、启停、提案操作共享原技能锁。
`PersonalSkills.encode` 与 `_save_locked` 是对原保存流程的小范围提取，原手动保存语义不变。
提案写入原技能目录的 `proposal.json`，使用原私有、拒绝符号链接、有界读取和原子替换方法。
未新建知识数据库、任务数据库、调度器或可供模型写入/启用技能的工具。

每个技能一份当前提案和至多 20 条较早的紧凑记录；只保留当前提案全文，不保留旧草稿正文。
目录仍受原 100 项限制，来源显示最近 20 项，超限明确提示。相同来源和草稿的重复点击返回
原提案；已处理来源在保留窗口内不得再次生成同一技能提案。没有监听、定时、自动生成、
自动审核、自动启用或失败重试，因而不会形成“改一次再学一次”的自动循环。
这不是无限历史或永久幂等，旧来源随保留窗口淘汰后仍可由操作人手动再次提出。

接受时先持久记录 `applying` 意图，再沿用原“先停用 → 写正文”，最后记录 `accepted`。
中途写盘失败不声称回滚或成功，也不自动再次写正文。刷新并打开提案会显示“保存结果待核对”，并只读刷新原技能状态：

- 当前内容与目标摘要相同且已停用时，操作人可以“核对已写入版本”，仅补记审核结果。
- 目标未完整写入、摘要不符或仍启用时，不允许这样补记。可以查看原技能，或“结束提案，
  保留当前技能”；结束不会恢复旧启用状态或回滚磁盘内容。

这是保守的跨文件中断协议，不是所有文件的原子事务。若正文写入前失败，旧版可能仍启用，
或因停用已经落盘而停止后续加载；界面和记录不得把这两种状态合称保存成功。

Desktop 读取/写入/后续刷新复用 `PersonalSkillRequests`，同时核对原 Gateway 连接代次。
切运行端、断连、卸载或同对象重连后，旧响应不能填回新界面或发送后续读取。重连前已经
发送的写入可能完成，须在原运行端手动核对，不能把界面丢弃旧回包解释为撤销远端写入。

## 验证与剩余范围

单元测试覆盖来源严格判定、来源/目标/审核令牌变化、原锁冲突、重启读取、重复点击与拒绝、
有界历史、文件私有性/损坏/符号链接/脱敏，以及每个写入阶段的中断和显式核对。
前端覆盖检查表、原版本保留、来源展示、差异审核、停用保存、过期与待核对阻止应用，
并验证同对象重连在 React 渲染前使迟到响应失效。

`desktop/qa/skill-learning.html` 使用生产卡片与合成内存传输；可手动验收编辑、差异、拒绝、
接受后独立启用、来源失效、保存中断、换运行端和窄窗口。夹具不请求真实任务、账号、模型或设备；
夹具结果不替代真实后台来源与落盘行为，后者由离线 Python 测试分别验证。

真实项目完整交付、模型自主提炼、原生应用安装和跨账号/多 bot 审核仍未验收。管理员凭证
委托仍未收窄，不由技能审核补齐。下一轮优先从真实交付取得反馈；不要先增加自动学习或更多角色。
