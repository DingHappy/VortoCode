## 数据与范围

`turn.request` 继续用于短进度显示。新增 `turn.review_context` v1 专供判断当前材料
是否可用，不能据此授权。它只包含当前可见 turn 的 `userMessage.content` 文本，
按原顺序保留换行与同轮补充；不扫描此前会话、工作区、附件、完整 diff 或工具结果。
`complete` 仅表示这个范围内的用户文本已收齐，不表示整段会话、验收证据或上游 API 完整。
原计划与最终回复仍是有损显示摘要，不能作为用户验收事实。

字段包括 `schema_version=1`、`scope=turn_user_messages`、精确 `turn_id`、
`status`、`messages`、`message_count`、`omitted_messages`、`unsupported_content`、
`fingerprint`。每条消息保留 `text/original_chars/truncated`。

- 最多 8 条用户消息、累计 4096 个文本字符；上限是字符数，不是 token 数。
- 超长、超条数、非文本附件、未知内容类型、混杂空用户消息明确 `incomplete`；
  无可核对文本为 `unknown`。超限不靠模型摘要恢复成 complete。
- 接收端复核版本、范围、身份、计数、类型、长度、完整度和规范化 SHA-256。
  哈希用于检测材料变化，不是签名、信任来源或授权证明。
- 不支持的版本、错误计数、篡改、缺字段都保留不可用事实。显式无效新字段不退回旧摘要。
  旧观察员缺字段也保持 unknown，进度与原人工控制仍可用。

当前原报告上限仍为 12 个会话；新文本每会话最多 4096 字符。它随原状态槽替换，
不新增全量会话归档。完整用户文本较原短摘要更长，仍须遵循原观察员的交接、鉴权和存储边界。

## 判断、额度与建议失效

监督器在候选筛选和模型入口都检查完整度。材料不足时不构造模型客户端、不发送请求、
不预留 Goal 判断额度、不记为本轮已判断；其他完整候选照常竞争原来每次最多两轮的额度。
同一份不足材料用原监督 marks 去重提醒，原目标进度投影显示暂停原因。
只暂停自动拟下一步，不停止 Codex 当前执行，不改变用户验收。

更新观察员后，同一轮若此前没尝试模型判断，可以首次判断；若已经尝试过，即使结果
因材料更新作废，也保留已消费额度和该轮认领，不自动重跑或补发。

模型看到有明确范围和顺序的用户消息数据，以及原 Goal/验收项材料。用户限制、延期
优先于补齐计划；这些文本仍是待分析数据，不能覆盖系统权限。没有关联 Goal 的监督
也不会因此获得整段会话的长期范围合同，历史限制的持久确认仍是下一阶段工作。

模型等待期间同轮补充也改变材料指纹，旧结论丢弃。自动建议创建时必须再次核对完整度
和指纹；待批、已批建议在报告更新、批准、认领前复核。失效后不发给 Codex，也不重放
`sending/unknown` 动作。旧的自动建议缺少材料版本时要求重新拟话。
主人明确提出、绑定原助理会话的手工消息和叫停保持原有人工门，不因本次完整度检查失去控制能力。

观察员与常驻监督服务需要都更新；旧观察员对新版服务仍可报进度，但自动拟下一步暂停。
这次提交不安装、不重启、不启用生产监督；旧服务也不能被新字段自动补出这些保护。

离线回归覆盖长消息末尾限制、同轮补充、附件与超限、旧/未来版本、接收端拒绝篡改、
候选公平性、额度不消耗、判断中材料更新、已批建议失效，以及清理锁忙时认领再检查。
