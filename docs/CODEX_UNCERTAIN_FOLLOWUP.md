# Codex 结果不明时的跟进边界

2026-10-31。复用原动作台账、交接、监督 marks、待办和回执入口；没有新 API、
调度器、恢复 Agent、任务库或自动核对模型。

## 复现与决策

离线复现中，一条 sending 动作超时变成 unknown 后，监督器调用了一次模型，并在
旧 unknown 旁边生成新的 proposed 动作。超时只是未确认收到回执，上一条指令可能已经生效，
不能据此认定可以安全推进。这是替身轨迹，不是生产重复发送事故证据。

unknown 现在继续阻止所属 Codex 会话的自动判断、拟话和拟叫停；其他会话照常竞争原
每轮最多两次判断额度。该暂停不会花新的 Goal 判断次数，也不会记成该轮已判断。
重启、刷新、时间流逝、换新轮次或重新交接都不是旧动作的结果证据，不能清掉这个条件。

真实迟到回执按原 ID 将 unknown 核对为 sent/failed 后，可以进行此前尚未尝试的判断；
如果模型已经尝试，后来出现新未知结果而使结论失效，该轮认领与已用次数仍保留，不重评、
不退款。Goal 逐项用户验收仍独立，不能用传输结果替代业务验收。

## 并发窗口和人工操作

- 候选筛选先排除被未解决动作阻挡的会话，避免占住其他会话的两个判断名额。
- 模型返回后再次核对待处理动作。如果此时仍有新的拟话、批准、认领或结果不明，旧判断作废。
  后续 [动作版本检查](CODEX_ACTION_CAUSALITY.md) 也覆盖新动作已结束、此刻没有待处理项的情况。
- 自动拟话/叫停创建前，在原交接与动作锁内核对；待批/已批的自动动作在批准、认领时
  再检查其他未解决动作，不能利用尚未执行的清理绕过。
- 新动作保存 `automatic` 布尔标记，来源由原监督器或交互工具装配决定，不接受模型在
  工具参数里扩大权限。旧材料判断标记仍作为更严格依据，显式 false 不能削弱它。
  显式无效标记按损坏记录拒绝，不降级为手工作业。
- 交互工具仍可提出新的消息或叫停，逐条由用户批准；这只保留人工控制通路，不表示已经
  批准、更不等于旧消息没发出去。用户应先核对原会话，避免明确新指令重复已有副作用。

这里没有“忽略未知”“按已失败重试”或自动解除暂停入口。观察员重启丢失内存回执、且
无法取得原动作结果时，自动跟进保持暂停；用户仍可在原 Codex 会话或人工提议通路继续处理。
本轮没有把人的一次模糊确认伪装成原生 RPC 回执。

## 统一旧记录和可见性

旧 failed 记录的原因包含“无法确认”或“可能已送达”时，按 unknown 理解，保持原文件事实。
监督、容量保留、原会话归属、查询、早晚报、待办和通知共用同一后端判定，与现有 Desktop
兼容处理一致；这些记录不能被作为确定失败历史淘汰，也可以接受原 ID 的真实迟到回执。
确定失败的记录不会因此获得新的执行机会。

未解决动作不再受 24 小时显示窗口影响。助理查询优先显示结果不明及其总数，待办不会到期消失。
原动作列表无筛选读取最多展示 100 条，覆盖原台账容量，避免旧未知结果被新历史遮掉；
观察员按 approved 轮询仍最多 50 条，不扩大执行批次。
关联 Goal 的原状态投影显示暂停原因，进度和外部 Codex 的当前执行照常查看。

同一组未知动作的巡视提醒只在通知被受理后记入原 marks；投递未受理可在下次巡视重试。
重复未知回执只更新同一事实，不靠时间戳变化反复推提醒；原会话进展或未知集合变化仍可汇报。
存在未知结果时，早晚报直接使用确定性资料版并保留其他已知进展，不为反复改写同一未知状态
调用报告模型。其他健康会话的监督调用仍遵循原节奏与额度，不构成供应商金额硬预算。

## 验证边界

离线回归覆盖超时 → unknown → 重启/重新交接仍暂停 → 原 ID 迟到回执 → 首次判断恢复，
并核对额度不消耗/不退款、并发创建与审批、人工控制、旧版不确定失败、长期记录保留与查询、
其他会话不饥饿、通知未受理及去重，以及早晚报不新增模型改写。
外部执行和模型为替身，只验证确定性状态边界，不证明模型判断质量或真实主机已验收。
