# 私人助手记忆优化与回测

复现示例中的 `BENCH_ROOT` 为自行选择的公开题库与依赖缓存目录，运行前请设置该变量；不是固定机器路径。

2026-10-13。以首次公开标准集校准为起点，本轮保留原题、官方裁判提示及同一端点；不把题目答案或证据会话标签放入检索和回答流程。首次报告见[校准结果](STANDARD_ASSISTANT_CALIBRATION.md)。

## 已实现

- SQLite FTS5检索增加会话多样性：扩大候选池，先取各会话的最佳命中，再取同会话更多命中；仍保留BM25顺序、相邻片段和原始记录，不调用模型提炼。候选扫描最多800个命中、最终最多50个，标准题固定16个命中。
- 检索上下文携带原始会话ID及日期；标准题的8k代理token上限现在计入分隔符和截断标记，超限片段明确标注。会话命中标签仅在离线事后诊断使用。
- 读者提示区分事件日期与对话日期，以问题日期计算经过时间；跨会话合并证据、去重事件，处理更新/累计值前先检查是否在描述同一对象。提示不含特定题型ID、标准答案或预设结果。
- 原记忆工具组增加 `search_conversations`，General的既有工具装配自动获得它。它先只读搜索当前范围 `.vortocode/web_sessions/*.json` 的已保存对话，再检索旧SQLite会话记录；不扫描任意用户目录、不把历史写入长期事实。没有落盘的临时对话不在检索范围。
- JSON读取最多100个会话/16MB，每文件最多1MB；跳过符号链接、非普通文件、损坏或超限资料。只提取user/assistant文本，不使用活动、排队输入或系统指令。每会话保留最佳窗口并跨会话排序；JSON路径支持中文关键词字面匹配，SQLite标准题仍使用英文词法检索。尚未测试中文语义召回或本地embedding。
- 工具结果标记为不可信证据，继承原污点与确认机制。片段每条最多2000字符、正文总计12000字符；含检索范围受限标记。无消息时间戳时只能标记存档时间，明确它不是事件日期。I/O在线程中执行，避免阻塞Agent事件循环。

上述为源码实现，已安装Desktop仍未替换；标准题衡量SQLite后端，JSON产品接入另由工程测试验证，不能直接套用标准题分数。

## 中文产品检索补齐

JSON 存档检索原先将连续中文问句当作一个完整词，只做该句的字面包含匹配，导致“我之前讨论的显卡升级方案是什么”无法找到“讨论显卡升级计划”。现在仅在产品 JSON 存档路径加入中文双字片段匹配，过滤常见问句/讨论用语，分开混合中英文型号，并规范化全角字符。查询仍限前2000字符、最多32个去重检索词，原100文件/16MB/单文件1MB读取限制及不可信证据合同保持不变。

英文仍按独立词边界匹配，避免 violin 命中 violinist；各会话仍取最佳窗口后跨会话排序。该方法是字面检索，不能识别所有同义词或判断事实更新。SQLite FTS5、公开标准回测基线和实验 ONNX 检索均未更改。工程测试覆盖自然中文问句、混合/全角型号、泛词误命中、英文排名、查询/结果上限和原工具的只读证据返回；这些用例不是新的能力题库或准确率成绩。

后续优先顺序：时间范围过滤须区分消息时间与存档时间；增加原始片段定位/按需补读，避免截断信息被当成完整事实；再核对更新与冲突。任务方向优先失败恢复及结果证据，复用既有任务/调度台账。能力比较继续使用冻结的公开题库，并分别记录覆盖、准确率、token及耗时；MiMo 上游过滤仍是完整留出对照的阻断条件。

## 检索诊断

同一20题、同一16命中/相邻1条和最多8000代理tokens，离线复建检索后全部标注证据会话覆盖从18/20变为20/20。两道此前跨会话错误题的会话召回由60%与50%变为100%。它只证明会话覆盖，不能保证正确证据片段已完整进入上下文，也不能当作答案准确率。

诊断输出 `${BENCH_ROOT}/diverse-recall.json`；不发送模型请求。改进方案未用标签挑选片段或调整排序，标签只用于事后比较。

## 日期范围与原文补读（2026-10-13）

`search_conversations` 增加可选 `after` / `before`，格式 YYYY-MM-DD，包含边界当天；按消息 ISO 时间戳记录的日历日期筛选，不将文件修改时间当成消息或事件日期。缺失/无效消息时间不进入日期范围结果，并报告 `undated_messages_excluded`。非法范围在读取前拒绝。当前日期过滤仅覆盖 JSON 产品存档，旧 SQLite 路径暂不纳入日期范围查询，结果明确返回 `legacy_sqlite_included=false`；不带日期时仍保留双来源检索。长于200条的存档明确标记范围受限，不能将空结果当成从未讨论。

JSON 检索片段携带文件 SHA256 `archive_revision`。新增只读且不可信的 `read_conversation_excerpt`，用检索返回的 id/revision 定位原消息，单次最多6000字符，返回字符偏移/总长度/next_offset供按需继续补读。每次核对版本，文件变化必须重新检索；拒绝路径穿越、符号链接、超限文件、系统消息与非法偏移。不会把原文自动写为长期事实。旧 SQLite 片段暂不支持此补读入口。

这些是源码和工程合同测试；没有新增模型请求、没有替换已安装 Desktop，也没有新的标准能力分数。接下来优先用原生界面验证搜索→补读→来源核对，并继续补旧记录的日期/定位支持；再做显式事实更新与冲突审阅，复用现有确认门。

## 旧 SQLite 证据链补齐

产品工具现已支持旧 SQLite 的日期筛选及原文补读，替代上一节初版的“日期范围仅限 JSON”限制。新增 `conversation_evidence.py`，仅用 `mode=ro` 连接；不初始化数据库、不建 FTS 索引、不写入长期事实。原 `ConversationSearch` 继续服务冻结的英文公开回测，未更改其检索协议。

产品旧记录按最新1000条消息有界扫描，累计文本/元数据预算16MB，单条正文最多100000字符、元数据最多16000字符；超限/不可读/截断扫描明确报告 `sqlite_coverage.coverage_limited`。使用与 JSON 相同的中文短片段及英文词边界匹配，最多8个命中，优先分散到不同会话。该路径返回直接命中，不自动附加相邻消息，不能宣称检索覆盖已提高；产品答案质量仍需实测。

日期优先使用导入记录的 `history_date`，其次为真实记录的 `created_at`；分别标记 `recorded_conversation_date` / `stored_message_date`。已有 history_date 无效时，不用导入当天的创建时间替代。日期不明的记录在范围查询中排除并计数。任何记录日期均不自动作为文本中事件的发生日期。

检索结果统一包含 `source_kind` 与 `source_revision`。`read_conversation_excerpt` 按来源分派，旧 JSON 的 archive_revision 参数继续兼容；SQLite 每次核对消息文本、角色、时间和元数据组成的版本。变更/删除/超限后必须重新检索；其他消息新增不会让这条证据的版本失效。补读仍最多6000字符，分页偏移和不可信证据合同复用。数据库损坏不丢弃已找到的 JSON 结果，报告旧来源覆盖受限。

工程测试验证只读连接前后数据库文件哈希不变、无 FTS/事实写入、消息日期和导入日期区分、版本变更拒读、双来源工具路径、中文/英文匹配、查询上限及损坏降级。没有新增模型请求、安装版替换或能力提升成绩；下一步仍需要原生界面和真实模型的来源核对验收。
