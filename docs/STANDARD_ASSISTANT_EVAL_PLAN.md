# 标准私人助手测试集：方向与 token 预算

复现示例中的 `BENCH_ROOT` 为自行选择的公开题库与依赖缓存目录，运行前请设置该变量；不是固定机器路径。

2026-10-12。用户要求先选择公开标准测试集并估算用量，再做能力回测。此前自拟14题与100分评分只保留为产品功能回归，不能作为私人助手综合能力成绩。改进后自拟题的模型运行已停止，未产生完整前后比较结论；未晋升新的改进后基线。

## 优先测试的能力

1. **多步工具执行与信息不足时的处理**：首选 [Apple ToolSandbox](https://github.com/apple-aiml-research/ToolSandbox)。它有真实可检查的设备设置、联系人、消息和提醒状态，覆盖多工具、多轮用户交互、状态依赖、时间/数字规范化和信息不足等类型。使用原题、原模拟环境及官方milestone/minefield评分，不改题来适应现有工具、不用最终回复里的“已完成”判成功。已建立隔离的MainAgent工具环境与用户模拟器适配，用于本轮子集校准。
2. **长期用户记忆**：首选 [LongMemEval V1 cleaned S](https://github.com/xiaowu0162/LongMemEval)，官方数据见[Hugging Face](https://huggingface.co/datasets/xiaowu0162/longmemeval-cleaned)。500题，涵盖提取、跨会话推理、知识更新、时间推理、偏好和不知道时的回答。测试时历史必须走实际记忆写入/检索流程，答案只交给官方裁判；不把所有历史或标准答案直接喂给回答模型。Oracle仅用于诊断“证据已给全时能否答对”，不是记忆检索成绩。
3. **跨应用自主办事**：第二阶段接 [AppWorld](https://github.com/StonyBrookNLP/appworld)。它用日常应用的模拟API与数据库构成复杂任务，检查实际完成状态及附带影响。比单一工具任务更接近Muse，但需要隔离的代码/API执行适配，超出现有General会话边界，不能顺手开放用户真实文件/账号。固定dev用于调试，保留test任务作为最终评估，不能反复用test答案调提示。

[AssistantBench](https://assistantbench.github.io/)重点测联网调查与多站信息汇总；[GAIA](https://huggingface.co/datasets/gaia-benchmark/GAIA)涉及联网、附件和复杂推理。这两项可在研究/浏览器能力阶段追加。当前不先选更大的 [LongMemEval-V2](https://github.com/xiaowu0162/LongMemEval-V2)：它测Agent的环境经验，包含大型多模态轨迹，并非普通用户偏好记忆。

能力主成绩按官方指标分别报告：ToolSandbox里程碑/禁行错误，LongMemEval官方答案准确率及题型分数，AppWorld官方任务完成与约束结果。tokens、调用数、耗时是独立效率指标，不用自拟加权总分抵消能力失败。子集成绩明确标为子集，不能称为完整榜单成绩。

## 离线统计依据

已经下载官方cleaned Oracle数据到${BENCH_ROOT}/longmemeval_oracle.json，并使用已有缓存中的tiktoken离线计数，没有发送模型请求、没有安装依赖。

代理tokenizer为cl100k_base，不是mimo或27B模型的精确分词器。把会话日期、role/content、问题日期与问题拼接，不包含标准答案：

- 共500题，历史与问题合计2,873,551 tokens。
- 平均5,747，中央値5,766.5；p90=9,767；最大22,386。
- 文件SHA-256：821a2034d219ab45846873dd14c14f12cfe7776e73527a483f9dac095d38620c。
- 统计文件：${BENCH_ROOT}/token-estimate.json。

这只是Oracle文本长度，不是完整推理用量。系统提示、工具schema、重复上下文、输出、用户模拟器、记忆提炼、重试和裁判都必须另外算。不同模型tokenizer会有偏差。

V1 S官方说明的历史规模约115k tokens/题（Llama 3分词器）。全500题直接长上下文回答，单轮仅历史输入约57.5M tokens；前后各2遍就是约230M输入，再加输出/裁判。因此不能把S全量长上下文和低成本RAG混成一个预算。

## 建议的启动规模及估算

全部是**LLM输入+输出tokens**的预算估算；模型、模拟器与裁判分别记账，最后相加。不是公开测试集公布的固定耗费。

### 校准试跑：5道ToolSandbox + 20道LongMemEval-S，各1次

- ToolSandbox：预计每题8–15次Agent请求，2–5次模拟器请求。Agent平均输入6–8k、模拟器平均输入2–4k，每次输出约300–500；取每题60–150k总用量，5题约0.30–0.75M。
- LongMemEval-S：本地无LLM索引，检索上下文限制约6–10k，一次reader与一次judge；连同系统提示、答案、裁判，预计每题8–12k，20题约0.16–0.24M。
- 合计约0.46–0.99M（46–99万），建议先预留100–150万，并用实测5题校准。这不包含任何LLM记忆构建。
- 若记忆写入需要模型提炼，20题原始历史约2.3M输入；按8k分块、固定约1k提炼提示和短输出，还需约2.5–3M，试跑总预算约3–4M。

### 正式小规模前后回测：20道ToolSandbox + 50道LongMemEval-S，前后各2次

同一批官方题ID、同一模型/模拟器/裁判、同一协议、同一执行限制，保持题型分层覆盖；不挑只会做的任务，不改原题或官方评分。

| 项目 | 单轮估算 | 四轮合计 |
|---|---:|---:|
| ToolSandbox 20题，含Agent和模拟器 | 1.2–3M | 4.8–12M |
| LongMemEval-S 50题，本地无LLM索引，含reader/judge | 0.4–0.6M | 1.6–2.4M |
| 两项合计，不含LLM记忆构建 | 1.6–3.6M | 6.4–14.4M |

如果采用LLM提炼记忆，50题历史每个版本约5.75M；前后两个版本分别构建一次，两个重复查询复用该版本的索引，预计另加12–15M提炼输入/输出。合计约18–30M，可按20–35M预留分词差异及运行波动。索引/提炼单独计费计量，不能藏在“回答每题只用8k”后面。

如果采用原始记录加本地搜索/本地embedding，初始化仍有数据处理、算力与存储成本，但不产生上述LLM提炼tokens；若改用本地模型提炼，仍应计入LLM tokens，只是不一定有API账单。它与现有记忆写入策略的适配需先明确，不能把预估方案冒充已存在的能力。

AppWorld放第二阶段；10题单轮可先按约1–3M估算（20–30次模型请求/题，平均5–10k上下文加代码输出）。长任务和反复纠错可能明显超出，不能把这个经验预算当固定上限。先做独立5题校准再定正式规模。

## 开跑前固定的记录

固定官方仓库revision、数据SHA、题ID/分层方式、Agent版本、记忆构建方法、reader/judge/用户模拟器模型、随机种子及预算/停止条件。工具API调用次数不等于模型请求次数；完整对话历史重复发送的输入都计入tokens，缓存折扣只改变价格。预算停止的任务必须报告未完成，不能记为成功；更改官方上限的测试必须标为预算限制版，不能宣称官方同条件榜单结果。
