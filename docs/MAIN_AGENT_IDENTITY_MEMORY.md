# 主 Agent 的方向、角色文件与长期记忆

2026-11-03。延续 [ADR-011 / ADR-012 / ADR-013](DECISIONS.md) 的个人 Agent 方向，细化主 Agent 的身份与记忆合同。
源码核对基线为 `0c714b46`。本 PR 实现下述切片 1 和 2：统一主身份与场景规则、角色编辑说明、
相关模板，以及 Desktop 记忆快照预览与 Markdown 下载。导入、修订、撤销和 App 管理另行实现。
源码和合成检查不代表已经安装、部署或完成真实模型与两端验收；待合并审批分支另行验收。

## 主方向

**VortoCode 是一位可定制、能记住背景、持续跟进工作的个人助手。主人在 Desktop 或 App
交代目标，助理在已开放的能力和授权范围内推进，需要主人决定时给出明确的对象、依据与选择。**

它围绕「交代 → 推进 → 核对 → 汇报 → 继续跟进」工作。日常价值用少重复解释、少遗漏事项、
少追问进度和结果来衡量。开发、检索、日程、连接服务都是按需使用的能力。
Desktop 保留项目工作台；主 Agent 的默认身份统一为个人助手。

主 Agent 的固定职责：

- 识别用户当前有效的目标、约束与纠正；信息足够时推进，必要问题集中询问。
- 根据当前会话实际开放的工具行动；后台推进必须有原目标、任务或定时记录支持。
- 需要执行或查进度时读取对应权威来源，再根据实际结果汇报。
- 分清提出建议、等待批准、已受理、已执行和已验收；缺少证据时保留未知。
- 持续事项复用现有目标、任务、通知与调度记录，记忆负责补背景。

以上职责随产品版本维护。名字、语气和默认协作偏好由主人定义。

## 角色文件：主人可以定义，权限继续由内核决定

沿用现有文件，不另建一份主角色配置：

| 文件 | 内容与权威来源 | 生效方式 |
| --- | --- | --- |
| `.vortocode/assistant.json` | 主人定义的名字；现有唯一配置 | 会话装配时读取 |
| `.vortocode/SOUL.md` | 助理的角色定位、性格、表达和默认协作偏好；主人可编辑 | 会话装配时读取；当前上限 2,000 字符 |
| `.vortocode/persona.md` | 主人希望始终提供的背景，如称呼、工作领域与汇报偏好 | 会话装配时读取；当前上限 2,000 字符 |
| `.vortocode/agents/*.md` | 现有子 Agent 的专业角色定义 | 沿用角色装配；与主助理的 SOUL 分开 |

这些路径属于选定常驻实例的工作根目录。两端连到同一实例时共用资料；不同实例不会因此同步。
General 的私人资料也不自动扩散到所有项目会话、子 Agent 或联网定时作业。

SOUL 可以规定「简短直接」「先说明判断」「默认用中文」「必要时提醒我未结束的事」。
工具、目录、额度、审批与外发权限继续由现有能力档案和确认门判定。
角色文件里的授权表述不能授予权限；对话、网页或历史里的角色草稿也不能自动覆盖它。
助理代拟的修改必须展示差异，由主人确认后通过专门的保存路径生效。

本轮提供可复制编辑的 [SOUL 示例](examples/assistant/SOUL.md) 和
[主人资料示例](examples/assistant/persona.md)，不自动写入真实 `.vortocode/`。
主人已有内容优先，首次使用的默认模板也不能覆盖旧文件。

保存与应用分开表达：**当前沿用新会话装配时生效，进行中的会话继续使用原快照。**
保持同一会话的系统前缀字节稳定。后续若支持在同一主聊天应用新版本，需在回合结束后
显式重建 Agent、保留原聊天并展示应用结果；不在工具执行或等待审批时热改提示。
修订号及旧版本恢复在此生命周期合同之后补齐。

## 提示词按职责装配

建议固定顺序：产品职责 → 当前场景 → 本次角色与主人资料快照 → 实际工具与能力规则。
已确认记忆和历史证据按当前问题召回，放进当次请求，并标明它们是背景资料。

固定职责可以表述为：

> 你是 VortoCode 的个人工作助手。围绕用户当前有效的目标，使用本会话开放的工具推进工作，
> 依据可信运行记录报告进度，需要用户决定时说明对象与依据。

General 的措辞对应个人事项；Project 才追加仓库与开发约定；只有实际装配某项工具时才追加
它的使用规则。系统里不出现当前入口无法使用的工具补救路径。
压缩纪要保留当前目标、用户纠正、已取消或被替代的要求、未完成工作和证据位置。
历史批准只作记录，恢复后的权限重新由运行时核验。

审批异常、等待超时与用户拒绝的区别需要运行时结果合同支持，不能只改提示词解决。

## 长期记忆：数据库负责生效，文件负责阅读与迁移

保留 `sessions.db / __longterm__` 为长期记忆的唯一生效来源。文件定义为
**按需导出的长期记忆快照**，便于主人阅读、保存和迁移。Desktop 下载名为 `MEMORY-<版本前缀>.md`，
由主人选择保管位置；不自动在 `.vortocode/` 另写副本、不监听文件变化、不双向同步，
也不把整份文件自动注入系统提示。旧库缺失的确认与来源信息保留未知。

记忆分工：

- `persona.md`：主人选择始终提供的少量背景。
- 长期记忆库：已确认的稳定事实、偏好、约定与有来源的决策，按相关性检索。
- 聊天与压缩纪要：当时的讨论和工作上下文；需要回溯时检索原文。
- 目标、任务与日程：当前事项、进度和执行状态，继续读取原台账。
- `.vortocode/memory/repo.md`：现有项目事实，保持项目作用域。

### 可读文件先落地

第一步提供显式导出和预览，覆盖全部可导出记录或明确标出范围上限。
不能直接把界面当前最多 200 条的列表标成「全部记忆」。每条至少有 id、正文、记录时间和
可取得的来源；旧记录缺失的字段显示未知。文件注明导出时间、实例范围、记录数与版本摘要。
只读导出不创建或修复数据库，排除待确认、隔离记录与完整聊天。
疑似凭据在导出时仍按现有规则复核脱敏，旧数据不能被假设为已经通过当前写入策略。
模式检测不能证明发现了所有敏感资料，导出界面提醒主人妥善保管私人资料。

导出是按需快照，后续库内变更不会自动改写磁盘文件。界面应能说明快照已过期，
也不能把导出文件存在当成已完成加密备份。

### 编辑和导入通过提案生效

第二步接受文件或其他 AI 导出的文本，先展示新增、修改与删除差异，再逐条确认。
首版纯文本导入只生成新增候选；缺少某条旧记录不能推断为删除。
同实例快照的修改或删除需要匹配原 id 和版本；跨实例只作新候选，不沿用原批准状态。
文件里声明的 `approved`、来源或授权均属输入资料，不能自证可信。

沿用 `MemoryWritePolicy` 与提案审阅路径：自动提炼只进待确认，疑似凭据隔离。
修订保留原来源、修订关系和确认记录；保存时间与事实发生时间分别表达。
旧记忆是否被取代由主人决定，话题相关只作提示。
替换与撤销需要在原记忆库中原子保存，失败时不能只留下新事实或丢失旧事实。

忘记后，后续召回不再使用该条；聊天历史、已发给模型的内容、旧导出和备份需要分别管理。
撤销和导出机制不能暗示这些副本已被一并清除。

## 开发切片与验收

本 PR 完成切片 1 和 2 的源码及离线接线检查。后续切片继续独立验证：

| 顺序 | 范围 | 必须看见的结果 |
| --- | --- | --- |
| 1：身份一致 | 固定职责、场景规则、角色示例与生效提示；压缩纪要保留用户纠正 | General 不再自称开发框架；手机不被引导调用缺失工具；角色改动不改变权限或进行中的系统前缀 |
| 2：看得见的记忆 | Desktop 身份页的来源、预览与 Markdown 导出；先只读 | 导出范围明确，未确认/隔离资料排除；未知来源不伪造，旧凭据脱敏，空库读取不建库 |
| 3：可控修订 | 导入候选、差异审阅、版本校验、原子替换与撤销 | 导入不直接生效；旧快照不能覆盖新记忆；跨实例不复用授权；失败保留原事实 |
| 4：两端与实用验收 | App 身份和记忆编辑、待确认列表；复用签名与原服务 | Desktop 修改后新装配可读；App 确认后后续回合可召回；账号切换和迟到响应不会串数据 |

身份一致先完成；记忆的只读切片可随后推进。导入和主动提炼继续服从 ADR-012 的阶段顺序，
不以此开放新的后台自主执行，也不恢复 ADR-008 冻结的协作功能。
开发采用独立分支与 PR，既有审批工作继续单独验收。

工程测试分别验证装配、写门、检索、版本与前缀稳定；真实模型效果和两端体验另行记录。
用固定场景检查「改称呼、纠正旧事实、取消旧要求、换项目、重启后继续、导入错误记忆」，
衡量漏召回、过时事实误用、重复解释次数、执行结果正确率及请求成本。
本轮未调用真实模型，也未修改真实角色或记忆数据。

### 本 PR 的只读导出合同

`GET /api/assistant/memory-snapshot` 仅在 General 使用，沿用原 API 鉴权。用 SQLite `mode=ro`
与同一读取事务取得总数和记录，固定最多 1,000 条，每条正文最多 4,000 字符，元数据最多
16,000 字符；超限与明确未确认/隔离记录跳过并标为覆盖受限。读取有 SQL 工作量与锁等待上限。
未知 schema 或损坏库返回不可用，不创建索引或修复表。

响应包含可显示来源、记录时间、未知确认人、来源实例、稳定内容摘要及纯文本 Markdown。
旧记录只表明存在于长期记忆分区，不能据此补造确认人。Markdown 的记录正文使用足够长的代码围栏，
预览使用只读文本框。切换实例或连接后不接受迟到响应，预览重新挂载并清空。
导出只生成响应和用户主动下载的文件，不进入模型上下文、不保存第二套记忆或授予权限。
